# Typsidian

**Typsidian** — редактор заметок на языке [Typst](https://typst.app/) в духе Obsidian: связанные
заметки, граф, доски, задачи и презентации, только вместо Markdown — Typst с настоящей вёрсткой
документа.

Заметки — это обычные файлы `.typ` в обычной папке (vault). Никакого обязательного сервера,
аккаунта и закрытого формата: папку можно открыть любым редактором, собрать `typst compile`,
положить в git или Syncthing. Typsidian — самый удобный способ с ней работать.

- **Local-first.** Всё работает без сети; индексы, поиск и проверка орфографии считаются на
  устройстве. В сеть приложение ходит только за шаблонами Typst из реестра и к удалённому
  репозиторию, если вы его подключили.
- **Typst целиком.** Предпросмотр — это настоящая сборка документа: формулы, таблицы,
  библиография, шаблоны пакетов, PDF и HTML на выходе.
- **Одно ядро на все платформы.** Web, рабочий стол, Android и свой сервер ведут себя одинаково:
  вся логика живёт в одном ядре на Rust.

---

## Где работает

| Оболочка | Что это |
| --- | --- |
| **Web** | Браузер на Chromium. Два режима: папка на вашем устройстве (File System Access API) или vault на своём сервере |
| **Рабочий стол** | Приложение на Tauri 2 (Linux; сборка `.deb`, на NixOS — `nix run .#desktop`) |
| **Android** | Приложение на Tauri 2; vault в `Documents/Typsidian`, захват через «Поделиться» |
| **Свой сервер** | `typsidian-server`: вход, свои vault на сервере, синхронизация; отдельно — публичный демо-режим |

## Возможности

### Vault и файлы

- **Vault — обычная папка.** Дерево заметок и досок, создание, переименование, удаление (в
  корзину ОС), несколько vault и быстрое переключение между ними.
- **Внешние изменения.** Правка файла другим редактором приходит в приложение сама; если в
  открытой заметке есть несохранённый текст, открывается сравнение со слиянием, а не тихая
  перезапись.
- **Служебное место.** Кэши, снимки, словарь и настройки vault лежат в одной скрытой папке
  `.typsidian/` и едут вместе с vault.
- **Перенос в дереве.** Заметки и папки перетаскиваются указателем, долгим нажатием или
  командой «Переместить в…»; ссылки на перенесённое переписываются, последний перенос
  отменяется.
- **Вкладки и разделение.** Несколько заметок во вкладках, две рядом, «назад/вперёд» по
  истории переходов; раскладка запоминается.
- **Закладки.** Заметки, разделы, сохранённые поиски и папки в своём порядке и группах.
- **Вложения.** Картинка из буфера обмена, перетаскиванием или с камеры Android сама ложится в
  папку вложений, а в текст подставляется `#image(...)`.
- **Импорт из Obsidian.** Папка Markdown становится vault Typsidian: дерево, ссылки, картинки,
  формулы LaTeX → Typst, YAML-шапка → свойства; непереводимое остаётся видимым текстом и
  попадает в отчёт. Импорт идёт пакетами, его можно отменить и продолжить.

### Редактор

- **Подсветка синтаксиса Typst** тем же разбором, которым собирается документ: разметка, код и
  формулы различимы, незакрытая скобка не ломает остаток заметки, заметка на тысячи строк не
  тормозит.
- **Дополнение.** `@` предлагает метки заметки и подключённых файлов и ключи источников, `[[` —
  заметки vault. «Перейти к определению» ведёт к метке, заметке или источнику; ссылки в никуда и
  повторные метки подчёркнуты ещё до сборки.
- **Параметры элементов.** Рисунок, таблица, колонки, `#set page` и любая встроенная функция
  Typst правятся формой с именованными полями; описание параметров берётся прямо из
  компилятора, а незнакомые аргументы, комментарии и выражения остаются нетронутыми.
- **Заготовки.** Библиотека шаблонов и сниппетов — обычная папка vault: заготовку можно
  развернуть в новую заметку или вставить у каретки, с превью.
- **Оглавление** заметки: заголовки, метки и рисунки с переходом и подсветкой текущего раздела.
- **Поиск и замена по vault** — подстрока или регулярное выражение, каждое совпадение
  «было → станет», замена отмеченных одним действием и отмена всего пакета.
- **Проверка орфографии** для русского и английского без сети: формулы, код, вызовы функций,
  метки и ссылки не проверяются; свои слова — в словарь vault.
- **Палитра команд** и переназначаемые сочетания клавиш.

### Документ Typst

- **Живой предпросмотр** рядом с текстом: постраничный SVG с выделяемым текстом, обновление по
  мере набора без кнопки «сохранить», ошибки с причиной и переходом к месту. Сборка идёт вне
  потока интерфейса и обрывается по пределу времени.
- **Шаблоны пакетов.** `#import "@preview/имя:версия"` — недостающий пакет приложение скачивает
  само и кладёт в vault; видно, что и откуда скачано, автозагрузку можно выключить. Скачанное
  не попадает ни в историю, ни в Syncthing — каждое устройство скачивает пакет само; положенные
  вручную пакеты (`.typsidian/packages/`) синхронизируются.
- **Встраивание заметок.** `#embed("Методика#Выборка")` показывает заметку целиком, её раздел или
  элемент по метке — в предпросмотре и в PDF, с обновлением вслед за источником.
- **Библиография.** Файлы `.bib` и Hayagriva `.yml` в vault находятся сами; «Вставить цитату»
  ищет по автору, названию, году и ключу; видно, где источник процитирован и каких ключей нет.
- **Свойства и выборки.** Теги и поля в начале заметки обычным Typst, форма их правки, поиск по
  свойствам и блок `#select(...)` — таблица заметок, которая сама обновляется.

### Связи

- **Обратные ссылки и упоминания.** У каждой заметки видно, кто на неё ссылается и где она
  упомянута без ссылки; упоминание превращается в ссылку одним действием.
- **Граф связей** в духе Obsidian: живая силовая раскладка, перетаскивание узлов, подсветка
  соседей, локальный граф вокруг заметки, фильтры, цветовые группы и силы раскладки — плавно и
  на тысячах заметок.
- **Состояние ссылок.** Один экран для битых ссылок и заметок-сирот: создать недостающую
  заметку, перенаправить ссылку на существующую, убрать ссылку, отметить сироту «намеренно».

### Организация работы

- **Задачи из заметок.** Пункты `- [ ]` со всего vault в одном окне: по заметкам или по сроку,
  фильтры по папке и свойствам, отметка выполненного меняет одну строку заметки.
- **Ежедневные заметки и быстрый захват.** «Сегодня» открывает заметку дня по шаблону;
  «Во входящие» дописывает мысль в конец заметки, не трогая прежний текст. На Android — через
  системное «Поделиться» и ярлыки значка.
- **Доски для рисования** на Excalidraw рядом с заметками: автосохранение, вставка снимка доски в
  заметку, отметка устаревшей вставки.

### Презентации и экспорт

- **Показ слайдов** прямо из приложения: с touying, polylux или просто страницами нужного
  размера. Листание клавишами и кликером, вид докладчика с заметками, следующим слайдом и
  часами; показ обновляется вслед за правками.
- **Экспорт в PDF** заметки или пакета заметок с ходом и отменой.
- **Экспорт в HTML** — заметки становятся сайтом: страница на заметку, оглавление, работающие
  ссылки, формулы MathML, картинки внутри; на web — архив zip.
- **Экспорт презентации** — PDF слайдов, PDF со страницами заметок докладчика, PDF с файлом для
  pdfpc, картинки PNG или SVG.

### История и синхронизация

- **Снимки заметок без git.** Приложение само откладывает версии по ходу работы; их можно
  сравнить с текущим текстом и вернуть одним действием, удалённую заметку — восстановить.
- **История версий на git.** Обычный `.git` в папке vault: снимки, история заметки, сравнение и
  возврат версий, правила исключения редактируются прямо в приложении.
- **Удалённый репозиторий.** Отправка и получение со слиянием; встречные правки — в редакторе
  слияния. Токен хранится в хранилище секретов системы, не в vault.
- **Syncthing.** Если папку доставляет Syncthing, приложение предлагает правила `.stignore`,
  собирает конфликтные копии в список и назначает одно устройство хранителем истории.
- **Разрешение конфликтов.** В редакторе слияния ваши правки подсвечены синим и знаком `<`, их —
  янтарным и `>`, правленые вручную строки результата — `✎`. Спорные участки решаются разом
  («везде своё / их / обе»), конфликты в списке — пачкой: оставить свои, взять их или принять
  все, что совместились сами.

### Свой сервер

- **Web на своём сервере.** Вход паролем и через OpenID Connect, у каждого аккаунта свои vault,
  та же рабочая область, что с папкой на устройстве; правки приходят во все вкладки сами,
  обрыв связи не теряет текст.
- **Синхронизация на сервере.** История версий и удалённый репозиторий по HTTPS ведёт сервер;
  токены хранятся на сервере для каждого аккаунта отдельно.
- **Демо-режим.** `serve --demo` — публичная площадка без входа: «Попробовать без регистрации»
  даёт на час свой vault с примерами всех возможностей, затем он удаляется целиком. Квота
  объёма, предел стартов с адреса и общий предел гостей защищают сервер.

### Интерфейс

- **Русский и английский** интерфейс, включая сообщения ядра; язык меняется на лету.
- **Настройки** без кнопки «сохранить»: внешний вид, сочетания клавиш, настройки vault; файл
  настроек не выбрасывает дописанное руками.
- Тёмная тема на дизайн-системе «Спецформа»; раскладка для телефона.

## Состояние

Проект в активной разработке. Все перечисленные возможности реализованы и покрыты
автотестами ядра на обоих таргетах (native и wasm); web-версия проверена сценариями в
браузере (`scripts/dev/scenarios/`). Ручные прогоны на рабочем столе и Android закрыты не для
всех возможностей — они перечислены в `tasks.md` фич, сводка — [`specs/ROADMAP.md`](specs/ROADMAP.md).

Пока нет: полнотекстового поиска с морфологией, разбора ссылок Typst сверх `[[…]]`, `@метка`
и `#embed`, оболочки под iOS; на сервере — Syncthing и импорта из папки Obsidian.

## Как устроено

```
                    ┌──────────────────────────────┐
                    │     packages/core (Rust)     │
                    │  вся логика: vault, сборка   │
                    │  Typst, ссылки, синхронизация│
                    └──────────────┬───────────────┘
                     wasm32        │        native
            ┌──────────────────────┴───────────────────────┐
            ▼                                              ▼
   ui/ (React, общий)                    packages/host — команды ядра
   apps/web (Next.js)                     ├─ packages/shell → apps/desktop, apps/mobile (Tauri)
                                          └─ apps/server (axum) → web в серверном режиме
```

| Каталог | Что внутри |
| --- | --- |
| `packages/core/` | Ядро на Rust — единственное место бизнес-логики; тесты `cargo test` и `wasm-bindgen-test` |
| `packages/host/` | Команды ядра без Tauri — одна реализация для оболочек Tauri и сервера |
| `packages/shell/` | Команды Tauri, общие для рабочего стола и Android |
| `ui/` | Общий интерфейс на React: рабочая область, редактор, панели, токены дизайна, тексты ru/en |
| `apps/web/`, `apps/desktop/`, `apps/mobile/`, `apps/server/` | Оболочки |
| `specs/` | Спецификации фич (Spec Kit): spec, plan, tasks, research, contracts, quickstart |

## Быстрый старт

Окружение — Nix (`nix develop`: Rust с таргетом wasm32, wasm-pack, Node 22, pnpm, Tauri,
chromium для тестов; Android — `nix develop .#android`).

```bash
nix develop
pnpm install
pnpm build:wasm                          # ядро → wasm-биндинги в ui/src/wasm-core
pnpm --filter @typsidian/ui build        # общий интерфейс

pnpm dev                                 # web на http://localhost:3000
pnpm --filter @typsidian/desktop dev     # рабочий стол (cargo tauri dev)
nix run .#desktop                        # собранное приложение на NixOS
```

Android: `nix develop .#android`, затем в `apps/mobile` — `pnpm build` (APK) или `pnpm dev` на
подключённом устройстве. Для установки нужен `--debug` или своя подпись.

Проверки — одной командой: `.specify/scripts/typsidian/gates.sh all` (формат, тексты
интерфейса, сборка native и wasm32, тесты ядра, хоста и сервера, `wasm-bindgen-test`, сборка и
проверка типов интерфейса).

### Свой сервер

```bash
nix build .#server                                    # или cargo build -p typsidian-server --release
pnpm --filter @typsidian/web build:server             # статика web → apps/web/out

typsidian-server --data /var/lib/typsidian user add anna --name "Анна"
typsidian-server --config /etc/typsidian/server.toml serve --static apps/web/out
typsidian-server --data /var/lib/typsidian-demo serve --demo --static apps/web/out   # демо
```

`server.toml`:

```toml
listen = "127.0.0.1:8787"
data = "/var/lib/typsidian"
public_url = "https://notes.example.org"   # внешний адрес за прокси с TLS
trust_proxy = true                          # адрес посетителя — из X-Forwarded-For прокси

[oidc]                                      # необязательно
issuer = "https://id.example.org/realms/team"
client_id = "typsidian"
label = "Authentik"

[demo]                                      # действует только с serve --demo
ttl_minutes = 60                            # сколько живёт гость
quota_mb = 50                               # объём его vault
per_ip_per_hour = 5                         # стартов с одного адреса (IPv6 — по /64)
max_guests = 200                            # гостей одновременно
```

Снаружи сервер работает только за HTTPS: cookie сессии `Secure`, без `public_url` с `https://`
сервер слушает лишь loopback. Прокси не должен буферизовать поток событий (`proxy_read_timeout
1h`, сервер сам отдаёт `X-Accel-Buffering: no`) и должен пропускать тела до 256 МБ для вложений.
В разработке: `cargo run -p typsidian-server -- --data /tmp/ts-data serve` и `pnpm dev` —
`next dev` проксирует `/api` на сервер.

Журнал сервера — входы, отказы и ошибки; текста и имён заметок, паролей и токенов в нём нет.

## Как ведётся работа

Проект живёт по [конституции](.specify/memory/constitution.md) и процессу
[Spec Kit](https://github.com/github/spec-kit): у каждой фичи есть спека, макет интерфейса, план
и задачи, а готовой она считается после тестов на обоих таргетах. Главные правила:

1. Бизнес-логика — только в `packages/core`; интерфейс её не дублирует.
2. Паритет таргетов: изменение ядра собирается и проходит тесты и под `wasm32`, и нативно.
3. TypeScript strict, без `any`; тексты интерфейса — только из каталогов локализации.
4. Содержимое заметок не покидает устройство: индексы и поиск строятся локально.
5. Массовые операции отменяемы и не блокируют интерфейс.
6. Серверные фичи проходят отдельное ревью безопасности.
