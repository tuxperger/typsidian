# Typsidian

Локальный **local-first** редактор заметок на языке [Typst](https://typst.app/) — по духу
Obsidian, но с Typst вместо Markdown.

Vault — это обычная папка с файлами на диске. Никакого сервера, аккаунта и проприетарного
формата: заметки читаются и правятся любым сторонним редактором, а Typsidian просто самый
удобный способ с ними работать.

> **Статус: ранняя разработка.** Работают менеджер vault, доски для рисования и панель
> настроек. Компиляции Typst и preview, моста к Neovim, полнотекстового поиска и мобильного
> клиента пока нет — см. [Что готово](#что-готово).

---

## Идея

Одно Rust-ядро (`packages/core`) — один поведенческий контракт для всех клиентов. Оно
собирается в WASM для веба и нативно для desktop/mobile; UI на React общий, клиент-специфичен
только тонкий связующий слой.

```
                    ┌──────────────────────────┐
                    │   packages/core (Rust)   │
                    │  вся бизнес-логика:      │
                    │  vault, доски, настройки │
                    └────────────┬─────────────┘
                    wasm32       │       native
              ┌─────────────────┴──────────────────┐
              ▼                                    ▼
     ui/ (React, общий)                   ui/ (React, общий)
              │                                    │
      apps/web (Next.js)              apps/desktop (Tauri) · apps/mobile (планируется)
```

Платформенные различия — файловая система, вотчеры, персистентность — скрыты за трейтами
внутри ядра. Вызывающий код никогда не ветвится по платформе.

## Параметры элементов Typst

Элементы каталога вставки с параметрами — рисунок, таблица, колонки, кодовый блок, цитата,
`#set text`, `#set page` и прочие — вставляются и правятся **формой с именованными полями**
вместо слепого обхода полей сниппета ([`specs/008-element-parameters`](specs/008-element-parameters/spec.md)).

- **Вставка** — выбрать элемент в меню ⌘E или на панели вставки: «Будет вставлено» показывает
  ровно тот текст, который попадёт в заметку.
- **Правка в любой момент** — каретку внутрь элемента, затем «Параметры»: кнопка на панели
  вставки, пункт «Параметры элемента…» в контекстном меню редактора, команда палитры ⌘K или
  `Ctrl/⌘+Shift+E`. Элемент переписывается на месте, одна отмена возвращает прежний вид.
- **Ничего не теряется** — меняется только то, что изменили в форме: незнакомые аргументы,
  комментарии, отступы и выражения (`100% - 2cm`) остаются как были. Где разметку нельзя
  разобрать однозначно (незакрытая скобка, параметр указан дважды), форма не открывается, и
  причина называется словами.

**Откуда берутся параметры.** Из самого Typst: ядро читает описание функции у
компилятора (`Func::params()`) — полный набор параметров, их типы, умолчания и описание из
справочника. Файла схемы нет, сверять и дописывать после обновления Typst нечего: новый
параметр появляется в форме сам. Поля названы так же, как в Typst (`width`, `caption`),
подсказка у поля — описание из справочника. Какой элемент вставляет запись меню, ядро
узнаёт, разобрав её шаблон; «Параметры» работают для любого вызова встроенной функции
Typst в заметке.

## Внешние шаблоны Typst

Заметка может подключать шаблон из общего реестра Typst: `#import "@preview/имя:1.2.3": *`.
Если такой версии в папке заметок нет, приложение **само скачивает её** и собирает документ
([`specs/007-template-download`](specs/007-template-download/spec.md)). Это единственное место,
где приложение обращается в сеть.

- **Что уходит с устройства** — только имя и версия шаблона, записанные в заметке. Ни текст,
  ни имена заметок наружу не отправляются.
- **Куда кладётся** — `<vault>/.typsidian/packages/<пространство>/<имя>/<версия>/`, рядом с
  заметками, и переезжает вместе с папкой. Там же `installed.json` — перечень установленного
  с адресами источников.
- **Что видно** — каждая загрузка называется в предпросмотре: имя, версия, полный адрес и
  отпечаток содержимого. Отказ называется причиной (сети нет, версии нет в источнике, среда
  запретила обращение, …) и тем же адресом.
- **Как выключить** — настройки: на web раздел «Vault» → «Внешние шаблоны Typst», на desktop
  и Android раздел «Шаблоны Typst»; флажок «Загружать недостающие шаблоны». Выключенная
  автозагрузка не отнимает явной: у замечания об отсутствующем шаблоне есть кнопка
  «Загрузить шаблон». Настройка хранится в `.typsidian/vault.json` (`templates.auto_download`).
- **Свой адрес** — там же, «Свои адреса»: архив для конкретной версии шаблона берётся по
  указанному адресу, а не из реестра.
- **Правка установленного** — приложение сверяет содержимое с отпечатком, записанным при
  установке, и сообщает о расхождении, но ничего не перезаписывает.
- **Без сети** — шаблон можно положить в ту же папку вручную: `typst.toml` в корне папки
  версии — признак того, что шаблон установлен. Пространства имён кроме `@preview` (например,
  `@local`) всегда только локальные.

## Синхронизация

История версий и доставка vault между устройствами
([`specs/011-vault-sync`](specs/011-vault-sync/spec.md)). Синхронизация необязательна:
vault без неё работает как раньше, а отключение ничего не удаляет.

- **История** — обычный `.git` в папке vault, читается стандартным git. Включается мастером
  из панели «Синхронизация» (пилюля в шапке или `Ctrl/⌘+Alt+S`): приложение показывает
  точный текст правил исключения, которые допишет в `.gitignore`, спрашивает автора и делает
  первый снимок. Дальше — список изменений с выбором файлов, снимок (`Ctrl/⌘+Alt+C`),
  история заметки (`Ctrl/⌘+Alt+H`), сравнение версий и возврат к любой из них; возврат
  версии открытой заметки — обычная правка редактора и отменяется `Ctrl+Z`.
- **Удалённый репозиторий** — адрес и токен; на рабочем столе также ssh с ключами системы.
  Токен хранится в хранилище секретов устройства (в браузере — в хранилище браузера, о чём
  диалог предупреждает) и никогда не попадает в vault. Отправка, получение со слиянием, а
  при встречных правках — редактор слияния: своя версия, их и общая, результат можно
  поправить руками, получение можно отменить целиком.
- **Syncthing** — если папку доставляет Syncthing, приложение это видит, предлагает правила
  для `.stignore` (чтобы история и кэши не уехали на другие устройства) и убирает
  конфликтные копии `*.sync-conflict-*` из дерева, поиска и графа в список конфликтов. С
  разрешения пользователя читает состояние папки у локального Syncthing — только читает.
- **Правила исключения** — `.gitignore` и `.stignore` открываются и правятся прямо из панели
  «Синхронизация» ([`specs/012-ignore-rules-editor`](specs/012-ignore-rules-editor/spec.md)).
  Виден весь файл, строки приложения подсвечены; если после правки их не хватает,
  приложение называет недостающие, возвращает их одним действием и без подтверждения такой
  файл не сохраняет. Файл, изменённый на диске за время правки, не перезаписывается молча.
- **Хранитель истории** — когда vault доставляет Syncthing, снимки делает одно устройство.
  Остальные читают историю из копии удалённого репозитория; снимок с не-хранителя требует
  явного подтверждения.
- **По оболочкам.** В браузере нет ssh и чтения состояния Syncthing, а обмен идёт только с
  серверами, разрешающими обращения со страниц, либо через указанного пользователем
  посредника; на Android нет ssh. Недоступное не прячется: действие отключено, причина
  названа.

Настройки автоснимков и автообмена — в разделе «Синхронизация» панели настроек; команды
можно переназначить в разделе «Кейбиндинги».

## Окружение разработки

### Через Nix (рекомендуется)

```bash
nix develop
```

Шелл даёт всё сразу: Rust stable с таргетом `wasm32-unknown-unknown`, `wasm-pack`,
`wasm-bindgen-cli`, `binaryen`, Node 22, pnpm, `cargo-tauri` с системными WebKitGTK/GTK для
линковки Tauri, sqlite, neovim и chromium+chromedriver из nixpkgs — последние два нужны, чтобы
`wasm-bindgen-test` реально гонялся в браузере (свой chromedriver от `wasm-pack` на NixOS не
стартует).

Android SDK/NDK сюда **не** входят — они весят ~3 ГБ и живут в отдельном шелле:

```bash
nix develop .#android
```

Это всё то же самое плюс JDK 17, Android SDK и NDK из `androidenv` и rust-std под четыре ABI
Android. Лицензия Google на SDK несвободна; разрешение выдаётся точечным предикатом по
`meta.homepage`, а не глобальным `allowUnfree`.

### Вручную

- Rust stable + таргет `wasm32-unknown-unknown`
- `wasm-pack`, `wasm-bindgen-cli`
- Node 22, pnpm 10+
- Для desktop: `cargo-tauri`, pkg-config и системные WebKitGTK 4.1 / GTK3 / libsoup3 / dbus
- Для Android: JDK 17, Android SDK (platform 36, build-tools 35.0.0), NDK 27, таргеты
  `aarch64-linux-android` и остальные три ABI
- Для wasm-тестов: Chromium и chromedriver

## Сборка и запуск

Порядок важен: ядро → wasm-биндинги → общий UI → клиент.

```bash
pnpm install

# 1. Собрать ядро в WASM и разложить биндинги в ui/src/wasm-core
pnpm build:wasm

# 2. Собрать общий UI-пакет (tsc + копирование стилей и wasm-core в ui/dist)
pnpm --filter @typsidian/ui build
```

**Web:**

```bash
pnpm dev            # next dev
pnpm build          # next build
```

Веб-клиент опирается на File System Access API и OPFS — нужен браузер на Chromium.

**Desktop:**

```bash
pnpm --filter @typsidian/desktop dev    # cargo tauri dev
pnpm --filter @typsidian/desktop build  # cargo tauri build
```

Запуск собранной оболочки — из корня репозитория:

```bash
nix run .#desktop
```

Не `./target/release/typsidian-desktop` напрямую: на NixOS этот бинарь не самодостаточен,
ему нужны `LD_LIBRARY_PATH` (libgdk, WebKit) и `XDG_DATA_DIRS` (схемы GSettings). Из голого
шелла он падает с `libgdk-3.so.0: cannot open shared object file`, а из dev-shell, в который
вошли до правки `flake.nix`, — с `GLib-GIO-ERROR: Settings schema 'org.gtk.Settings.FileChooser'
is not installed` и сбросом образа памяти. `nix run .#desktop` вычисляет окружение в момент
запуска и устареть не может. Собранный `.deb` на NixOS тоже не поставится — он для других
дистрибутивов.

Только через `cargo tauri`, **не** `cargo build -p typsidian-desktop`. Голый `cargo build`
собирает Tauri в dev-режиме (`tauri-build` выставляет `cfg(dev)`), и в бинарь вместо
фронтенда попадает `http://localhost:1420` — запуск такого бинаря без поднятого Vite даёт
`Could not connect to localhost: Connection refused`, хотя сборка прошла успешно. Фронтенд
вшивается только под feature `tauri/custom-protocol`, которую включает `cargo tauri build`;
он же сначала прогоняет `vite build`.

**Android:**

Нужен отдельный шелл — Android SDK и NDK весят ~3 ГБ, и в `nix develop` по умолчанию их нет:

```bash
nix develop .#android

cd apps/mobile
pnpm build           # cargo tauri android build --apk
pnpm build:aab       # то же в .aab для публикации
pnpm dev             # cargo tauri android dev, на подключённом устройстве
```

Первый запуск: `pnpm android:init` (`cargo tauri android init`) — он создаёт
`src-tauri/gen/android`. Каталог **уже в репозитории**, и повторный `init` перезапишет в нём
правки, которых в шаблоне нет: разрешение на общую память в `AndroidManifest.xml` и запрос
этого разрешения в `MainActivity.kt`. Если пришлось перегенерировать — сверить эти два файла.

`--target aarch64` собирает только под arm64; без него собираются все четыре ABI и сборка
идёт вчетверо дольше.

Vault на Android лежит по фиксированному пути `Documents/Typsidian` в общей памяти
устройства. Выбора папки нет: `pick_folder` у `tauri-plugin-dialog` реализован только под
desktop, а SAF отдаёт `content://`-адреса, которых `NativeBackend` не понимает. При первом
запуске система спросит доступ ко всем файлам — без него приложение не сможет создать папку
и покажет отказ. Корзины на Android нет: удаление сразу безвозвратное.

Доски на мобильном рисуются наравне с остальными клиентами (с 2026-09-23; раньше профиль
записи выбирался таргетом сборки и давал на планшете холст без инструментов). Профиль
просмотра из ядра никуда не делся — он просто не назначается ни одной сборкой.

`--apk` в release даёт **неподписанный** APK — установить его нельзя. Для установки либо
`--debug` (подписывается отладочным ключом автоматически), либо своя подпись: положить
keystore и `key.properties` в `apps/mobile/src-tauri/gen/android` (оба уже в `.gitignore`
шаблона) и добавить `signingConfigs` в `app/build.gradle.kts`.

## Тесты и проверки

```bash
cargo test -p typsidian-core                          # ядро, нативный таргет
wasm-pack test --headless --chrome packages/core      # ядро, wasm32
cargo build -p typsidian-core --target wasm32-unknown-unknown
pnpm typecheck                                        # tsc --noEmit по всем пакетам
```

Бенчмарки ядра (`harness = false`, меряют сквозные сценарии, а не микрооперации):

```bash
cargo bench -p typsidian-core --bench vault_scale
cargo bench -p typsidian-core --bench vault_bulk_change
cargo bench -p typsidian-core --bench board_digest
```

Корневой `cargo build`/`cargo test` намеренно ограничен ядром через `default-members`: иначе
проверка wasm-таргета в корне тянула бы Tauri, GTK и WebKit под wasm32 и падала.

## Как ведётся работа

Проект живёт по [конституции](.specify/memory/constitution.md) и процессу
[Spec Kit](https://github.com/github/spec-kit). Ключевое, что стоит знать до первого PR:

1. **Бизнес-логика — только в `packages/core`.** UI её не дублирует и не «подстраховывает».
2. **Паритет двух таргетов (non-negotiable).** Изменение ядра обязано собираться и проходить
   тесты и под `wasm32-unknown-unknown`, и нативно. Иначе фича не готова.
3. **`spec.md` описывает только поведение** — без API, крейтов и путей к файлам. Технические
   решения живут в `plan.md`.
4. **TypeScript strict, без `any`** и без `@ts-ignore` в роли глушителя ошибок типов.
5. **Мост к Neovim и встраиваемые движки — зона повышенного риска:** отдельный
   `/speckit-clarify` до планирования, синхронизация с файлом vault вместо общего состояния,
   никакой стилизации чужого DOM.
6. **Индексы и поиск строятся локально.** Содержимое заметок не покидает устройство — включая
   эмбеддинги, сводки и любые производные представления.
