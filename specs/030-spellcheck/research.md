# Research: Проверка орфографии

## 1. Чем проверять

**Decision**: крейт `spellbook` 0.4.2 (MPL-2.0) — проверка и подсказки по словарям Hunspell
на чистом Rust, `no_std` + `alloc`, собирается под `wasm32` и нативный таргет без системных
библиотек. Словари `ru_RU` (А. Лебедев, BSD-подобная лицензия, LibreOffice 6.3.0.4) и
`en_US` (SCOWL 2026.02.25) лежат в `packages/core/dictionaries/`. Нативной сборке (рабочий стол,
Android, `cargo test`) они вшиты `include_str!`; wasm приложения получает их файлами рядом с
модулем (`scripts/spell-dictionaries.mjs` → `/dictionaries/`, кэш устройства) и отдаёт в
`SpellChecker.loadDictionary` — как шрифты предпросмотра (005 T029): 4 МБ словарей не
раздувают модуль, который пересобирается на каждом релизе. Тестам wasm словари вшиты фичей
`embedded-dictionaries`. `ru_RU` переведён из KOI8-R в UTF-8 (`SET UTF-8`) — `spellbook` читает только
UTF-8; переделка отмечена в `dictionaries/NOTICE.md`, как требует лицензия.
**Rationale**: одна проверка во всех оболочках и офлайн (принципы II, VII; FR-006, FR-007).
Замер (нативно, release): загрузка `ru_RU` — 69 мс, `en_US` — 11 мс, один раз за процесс
(`OnceLock`); проверка слова ~3 мкс; подсказки к слову ~160 мс. Словари грузятся лениво при
первой проверке языка.
**Alternatives**: орфография браузера/ОС (`spellcheck` у `contenteditable`) — не отличает
разметку Typst от текста, нет в WebKitGTK по умолчанию, разная по оболочкам; `hunspell` через
FFI — нет под `wasm32`; `zspell` — медленнее загрузка, нет подсказок; словари отдельным
ресурсом UI — на web их пришлось бы тянуть по сети, а файл ядра уже кэшируется целиком.
Цена — +4 МБ к бинарю рабочего стола и к статике web; wasm-модуль не растёт.

## 2. Что проверяется

**Decision**: проверка идёт по дереву сессии подсветки 024 (`HighlightSession`): листья
`SyntaxKind::Text` в режиме разметки. Узлы `Raw`, `Equation`/математика, код (`#…`, аргументы,
строки), `Label`, `Ref`, `Link`, комментарии — другие виды, в них `Text` не заходит или
обход их пропускает. Вики-ссылки `[[…]]` для Typst — обычный текст, их диапазоны вычитаются
по `graph::link_sites`. Окна — те же, что у подсветки (видимая часть ± 50 строк).
**Rationale**: граница «текст/разметка» та же, что у сборки и раскраски (FR-002, SC-001);
второй разбор не нужен — сессия уже держит инкрементальное дерево.

## 3. Слова и языки

**Decision**: слово — непрерывная последовательность букв (Unicode `Alphabetic`) с
внутренними `-` и `'`/`’`. Не проверяются: короче 2 букв, с цифрами, из двух азбук, целиком
в верхнем регистре. Язык — по азбуке: кириллица → `ru`, латиница → `en`; язык выключен —
слово не проверяется. Слово с дефисом верно, если верно целиком или верна каждая часть.
`ё` → `е` при второй попытке. Слово из словаря vault (без учёта регистра) верно.

## 4. Словарь vault

**Decision**: `.typsidian/dictionary.txt`, UTF-8, слово в строке, отсортировано, без
повторов. Пишется через `VaultBackend::write` служебного файла — едет с синхронизацией 011
(не производный путь). Добавить/убрать — функции ядра, они же обновляют проверяющий объект.

## 5. Где состояние проверки

**Decision**: `SpellChecker` — объект ядра: включено, языки, слова vault. На web — объект
wasm у клиента, на Tauri — состояние оболочки `Speller(Mutex<SpellChecker>)`. Настраивается
`spell_configure(backend)` при открытии vault и после смены настроек; сессия подсветки
получает его в вызове `spelling(windows)`. Словари — общие неизменяемые `OnceLock`.

## 6. Когда и как часто

**Decision**: UI спрашивает ошибки через 400 мс после последней правки и при прокрутке, тем
же расписанием, что подсветка, только реже; ответ не задерживает ввод (SC-002). Подсказки —
при открытии меню на подчёркнутом слове, до пяти.

## 7. Меню на телефоне

**Decision**: на телефоне то же контекстное меню редактора (долгое нажатие), без отдельного
листа с кнопками-чипами из макета O2.
**Rationale**: все меню редактора на телефоне — общий `ContextMenu`; отдельный лист только
для орфографии выпал бы из ряда. Расхождение с макетом намеренное.
