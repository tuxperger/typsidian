# Feature Specification: Шифрование заметок

**Feature Branch**: `036-note-encryption`

**Created**: 2026-10-21

**Status**: Draft

**Priority**: P3

**Summary**: Личную заметку или папку можно зашифровать паролем: на диске и в синхронизации лежит только шифр, а в приложении после ввода пароля заметка правится как обычная.

**Input**: User description: "Шифрование отдельных заметок или папок паролем, в том числе для синхронизации."

## Clarifications

### Session 2026-10-21

- Q: Нужен ли сброс пароля? → A: Нет: забытый пароль означает потерю данных, и приложение
  говорит об этом при шифровании прямо. Иначе шифр был бы обходим. Закрыто без вопроса
  пользователю — это свойство шифрования, а не выбор.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Зашифровать и открыть (Priority: P1)

Пользователь выбирает «Зашифровать…» для заметки, задаёт пароль дважды и подтверждает, что
понимает: без пароля текст не вернуть. Файл на диске становится зашифрованным. При открытии
приложение спрашивает пароль; после ввода заметка правится как обычная и сохраняется снова
зашифрованной.

**Independent Test**: Зашифровать заметку, прочитать файл на диске — текста заметки в нём
нет; открыть в приложении с паролем — текст прежний.

**Acceptance Scenarios**:

1. **Given** заметка, **When** она зашифрована, **Then** в файле нет её текста, а дерево
   показывает её с замком.
2. **Given** зашифрованная заметка, **When** введён верный пароль, **Then** она открывается и
   правится; сохранение пишет только шифр.
3. **Given** неверный пароль, **Then** сказано «пароль не подошёл», файл не тронут.
4. **Given** заметка расшифрована пользователем («Снять шифрование»), **Then** файл снова
   обычный текст.

---

### User Story 2 - Папка и сессия (Priority: P2)

Шифрование папки шифрует все её заметки одним паролем; пароль запоминается до блокировки
(команда «Заблокировать» или бездействие N минут).

### Edge Cases

- Предпросмотр, поиск, связи и граф видят зашифрованную заметку только после ввода пароля;
  без пароля — только её имя.
- Пароль и расшифрованный текст не пишутся на диск, в журналы и снимки (029) в открытом виде.
- Синхронизация (011) переносит шифр как обычный файл.
- Формат шифра описан открыто, чтобы заметку можно было расшифровать без приложения.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Пользователь MUST мочь зашифровать заметку или папку паролем и снять шифрование.
- **FR-002**: Файл зашифрованной заметки MUST NOT содержать её текст в открытом виде.
- **FR-003**: Открытие MUST требовать пароль; неверный пароль MUST NOT менять файл.
- **FR-004**: Пароль и открытый текст MUST NOT сохраняться на диск, в журналы и снимки.
- **FR-005**: Пароль MUST забываться при блокировке и по бездействию.
- **FR-006**: Шифр MUST использовать проверенный стандартный алгоритм; формат — описан.
- **FR-007**: Одинаково во всех оболочках (принцип II).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 0 байт открытого текста зашифрованной заметки в файлах vault, журналах и снимках.
- **SC-002**: Заметка открывается после ввода пароля не дольше 1 с.

## Assumptions

- Зависит от 001 (файлы), 011 (синхронизация), 029 (снимки — исключение для шифрованных).
- Требует ревью безопасности до реализации.
