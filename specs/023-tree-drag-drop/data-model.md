# Data Model: Перетаскивание в дереве файлов

Все типы — в `packages/core/src/vault/relocate.rs`, `serde` + `Tsify`; в `ui/` приходят
через `import type` из `wasm-core`. Пути — относительно корня vault; корень — пустой
путь.

## MoveRequest

| Поле | Тип | Смысл |
|---|---|---|
| `from` | `PathBuf` | переносимый элемент: заметка, доска или папка |
| `to_folder` | `PathBuf` | цель; пустой путь — корень vault |

## MoveTarget

Строка списка «Переместить в…» и элемент множества допустимых целей жеста.

| Поле | Тип | Смысл |
|---|---|---|
| `path` | `PathBuf` | путь папки; пустой — корень |
| `name` | `String` | имя папки; для корня — имя vault |
| `parent` | `String` | путь родителя для показа справа; у корня пусто |
| `is_section` | `bool` | папка помечена разделом (006) |
| `name_match` | `Option<TextSpan>` | где в `name` совпал фильтр; `None` — совпало в пути или фильтра нет |

Правила: в список не входят папка, где элемент уже лежит, сам элемент-папка, его
потомки, служебная папка vault (006). Порядок: корень, затем по пути.

## MovePlan (внутренний, не пересекает границу)

| Поле | Тип | Смысл |
|---|---|---|
| `steps` | `Vec<(PathBuf, PathBuf)>` | пары «откуда → куда» верхнего уровня: сам элемент и, для одиночной заметки, её собственные папки снимков (research.md §2) |
| `notes` | `Vec<PathChange>` | пары по каждой переезжающей заметке и доске |
| `folders` | `Vec<PathChange>` | пары по каждой переезжающей папке |

## PathChange

`{ from: PathBuf, to: PathBuf }`.

## MoveImpact

| Поле | Тип | Смысл |
|---|---|---|
| `broken` | `Vec<Note>` | заметки, у которых после переноса хотя бы одна рабочая ссылка станет битой; отсортированы по пути. Пусто — предупреждение не показывается (FR-016) |

## MoveRefusal

Причина отказа до изменений на диске. `#[serde(tag = "kind")]`.

| Вариант | Когда | FR |
|---|---|---|
| `SamePlace` | элемент уже лежит в цели — интерфейс молчит | FR-005 |
| `IntoItself` | цель — сама папка или её потомок | FR-003 |
| `NameConflict { name }` | в цели занято имя элемента или его папки снимков | FR-004, FR-018a |
| `NotFound` | элемента больше нет | Edge cases |
| `TargetNotFound` | цели больше нет | Edge cases |
| `AccessDenied` | vault недоступен или только для чтения | FR-006 |
| `ServiceFolder` | элемент или цель — служебная папка vault | Edge cases |

## MoveOutcome

`#[serde(tag = "kind")]`.

| Вариант | Поля | Смысл |
|---|---|---|
| `Done` | `moved: Vec<PathChange>`, `folders: Vec<PathChange>`, `undo: MoveRequest` | перенос выполнен целиком |
| `Cancelled` | — | отменён до удаления источника; на диске ничего не изменилось |
| `Partial` | `moved`, `folders`, `left: Vec<PathBuf>` | цель получила всё, но часть источника удалить не удалось (только web); `left` — что осталось на прежнем месте (FR-007) |

Ошибка операции: `MoveError = Refused(MoveRefusal) | Io` — `Io` означает, что на диске
ничего не изменилось (native: откат обратным `rename`; web: копия в цели удалена).

## MoveControl

Ход и отмена массового переноса (принцип X). Трейт ядра:
`fn progress(&self, done: u32, total: u32)` и `fn cancelled(&self) -> bool`. Native —
пустая реализация (один системный вызов). Web — объект с колбэком и флагом.

## Состояние, следующее за путём

| Что | Где живёт | Как переезжает |
|---|---|---|
| записи индекса заметок | `NoteIndex` | новый `rename_prefix(from, to)` |
| буфер, конфликт, «удалено с правками» | `ConflictRegistry` | новый `rename_prefix(from, to)` |
| таблица ссылок | `VaultCache` | `rename_note` по каждой заметке + переразбор исходящих ссылок перенесённых |
| пометки разделов | настройки vault | `move_sections` (есть) |
| открытый файл, раскрытые папки, выделение | `Workspace`, `useVaultTreeActions` | по `MoveOutcome.moved`/`folders` |

## Переходы жеста (интерфейс, `useTreeDrag`)

```text
idle ──pointerdown──▶ armed ──сдвиг ≥4px (мышь) / 400 мс (палец)──▶ dragging
armed ──pointerup / сдвиг пальца до порога──▶ idle        (обычный клик / прокрутка)
dragging ──pointerup над допустимой целью──▶ dropping ──исход──▶ idle
dragging ──Escape / pointerup вне цели / blur окна / pointercancel──▶ idle
```

В `dragging` хранится: переносимый элемент, множество допустимых целей (ответ
`move_targets`), текущая цель, таймер раскрытия папки.
