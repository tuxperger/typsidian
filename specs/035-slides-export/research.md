# Research: Экспорт презентации

## 1. Слайды и шаги

**Decision**: сведения о страницах — те же `PageSlideInfo`, что у показа 019 (логический номер
из `<pdfpc>` и заметки докладчика). Слайд — подряд идущие страницы с одним логическим
номером; страница без номера — отдельный слайд. «Последний шаг» — последняя страница слайда,
«все шаги» — все страницы (FR-003, SC-001).

## 2. PDF слайдов и для pdfpc

**Decision**: `Render::Pdf` получает список страниц (`PdfMeta.pages`) → `PdfOptions.page_ranges`
`typst-pdf`. Для pdfpc — все шаги и `.pdfpc` (JSON, `pdfpcFormat: 2`): `pages[]` с `idx`,
`label` (номер слайда), `overlay` (номер шага в слайде), `note`; так его пишет Polylux/Touying
и открывает pdfpc ≥ 4.5 (SC-002).

## 3. PDF со страницами заметок

**Decision**: вторая сборка без vault: выбранные страницы слайдов — SVG (`typst-svg`)
виртуальными файлами; главный файл — страницы шириной в слайд, `height: auto`: слайд
`image(…, width: 100%)` и заметки строкой Typst (без разбора разметки — заметки как текст).
Вектор слайда сохраняется.

## 4. Картинки

**Decision**: `Render::Images { png_scale, pages }` — по файлу на выбранную страницу: SVG
(`typst-svg`) или PNG (`typst-render` 0.15.1, чистый Rust, `pixel_per_pt` = масштаб × 1);
байты упакованы в один буфер (`u32` число файлов, затем `u32` длина + байты) — так они
проходят тот же путь, что PDF, включая воркер web. Имена: `NN.ext` или `NN-K.ext` при всех
шагах.

## 5. Где и как

**Decision**: модуль ядра `slides/export.rs`: `export_slides(backend, packages, note, text,
fonts, overrides, request) -> SlidesExportReport` — сборка той же цепочкой 009
(`build_with_templates`), запись `write_bytes` в папку экспорта. Ошибка сборки — ничего не
пишется, диагностики названы (как 009). UI: пункт в меню «Показ» и команда палитры; окно
выбора и итог.
