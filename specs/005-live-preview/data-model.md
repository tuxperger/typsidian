# Data Model: Note Rendering and Live Preview

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

Все сущности живут в `packages/core/src/preview/`. Ни одна не хранится на диске: свёрстанный
вид между запусками не сохраняется (Out of Scope спеки), поэтому всё ниже — состояние в памяти
плюс форма того, что пересекает границу ядро→UI.

## `CompiledDocument` — свёрстанный вид

Соответствует сущности «Свёрстанный вид» из спеки.

| Поле | Тип | Смысл |
|------|-----|-------|
| `revision` | `u64` | Версия текста заметки, из которой собран этот результат. Монотонна (research.md §9) |
| `note_path` | `PathBuf` | Заметка, к которой относится результат |
| `pages` | `Vec<RenderedPage>` | **Все** страницы документа по порядку — не только изменившиеся |
| `diagnostics` | `Vec<Diagnostic>` | Ошибки и предупреждения этой сборки |
| `outcome` | `CompileOutcome` | Чем закончилась сборка |

**Правила**:
- Результат с `revision` меньше уже показанного UI отбрасывает (FR-009).
- `pages` непуст при `outcome == Succeeded`; при неуспехе он пуст, а UI продолжает показывать
  предыдущий `CompiledDocument`, помечая его устаревшим (FR-014).

## `CompileOutcome` — чем закончилась сборка

```
Succeeded                      // документ собран; diagnostics могут содержать предупреждения
Failed                         // документ не собран; diagnostics содержат хотя бы одну ошибку
TimedOut                       // прекращена по пределу 10 с (FR-026)
Cancelled                      // заметка закрыта или заменена (FR-011)
VaultUnavailable               // vault стал недоступен во время сборки (FR-025)
DependencyBudgetExhausted      // снимок не сошёлся за предел итераций (research.md §2)
```

**Запрещённые переходы**: `Succeeded` не может нести ни одной диагностики серьёзности
`Error` — иначе UI не сможет решить, показывать новый вид или помечать старый устаревшим.
`Cancelled` и `TimedOut` **не** изменяют ни одного файла vault (FR-026).

## `RenderedPage` — одна страница

| Поле | Тип | Смысл |
|------|-----|-------|
| `number` | `u64` | Логический номер страницы (`Page::number`, может не совпадать с физическим) |
| `index` | `usize` | Физический порядковый номер, 0-based |
| `width_pt` / `height_pt` | `f64` | Размер страницы в пунктах — UI нужен для раскладки и масштаба |
| `svg` | `String` | Визуальный слой, `typst_svg::svg(page, &opts)` |
| `text_runs` | `Vec<TextRun>` | Текстовый слой поверх SVG (см. [contracts/text-layer.md](./contracts/text-layer.md)) |
| `digest` | `[u8; 32]` | Хэш `Page` — единица сравнения между сборками |

**Правила**:
- `digest` считается от `Page` (тип выводит `Hash`, `typst-layout-0.15.1/src/document.rs:79`).
  Ядро отдаёт страницу всегда; `digest` нужен UI, чтобы **не перерисовывать** ту, что не
  изменилась с прошлой сборки (research.md §5).
- `svg` и `text_runs` описывают одну и ту же страницу и обязаны быть согласованы: текстовый
  прогон без соответствующего изображения — дефект.

## `TextRun` — прогон текста в текстовом слое

Извлекается обходом `Frame` страницы из `FrameItem::Text(TextItem)`.

| Поле | Тип | Смысл |
|------|-----|-------|
| `text` | `String` | Текст прогона (`TextItem::text`) — то, что попадёт в буфер обмена |
| `x_pt` / `y_pt` | `f64` | Позиция базовой линии в координатах страницы |
| `width_pt` | `f64` | Ширина прогона — нужна, чтобы растянуть невидимый текст по месту |
| `size_pt` | `f64` | Кегль (`TextItem::size`) |
| `lang` | `Option<String>` | Язык прогона (`TextItem::lang`) — объявляется программе чтения с экрана (FR-032) |

**Правила**:
- Порядок `text_runs` — порядок чтения документа, а не порядок обхода кадра. От этого зависит,
  что именно пользователь получит, выделив несколько абзацев (FR-031, SC-011).
- Прогоны не склеиваются между страницами.

## `Diagnostic` — одно замечание

Соответствует сущности «Диагностика» из спеки. Строится из `SourceDiagnostic` и
`WorldExt::range` (research.md §7).

| Поле | Тип | Смысл |
|------|-----|-------|
| `severity` | `Error` \| `Warning` | Из формы `Warned`, а не из разбора текста (FR-018) |
| `message` | `String` | Причина словами (FR-012) |
| `location` | `Option<DiagnosticLocation>` | Место; `None` для диагностики без привязки к файлу |

## `DiagnosticLocation` — место замечания

| Поле | Тип | Смысл |
|------|-----|-------|
| `path` | `PathBuf` | Файл vault, к которому относится место |
| `is_open_note` | `bool` | Это сама открытая заметка или связанный файл |
| `openable` | `bool` | Открывается ли файл в редакторе — решает, предлагать ли переход (FR-033) |
| `line` / `column` | `u32` | Позиция, 1-based, для показа пользователю |
| `byte_range` | `Range<usize>` | Диапазон для точной установки курсора (FR-015) |

**Правила**:
- `openable == false` для шрифтов и изображений: перехода к ним не предлагается, показываются
  только имя и причина (FR-033).
- Сортировка списка диагностик — по `(path, byte_range.start)` (FR-016).

## `DependencySnapshot` — снимок зависимостей

Внутренняя сущность фазы резолва (research.md §2). Наверх не отдаётся.

| Поле | Тип | Смысл |
|------|-----|-------|
| `main` | `FileId` | Открытая заметка — точка входа |
| `files` | `HashMap<FileId, Bytes>` | Всё, что уже вычитано: исходники, изображения, шрифты vault |
| `missing` | `HashSet<FileId>` | Запрошено сборкой, но ещё не вычитано |
| `iterations` | `u8` | Сколько раз чередовались резолв и сборка |

**Правила**:
- `World` читает **только** из `files` и никогда не обращается к файловой системе.
- Пополнение `missing` — единственный сигнал фазе резолва, что нужен ещё один проход.
- `iterations` ограничен (предлагается 8); превышение даёт `DependencyBudgetExhausted`, а не
  бесконечный цикл.
- Байты в `files` — простые данные: `World` обязан быть `Send + Sync`, поэтому браузерные
  хендлы туда положить нельзя даже случайно (research.md §11).

## `PreviewState` — состояние панели (UI)

Живёт в `ui/`, но перечислен здесь, потому что задаёт, что видит пользователь.

| Поле | Смысл |
|------|-------|
| `shown` | Последний **успешно** собранный `CompiledDocument` или `null` |
| `is_stale` | `shown` не соответствует текущему тексту (FR-014) |
| `is_building` | Идёт пересборка — показывается признак, но `shown` не убирается (FR-010) |
| `diagnostics` | Диагностики последней сборки, даже если она провалилась |
| `anchor` | Якорь места в содержимом для удержания прокрутки (FR-004, FR-034) |

**Переходы**:
- `is_building: true` **никогда** не обнуляет `shown` — это и есть FR-010.
- Успешная сборка: `shown` заменяется, `is_stale = false`.
- Провалившаяся сборка: `shown` остаётся, `is_stale = true`, `diagnostics` заменяются.
- Исправление ошибки: `is_stale = false`, `diagnostics` пустеет (FR-017).
- `shown == null` и есть ошибки — единственное состояние, в котором панель не показывает
  документ; она обязана назвать причину (FR-014).
