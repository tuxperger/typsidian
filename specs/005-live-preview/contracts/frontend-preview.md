# Contract: Что UI получает от ядра

**Feature**: [../spec.md](../spec.md) | **Plan**: [../plan.md](../plan.md)

UI не решает ничего из перечисленного сам — он отображает готовое (принцип I). В частности, он
**не** определяет, устарел ли вид, **не** сортирует диагностики и **не** решает, можно ли
перейти к месту ошибки: всё это приходит из ядра.

## События предпросмотра

Поток `PreviewEvent` доставляется тем же способом, что и `VaultEvent` фичи 001: pull-методом
`pollEvents` на web, каналом событий Tauri на native. Второго механизма подписки фича не вводит.

```rust
pub enum PreviewEvent {
    /// Сборка началась. UI показывает признак пересборки, НЕ убирая текущий вид
    /// (FR-010).
    BuildStarted { note_path: PathBuf, revision: u64 },

    /// Сборка завершилась. Полная форма — в data-model.md.
    BuildFinished { document: CompiledDocument },

    /// Изменился связанный файл — заметка будет пересобрана (FR-020, FR-029).
    /// Отдельное событие, потому что причина пересборки другая: пользователь
    /// эту заметку не трогал.
    DependencyChanged { note_path: PathBuf, dependency: PathBuf },
}
```

**Гарантии**:
- `BuildFinished` с `revision` меньше уже доставленного не отправляется (FR-009).
- Между `BuildStarted` и `BuildFinished` предыдущий показанный документ остаётся валидным для
  показа — UI обязан его не убирать (FR-010).
- После закрытия заметки события по ней не приходят (FR-011).

## Поверхность клиента

Расширение существующего `VaultClient` (`ui/src/vault-client.ts`), а не второй интерфейс:
предпросмотр относится к той же открытой заметке.

```ts
export interface PreviewClient {
  /**
   * Поставить в очередь сборку текущего текста заметки.
   *
   * Вызывается по паузе в наборе, а не на каждое нажатие: дебаунс живёт в UI,
   * потому что он про ритм ввода, а не про правила сборки. Ядро при этом само
   * отбрасывает устаревшие результаты по `revision` — UI на это не полагается
   * как на единственную защиту, но и не дублирует её.
   */
  requestBuild(notePath: string, text: string, revision: number): Promise<void>;

  /** Отменить сборку заметки: она закрыта или заменена другой (FR-011). */
  cancelBuild(notePath: string): Promise<void>;

  /** Подписка на поток `PreviewEvent`. Возвращает функцию отписки. */
  subscribePreview(onEvents: (events: PreviewEvent[]) => void): () => void;
}
```

**Важно для web-реализации**: все вызовы экземпляра ядра обязаны идти через очередь
сериализации (`ui/src/wasm-call-queue.ts`). Экспортированный `async`-метод с `&mut self` держит
заимствование объекта до конца future, и наложение сборки на цикл опроса vault даёт
`recursive use of an object detected`. Это уже работающее правило проекта, а не новое.

## Что показывает панель

| Состояние ядра | Что видит пользователь | Требование |
|----------------|------------------------|------------|
| Идёт первая сборка, показывать нечего | Признак сборки, панель пуста без ложных обещаний | FR-010 |
| `Succeeded` | Страницы документа; пометки устаревания нет | FR-001 |
| `Succeeded` с предупреждениями | Страницы **и** список предупреждений; показ не блокируется | FR-018 |
| `Failed`, ранее был успех | Прежний вид с пометкой «не соответствует тексту» + список ошибок | FR-014 |
| `Failed`, успеха не было | Прямое сообщение, что показывать нечего, **и причина** | FR-014 |
| `TimedOut` | Прежний вид + сообщение о причине остановки | FR-026 |
| `VaultUnavailable` | Сообщение о недоступности; текст в редакторе не тронут | FR-025 |
| `Cancelled` | Ничего: заметка уже закрыта | FR-011 |

**Запрещено**: пустая панель без объяснения в любом состоянии (SC-004).

## Переход к месту ошибки

UI берёт решение из `DiagnosticLocation`, а не выводит его сам:

- `is_open_note == true` → поставить курсор в текущем редакторе на `byte_range`.
- `is_open_note == false`, `openable == true` → открыть `path` в редакторе и поставить курсор
  (FR-015). Одновременный показ двух файлов не вводится.
- `openable == false` → действия перехода **не показывать** вовсе; только имя файла и причина
  (FR-033). Показывать недействующую кнопку запрещено.

## Удержание места при пересборке

Якорь — место в содержимом, а не смещение от начала документа (FR-004).

**Разделение обязанностей**: правило «какое место в новом документе считать тем же самым»
решает **ядро** (`packages/core/src/preview/anchor.rs`). Это правило над содержимым документа,
а не affordance интерфейса, и SC-005 делает его проверяемой гарантией — по принципу I его
место в ядре, и оно покрывается тестами на обоих таргетах. UI снимает якорь с того, что видно
на экране, и прокручивает к тому, что вернуло ядро; сам ничего не сопоставляет.

```ts
/** Место документа, которое нужно удержать на экране при пересборке. */
export interface ScrollAnchor {
  /** Индекс страницы, с которой снят якорь. */
  pageIndex: number;
  /** Текст прогона, по которому опознаётся место после переверстки. */
  runText: string;
  /** Порядковый номер прогона на странице — различает повторяющийся текст. */
  runIndex: number;
}

/** Куда прокрутить после пересборки. Вычисляется ядром, не UI. */
export interface ResolvedAnchor {
  pageIndex: number;
  runIndex: number;
  /** Найден ли исходный фрагмент, или это ближайшее сохранившееся место (FR-034). */
  exact: boolean;
}
```

**Правила**:
- Ядро ищет прогон с тем же текстом; найдя — возвращает его позицию с `exact: true`, даже если
  страница сменилась (FR-004).
- Не найдя — возвращает ближайшее сохранившееся место с `exact: false`, а **не** начало
  документа (FR-034).
- Возврат к началу документа при обновлении запрещён всегда (SC-005).
- UI не имеет права подменять решение ядра собственным поиском — это была бы вторая
  реализация того же правила (принцип I).
