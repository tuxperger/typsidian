# Implementation Plan: Note Rendering and Live Preview

**Branch**: `005-live-preview` | **Date**: 2026-09-06 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/005-live-preview/spec.md`

## Summary

Пользователь открывает текстовую заметку и видит рядом с текстом её свёрстанный вид, который
догоняет правки сам — без сохранения и без кнопки «обновить». Ошибка в тексте не гасит
предпросмотр: последний удачный вид остаётся на экране с пометкой, а причина и место ошибки
названы, и одно действие ведёт к ним в редакторе — в том числе когда ошибка лежит в подключённом
файле.

Сборку выполняет крейт `typst` 0.15.1 внутри `packages/core`. Ключевое ограничение,
определившее всю конструкцию: `typst::World` синхронный, а web-бэкенд vault асинхронный
(research.md §2). Поэтому сборка разделена на асинхронную фазу резолва, которая собирает снимок
зависимостей через существующий `VaultBackend` фичи 001, и синхронную фазу сборки над этим
снимком, не касающуюся файловой системы вовсе. Замыкание зависимостей заранее неизвестно,
поэтому фазы чередуются итеративно, пока снимок не перестанет пополняться.

Второе ограничение: `typst-svg` рисует глифы контурами, а не текстом (research.md §4), поэтому
одного SVG для FR-031 и FR-032 недостаточно. Вывод состоит из двух частей на страницу —
SVG для вида и извлечённый из свёрстанного кадра текстовый слой для выделения, копирования и
программ чтения с экрана.

Сборка идёт вне UI-потока (воркер на web, отдельный поток на native), результат отдаётся
постранично: `Page` хэшируется, и наверх уходят только изменившиеся страницы.

## Technical Context

**Language/Version**: Rust (stable, зафиксирован через `flake.nix`/fenix) — вся логика фичи в
`packages/core`. TypeScript `strict` — панель предпросмотра и текстовый слой в `ui/`.

**Primary Dependencies**:
- `typst` `0.15.1` — компилятор. Проверено: собирается под `wasm32-unknown-unknown`
  (research.md §1).
- `typst-layout` `0.15.1` — `PagedDocument` и `Page` (постраничный результат вёрстки).
- `typst-svg` `0.15.1` — постраничный экспорт вида, `svg(page, &opts)`.
- `typst-assets` `0.15.1` — источник встроенных шрифтов, **без feature `fonts`**: шрифты едут
  отдельными файлами, а не внутри wasm (research.md §6).
- `comemo` — приходит с `typst`; используется только `evict` для ограничения кэша
  (research.md §10).
- Существующие `VaultBackend`, `FileStamp`, события фичи 001 — переиспользуются без изменения
  механизма.

**Storage**: собственных файлов фича в vault не создаёт. Свёрстанный вид между запусками не
сохраняется (Out of Scope спеки). Шрифты встроенного набора — файлы приложения рядом с
wasm-модулем, шрифты пользователя — обычные файлы vault.

**Testing**: `cargo test` (native) и `wasm-bindgen-test` (`wasm32-unknown-unknown`) — обязательны
для каждой единицы логики ядра (принципы I и II). Бенчмарк по образцу 002 — на пороги SC-001,
SC-002 и предел 50 страниц.

**Target Platform**: `wasm32-unknown-unknown` (web, Next.js) и нативная сборка (desktop через
Tauri). Мобильный клиент вне скоупа спеки — его нет.

**Project Type**: та же схема, что у 001, 002 и 004: Rust-ядро `packages/core`, потребляемое
общим UI-кодом `ui/` из клиентов.

**Performance Goals** (из spec.md → Success Criteria):
- Вид ≤2 с после открытия заметки (SC-001), обновление ≤1 с после паузы набора (SC-002).
- Отклик на ввод ≤100 мс во время сборки (SC-003) — отсюда требование сборки вне UI-потока.
- Изменение связанного файла отражается ≤2 с (SC-006).
- Потолок гарантий — документ до 50 страниц; выше best-effort.

**Constraints**:
- Сборка прекращается на 10 секундах (FR-026).
- Полностью офлайн (FR-024); пакеты Typst из сети не поддерживаются (research.md §8).
- Вес доставки: 6,8 МБ brotli на модуль компилятора — требует ленивой загрузки (research.md §6,
  §11).

**Scale/Scope**: 34 функциональных требования, 11 критериев успеха, 4 пользовательские истории
(P1…P4).

### Перепроверка после Phase 1

Проектирование не добавило нарушений и одно из них сняло.

- **Принцип I** — после раскладки модулей проверено ещё раз: единственное, что решает UI сам, —
  ритм дебаунса (contracts/frontend-preview.md). Это про ритм ввода, а не про правила сборки;
  «устарел ли вид», порядок диагностик и доступность перехода приходят из ядра готовыми.
- **Принцип II** — платформенный шов сузился до одного трейта `CompileExecutor`. Вызывающий код
  по платформе не ветвится.
- **Принцип X** — оговорка по отмене на native осталась и учтена в Complexity Tracking;
  наблюдаемое поведение на обоих таргетах одинаково.
- **Новых отклонений нет.** Гейт пройден.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Отмена сборки на native не прерывает вычисление: поток дорабатывает, его результат отбрасывается (принцип X — «отменяемые операции») | У `typst::compile` нет ни токена отмены, ни кооперативных точек прерывания. Наблюдаемое пользователем поведение при этом одинаково на обоих таргетах: сборка объявлена прекращённой, UI разблокирован, vault не тронут (research.md §3) | Отдельный процесс на каждую сборку ради killability — цена запуска процесса на каждую паузу в наборе несопоставима с выигрышем. Кооперативная отмена потребовала бы форка компилятора, то есть второго источника истины для языка, который мы не контролируем |
| Самая тяжёлая зависимость проекта: +6,8 МБ brotli к доставке web-клиента, +3 минуты к полной сборке под каждый таргет | Это и есть предмет фичи — постраничный документ, совпадающий с внешним `typst compile` (SC-008). Собственная реализация вёрстки Typst была бы вторым источником истины и нарушила бы принцип I по существу | Урезанный «почти-Typst» рендерер: расходится с внешней сборкой, то есть проваливает SC-008 и обесценивает предпросмотр. `typst-html` даёт настоящий текст дёшево, но не даёт страниц (FR-003) — см. research.md §4 |
| Два представления одной страницы: SVG для вида и текстовый слой для выделения | `typst-svg` выводит глифы контурами; текста в SVG нет вовсе (проверено в исходнике, research.md §4). Без второго слоя FR-031, FR-032 и SC-011 невыполнимы | Только SVG — проваливает выделение и доступность. Только HTML — проваливает пагинацию. Оба требования заданы спекой явно и оба подтверждены пользователем на шаге clarify |
