# Research: Практика с ИИ

## §1. Файл сессии практики

**Decision**: тот же файл урока 051 (`.lesson`) с полем шапки `kind: Practice`. Вкладка,
поток, журнал, восстановление, проверка `expected` — общие; отличаются инструкции,
инструменты и лента. Уроки 051 без поля читаются как `kind: Lesson`.

**Rationale**: в LearnHarness практика использует тот же механизм сессий; отдельный формат
удвоил бы код восстановления и потока.

**Alternatives**: расширение `.practice` — новый `FileKind` без новой пользы; вид различает
шапка, список показывает метку.

## §2. Инструменты агента практики

- `pose_problem { statement, solution }` — задача и решение одним вызовом: решение
  фиксируется до ответа (FR-004). Событие `Problem { n, statement, solution }`.
- `give_hint { text }` — подсказка; событие `Hint`.
- `conclude { outcome: Correct|Partial|Wrong|Unsolved, review }` — итог; событие `Verdict`.

Поставив задачу или подсказку, агент ждёт пользователя. После `conclude` ход заканчивается;
следующая задача — только по событию пользователя `NextProblem` (FR-006). Задача без
решения в `pose_problem` отклоняется ядром с причиной и записывается как `Problem` с
`solution: None` после второй неудачи (Edge Case: «без проверяемого решения»).

## §3. Решение и видимость

**Decision**: решение лежит в файле сессии (запись урока — файл vault), но `LessonView` не
отдаёт его, пока у задачи нет `Verdict` (FR-004, SC-001). Отображение — в ядре: UI просто не
получает текст.

**Rationale**: файл читается и без приложения; честно сказать об этом в подсказке поля
решения — «Решение хранится в файле практики». Подглядывание в файл — выбор пользователя.

## §4. Материал

**Decision**: при создании пользователь выбирает уроки, заметки или пишет описание.
- Урок → его цель и изложение `Summary`, иначе объяснения учителя до 30 тыс. символов.
- Заметка → через `check_access_in` (050), до 100 тыс. символов, событие `NoteRead` 051.
- Утверждения графа 054 — когда 054 готова (её задача).
Материал собирается один раз в событие `Material` в начале сессии; удаление урока потом
практике не мешает (Edge Case).

## §5. Сводка

**Decision**: `LessonView.practice` — список задач: номер, первая строка условия, итог, число
подсказок, номер события для перехода. «Трудности» — не вычисляются ядром: агент пишет их в
`review` последнего `conclude`; сводка показывает последний текст. Оценок вне файла нет
(FR-009).

## §6. Решение в журнале отправленного

**Decision**: модель знает решение открытой задачи — оно в блоке инструкций «открытая
задача» (помечен как данные урока), а значит и в дословном теле запроса в журнале 050.
Журнал показывает отправленное без купюр (принцип IX важнее), поэтому журнал — второе
место, где решение видно до ответа, наравне с файлом практики. Интерфейс практики журнал
не открывает сам.

## §7. Действие пользователя

**Decision**: `UserAnswer.action` (`Answer` по умолчанию, `HintRequest`, `GiveUp`,
`NextProblem`) — старые клиенты не меняются; неприменимое действие — `LessonChanged`.
«Сдаюсь» всегда даёт итог `Unsolved`; без вызова `conclude` итог пишет ядро.

## §8. Ревью безопасности (T012)

`security-review-agent`, 2026-11-02: CRITICAL и HIGH нет; решение без итога в `LessonView`
не попадает и на враждебном файле. Исправляется (T014–T020):

- **M1** — материал урока в практике — снимок в `Material`, а запрет папки на него не
  действовал (у заметок действует: они перечитываются). Решение: при сборке инструкций урок
  из `Material` с путём, закрытым `check_access`, выкидывается; исчезнувший урок остаётся
  снимком (Edge Case «удалён»).
- **M2** — `collect_lessons` считал только принятые уроки: миллион отклоняемых путей от
  одного пользователя сервера — часы работы под блокировкой vault. Решение: считаются
  попытки (как у заметок), список длиннее предела обрезается.
- **L1** — отказ по уроку был тихим; Edge Case требует видимого отказа. Решение:
  `Material.denied[] {path, reason}`, строка в ленте.
- **L2** — повтор номера задачи (слияние файла с двух устройств) навсегда оставлял задачу
  открытой. Решение: задача, перекрытая более поздней с тем же номером, считается закрытой.
- **L3** — ядро не мешает модели написать решение в подсказке. Решение: `give_hint`,
  содержащий решение (нормализованная подстрока, решение не короче 8 символов),
  отклоняется с причиной. Решение в обычной реплике учителя — принятый риск: модель знает
  решение, а запрещать ей текст — подмена педагогики фильтром.
- **L4** — подсчёт символов при сборке текста урока линейный.
- **L5** — повтор урока сравнивается в свёрнутой форме пути, как в `check_access`.
- Цель урока обрезается до предела при сборке инструкций (касается 051–053).
- Заметки практики: предел объёма — общий для прикреплений 051 (300 тыс.), §4 исправлен.

## §9. Расхождения вёрстки с макетом (T006, T008, T009)

**Decision** — намеренные:

- Заметки выбираются поиском и чипами, как в диалоге урока 051 (заметок в vault тысячи);
  чекбоксы — только у уроков. Поле «Название» необязательное.
- Задача, подсказки и форма ответа — отдельные блоки ленты: подсказки и ответы чередуются
  событиями.
- Одно поле «Ваш ответ и рассуждение», без уверенности — как в макете.
- Сводка — колонка со своей кнопкой в шапке, на узком экране лист; «Трудности» названы
  «Последний разбор»: ядро отдаёт разбор целиком (§5).
- Иконка замка — из набора иконок приложения.

Не расхождение, а недоделка, закрывается T021: закрытые для агента заметки и уроки
помечаются в диалоге через `ai_check_access` (050 FR-016), которой не было в клиенте.
