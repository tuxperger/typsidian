# Feature Specification: Практика с ИИ

**Feature Branch**: `053-ai-practice-sessions`

**Created**: 2026-11-02

**Status**: Implemented

**Priority**: P2

**Summary**: Отдельной сессией практики можно решать разные задачи по пройденному — без подсказки, какое знание нужно, — с подсказками и разбором, подстроенными под моё рассуждение.

**Input**: User description: "Practice из LearnHarness: отдельные сессии с разнообразными задачами, где нужное знание должно вспомниться без названия; задачи и подсказки подстраиваются под рассуждение; решение фиксируется до показа и раскрывается после ответа."

## Clarifications

### Session 2026-11-02

Вопросы закрыты без обращения к пользователю: ответы следуют из конституции и спек 051, 054.

- Q: Ведёт ли практика интервальные повторения или оценки освоения? → A: Нет. Итоги задач —
  сведения внутри сессии, а не рейтинг, сертификат или расписание повторений.
- Q: Откуда берётся материал? → A: Из выбранных пользователем уроков, заметок или
  утверждений графа 054 либо из свободного описания; автоматического подбора по vault нет.
- Q: Где хранится сессия практики? → A: Обычным файлом vault рядом с уроками (051 FR-006).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Решить задачу по пройденному (Priority: P1)

Пользователь начинает практику, выбирает материал — урок, заметки или описание темы.
Агент ставит задачу, не называя, какое знание она проверяет. Пользователь решает, пишет
рассуждение и отправляет ответ. Агент выносит итог, разбирает рассуждение и показывает
решение, зафиксированное ещё при постановке задачи.

**Why this priority**: практика делает понимание применимым — это отдельный от урока вид
работы.

**Independent Test**: начать практику по завершённому уроку, решить задачу и увидеть итог,
разбор и решение.

**Acceptance Scenarios**:

1. **Given** выбран материал, **When** пользователь начинает практику, **Then** агент ставит
   задачу без названия проверяемого знания.
2. **Given** задача поставлена, **When** пользователь отправил ответ, **Then** он видит итог
   (верно, частично, неверно), разбор рассуждения и решение.
3. **Given** решение показано, **When** агент закончил разбор, **Then** следующая задача не
   появляется, пока пользователь не нажмёт «Следующая задача».
4. **Given** материал — свободное описание темы, **When** практика начата, **Then** задачи
   ставятся по описанию без привязки к урокам.

---

### User Story 2 - Подсказка вместо ответа (Priority: P2)

Застряв, пользователь просит подсказку. Агент даёт наводящий шаг по его рассуждению, а не
решение.

**Why this priority**: подсказка сохраняет пользу задачи; без неё застрявший бросает.

**Independent Test**: попросить подсказку дважды и убедиться, что решение не раскрыто до
ответа или явного «Сдаюсь».

**Acceptance Scenarios**:

1. **Given** задача без ответа, **When** пользователь просит подсказку, **Then** агент даёт
   наводящий шаг, решение остаётся скрытым.
2. **Given** пользователь нажал «Сдаюсь», **When** агент отвечает, **Then** показывается
   решение и итог «не решено».

---

### User Story 3 - Видеть итоги сессии (Priority: P3)

После практики пользователь видит сводку: задачи, итоги, что вызвало трудности.

**Why this priority**: удобство, задачи полезны и без сводки.

**Independent Test**: решить три задачи и открыть сводку.

**Acceptance Scenarios**:

1. **Given** решено несколько задач, **When** пользователь открывает сводку, **Then** видит
   по каждой формулировку, итог и ссылку на разбор.

### Edge Cases

- Модель не зафиксировала решение при постановке задачи: задача помечается как без
  проверяемого решения, итог выносится по разбору, пользователь видит пометку.
- Выбранный урок удалён: практика использует уже взятый в сессию материал.
- Материал из запрещённой папки: не попадает в сессию, пользователь видит отказ.
- Обрыв сети после ответа: ответ сохранён, итог можно запросить снова.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Практика MUST быть отдельной от урока сессией с теми же условиями запуска,
  что у 051 (FR-001).
- **FR-002**: Материал MUST выбираться явно: уроки, заметки, утверждения графа 054 или
  свободное описание; содержимое заметок MUST проходить проверку доступа 050.
- **FR-003**: Формулировка задачи MUST NOT называть проверяемое знание.
- **FR-004**: Решение MUST фиксироваться при постановке задачи и MUST NOT показываться до
  ответа пользователя или «Сдаюсь».
- **FR-005**: После ответа агент MUST выносить итог (верно, частично, неверно, не решено),
  разбирать рассуждение и показывать решение.
- **FR-006**: Следующая задача MUST появляться только по явному действию пользователя.
- **FR-007**: Подсказка MUST давать наводящий шаг без раскрытия решения.
- **FR-008**: Сессия практики MUST храниться файлом vault и восстанавливаться как урок
  (051 FR-006–FR-008).
- **FR-009**: Итоги практики MUST NOT превращаться в оценки освоения, расписания повторений
  или иные данные вне файла сессии.
- **FR-010**: Каждый запрос MUST попадать в журнал 050; стоимость — по 050 FR-014.
- **FR-011**: Все тексты интерфейса MUST быть локализованы.

### Key Entities

- **Сессия практики**: материал, задачи, файл vault.
- **Задача**: формулировка, зафиксированное решение, ответ и рассуждение пользователя,
  подсказки, итог, разбор.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В 100% задач решение не видно пользователю до ответа или «Сдаюсь».
- **SC-002**: От выбора материала до первой задачи — не больше 3 действий.
- **SC-003**: После перезапуска сессия практики восстанавливается без потерь в 100% случаев.

## Assumptions

- Зависит от 051 (сессия, файл, проверки); 054 — необязательный источник материала.
- Разнообразие задач обеспечивают инструкции агента практики (059).
