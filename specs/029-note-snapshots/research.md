# Research: Локальные снимки заметок

## 1. Где хранить

**Decision**: `.typsidian/snapshots/` в служебной папке vault: опись `index.json` и файл
`<id>.txt` на снимок, `id` — `<время мс>-<первые 12 знаков blake3 текста>`. Путь добавлен в
`service_dir::derived_paths()` — его исключают правила истории 011 и `.stignore`.
**Rationale**: один путь записи на всех оболочках через `VaultBackend` (принцип II);
хранилище браузера на web привязано к источнику, а не к папке vault, и восстановление
удалённой заметки потерялось бы при смене браузера. Опись отдельно от текстов — история
открывается без чтения снимков (SC-003), тексты читаются только для различий и возврата.
**Alternatives**: один файл на заметку со всеми текстами — переписывать мегабайты на каждый
снимок большой заметки (SC-001); каталог данных приложения — на web его нет.

## 2. Когда снимок

**Decision**: `snapshot_take(backend, path, text, reason, now)`. Поводы: `Open`, `Save`,
`Close`, `External`, `BeforeRestore`, `Delete`. `Save` пропускается, если прошлый снимок
заметки моложе интервала (`TooSoon`); любой повод пропускается, если текст совпадает с
последним снимком (`Same`). Перед удалением и при переименовании снимок и перенос делает
сам backend — так их не обходит ни одна оболочка.

## 3. Срок и очистка

**Decision**: при каждом `snapshot_take` и при открытии истории истёкшие записи (старше
`keep_days`) убираются из описи, их файлы — через `remove_service_file`. Это новый метод
`VaultBackend`: удаляет файл внутри служебной папки мимо корзины (`delete` отправляет в
корзину ОС, и снимки засоряли бы её). Вне служебной папки отказывает.

## 4. Различия и возврат

**Decision**: различия — `vault::conflict::line_diff` (тот же, что у конфликта 001 и UI
`DiffView`). Возврат: снимок текущего текста с поводом `BeforeRestore`, затем для открытой
заметки — `TextEdit` на весь текст (одна единица отмены редактора), для закрытой — запись
со сверкой отпечатка индекса.

## 5. Удалённые

**Decision**: запись описи с `deleted_at`. Восстановление создаёт заметку по прежнему пути с
текстом последнего снимка; занятый путь — ответ `Occupied { suggested }` с именем
«<имя> (восстановлена)» и номером при повторе.

## 6. Git

**Decision**: версии git (011) запрашиваются UI у клиента синхронизации и примешиваются в
список по времени; сравнение и возврат таких версий — функции 011. В ядре снимков git нет.
