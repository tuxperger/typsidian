# Feature Specification: Локальные снимки заметок

**Feature Branch**: `029-note-snapshots`

**Created**: 2026-10-21

**Status**: Draft

**Priority**: P2

**Summary**: Даже без git у каждой заметки есть прошлые версии: приложение само откладывает снимки по ходу работы, их можно сравнить с текущим текстом и вернуть одним действием.

**Input**: User description: "История версий заметки: показать прошлые версии и вернуть, поверх истории синхронизации — без работы с git напрямую."

## Термины

- **Снимок** — сохранённое приложением состояние текста заметки на момент времени.
- **История заметки** — список снимков заметки и, если vault под git (011), версии из git.

## Clarifications

### Session 2026-10-21

- Q: Чем это отличается от истории 011? → A: 011 даёт историю только vault под git.
  Здесь — снимки, которые приложение делает само на любом vault (в том числе в папке
  Syncthing без git), и общий просмотр истории заметки, где версии git показываются рядом,
  если они есть. Закрыто по существующим спекам, без вопроса пользователю.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Вернуть прошлую версию (Priority: P1)

Пользователь случайно стёр половину заметки и сохранил. Он открывает «История заметки»,
видит снимки «сегодня 14:05, 13:40, вчера…», выбирает 13:40, видит различия с текущим
текстом и нажимает «Вернуть эту версию». Текст заменён; возврат — обычная правка, её можно
отменить.

**Why this priority**: Потеря текста без git сейчас необратима.

**Independent Test**: Vault без git, правки с паузами — снимки появляются; возврат даёт
ровно текст снимка.

**Acceptance Scenarios**:

1. **Given** заметку правили, **When** прошло время между правками, **Then** в истории
   появляются снимки с временем и размером изменения.
2. **Given** выбран снимок, **Then** показаны различия с текущим текстом построчно.
3. **Given** выбран снимок, **When** пользователь возвращает его, **Then** текст заметки равен
   снимку, прежний текст сам становится снимком, возврат отменяется Ctrl+Z.
4. **Given** vault под git, **Then** в той же истории видны и версии git, помеченные видом.

---

### User Story 2 - Удалённая заметка (Priority: P2)

Заметку удалили (в том числе мимо корзины). В «Недавно удалённых» она есть со снимками и
восстанавливается на прежнее место.

**Acceptance Scenarios**:

1. **Given** заметка удалена, **When** пользователь открывает «Недавно удалённые», **Then**
   видит её с последним снимком и восстанавливает; если путь занят — выбирает новое имя.

---

### User Story 3 - Срок и объём хранения (Priority: P3)

В настройках vault — сколько дней хранить снимки и как часто их делать; кнопка «Очистить».

### Edge Cases

- Снимки не попадают в синхронизацию (Syncthing, git) и не лежат среди заметок.
- Одинаковый текст снимком не дублируется.
- Большая заметка (10 000 строк) — снимки не замедляют набор.
- Доски (002) снимками этой фичи не покрываются.
- Переименование заметки — история едет за ней.
- Место на диске кончилось — новые снимки не делаются, это названо; редактирование не
  страдает.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Приложение MUST само сохранять снимки заметки при правках не чаще заданного
  интервала (по умолчанию 5 минут) и при закрытии, удалении, переименовании, внешнем
  изменении файла.
- **FR-002**: История заметки MUST показывать снимки с временем и размером изменения и
  различия выбранного снимка с текущим текстом.
- **FR-003**: Возврат снимка MUST быть обычной правкой, отменяемой, с сохранением текущего
  текста снимком.
- **FR-004**: Удалённые заметки MUST оставаться восстановимыми из снимков в течение срока
  хранения.
- **FR-005**: Снимки MUST храниться на устройстве вне файлов vault, не синхронизироваться и
  удаляться по сроку (по умолчанию 7 дней) и по кнопке очистки (принципы VI, IX).
- **FR-006**: Для vault под git история MUST показывать и версии git (011).
- **FR-007**: Одинаково во всех оболочках; на web снимки — в хранилище браузера.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Набор текста в заметке на 10 000 строк не замедляется заметно (задержка ≤ 50 мс)
  при включённых снимках.
- **SC-002**: Возврат снимка восстанавливает текст байт в байт в 100% случаев.
- **SC-003**: История заметки открывается не дольше 500 мс при 200 снимках.

## Assumptions

- Зависит от 001 (события изменения файлов), 011 (версии git для vault под git).
