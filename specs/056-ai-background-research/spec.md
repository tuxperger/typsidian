# Feature Specification: Фоновое исследование в уроке

**Feature Branch**: `056-ai-background-research`

**Created**: 2026-11-02

**Status**: Draft

**Priority**: P3

**Summary**: Учитель может отправить вопрос на исследование — в интернете или в PDF из vault — и продолжать урок, а найденное со ссылками на источники приходит в урок и остаётся заметкой.

**Input**: User description: "Background research и PDF reader из LearnHarness: агент в фоне исследует вопрос в вебе или читает PDF, урок не ждёт; результат со ссылками на источники доставляется в сессию."

## Clarifications

### Session 2026-11-02

Вопросы закрыты без обращения к пользователю: ответы следуют из принципа IX.

- Q: Каким сервисом искать в интернете? → A: Только поиском, встроенным в уже подключённого
  провайдера модели (050). Отдельный поисковый сервис со своим ключом — третья сторона, на
  которую принцип IX не распространяет исключение «Обучение с ИИ»; он потребовал бы
  MAJOR-поправки и в фичу не входит.
- Q: Нужно ли отдельное разрешение? → A: Да. Веб-исследование выключено по умолчанию и
  включается в настройках обучения с ИИ: запросы поиска выходят за пределы провайдера в
  открытый интернет.
- Q: Где хранится результат? → A: Заметкой рядом с уроком: это запись, написанная моделью
  (конституция, «Провайдеры моделей»).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Исследование, пока идёт урок (Priority: P1)

В уроке учитель или пользователь отправляет вопрос на исследование. Урок продолжается; в
сессии видна карточка исследования с состоянием. Когда результат готов, карточка
показывает выводы и источники, а учитель может на них опираться.

**Why this priority**: суть фичи — урок не ждёт поиска.

**Independent Test**: отправить вопрос на исследование, ответить учителю на два вопроса,
получить результат со ссылками.

**Acceptance Scenarios**:

1. **Given** веб-исследование включено и провайдер поддерживает поиск, **When** отправлен
   вопрос, **Then** в уроке появляется карточка «идёт», а урок можно продолжать.
2. **Given** исследование завершено, **When** пользователь открывает карточку, **Then** видит
   выводы, ссылки на источники и заметку с результатом в vault.
3. **Given** исследование идёт, **When** пользователь отменяет, **Then** запросы
   прекращаются, карточка помечена «отменено».
4. **Given** веб-исследование выключено, **When** учитель хочет искать, **Then** поиск
   недоступен, учитель продолжает без него, пользователь видит, где включить.

---

### User Story 2 - Прочесть PDF из vault (Priority: P2)

Пользователь просит учителя изучить PDF из vault — статью, главу книги. Чтение идёт в фоне,
итог с указанием страниц приходит в урок.

**Why this priority**: работает и без интернета, с локальной моделью.

**Independent Test**: попросить изучить PDF и получить итог со ссылками на страницы.

**Acceptance Scenarios**:

1. **Given** PDF в разрешённой папке, **When** пользователь просит его изучить, **Then** до
   отправки видит объём и примерную стоимость, после — итог со ссылками на страницы.
2. **Given** PDF в запрещённой папке, **When** учитель просит его прочесть, **Then** чтение
   отклоняется проверкой доступа 050.

### Edge Cases

- Провайдер (свой адрес, локальная модель) не поддерживает поиск: веб-исследование
  недоступно с объяснением; чтение PDF работает.
- Приложение закрыто посреди исследования: при следующем открытии карточка показывает
  «прервано» и предлагает повторить; частичных результатов, выданных за полные, нет.
- Источник из результата недоступен по ссылке: приложение ссылки не проверяет; результат
  целиком помечен как найденный моделью, чтобы пользователь проверял источники сам.
- Несколько исследований одновременно: каждое со своей карточкой, предел одновременных
  задаётся настройкой.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Исследование MUST выполняться в фоне и MUST NOT блокировать урок; у него MUST
  быть состояние, прогресс и отмена (принцип X).
- **FR-002**: Веб-исследование MUST использовать только поиск подключённого провайдера
  модели, MUST быть выключено по умолчанию и включаться явно в настройках обучения с ИИ.
- **FR-003**: Чтение PDF MUST быть доступно только для файлов внутри vault через проверку
  доступа 050; до отправки MUST показываться объём и примерная стоимость.
- **FR-004**: Результат MUST содержать источники: ссылки для веба, страницы для PDF.
- **FR-005**: Результат MUST сохраняться заметкой vault рядом с уроком и быть доступен
  учителю в уроке.
- **FR-006**: Каждый запрос исследования MUST попадать в журнал 050 до отправки.
- **FR-007**: Прерванное исследование MUST показываться как прерванное с возможностью
  повтора.
- **FR-008**: Все тексты интерфейса MUST быть локализованы.

### Key Entities

- **Исследование**: вопрос или PDF, вид (веб, PDF), состояние, урок, результат, источники.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Во время исследования урок отвечает на действия пользователя без задержек,
  связанных с исследованием.
- **SC-002**: 100% результатов содержат хотя бы один источник либо явную пометку, что
  источников нет.
- **SC-003**: При выключенном веб-исследовании выполняется 0 запросов поиска.

## Assumptions

- Зависит от 051 (урок), 050 (провайдер, журнал, доступ).
- Поддержка поиска зависит от провайдера; Anthropic и OpenAI его дают, свой адрес — как
  правило, нет.
- Отдельный поисковый сервис — только после MAJOR-поправки конституции (принцип IX).
