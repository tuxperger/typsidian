# Research: Фоновое исследование

## §1. Поиск в вебе — только у провайдера

**Decision**: веб-исследование — запрос к подключённой модели с её встроенным серверным
инструментом поиска: у Anthropic — серверный инструмент веб-поиска API сообщений, у OpenAI —
инструмент поиска API ответов. Своему адресу поиск недоступен (Edge Case). Точные имена и
версии инструментов, формат цитат и цена поиска сверяются с живой документацией при
реализации (задача T002, как 050 T010) и записываются сюда.

**Rationale**: принцип IX — данные идут только настроенному провайдеру; отдельный поисковый
сервис потребовал бы MAJOR-поправки (clarify спеки).

## §2. Задание исследования

**Decision**: общий реестр фоновых заданий 054 (`ai/knowledge/jobs.rs`) выносится в
`ai/jobs.rs` и получает вид `Research`. Задание: событие `ResearchStarted { id, kind: Web|Pdf,
question, path? }` в файле урока, затем ход без потока в интерфейсе (прогресс — число
найденных источников), итог `ResearchDone { id, note, sources }` или `ResearchFailed`.
Предел одновременных — `research_parallel` (по умолчанию 2), остальные в очереди.

## §3. Кто отправляет

**Decision**: учитель — инструментом `research { question }` (виден, только если поиск
включён и доступен) или `study_pdf { path, question }`; пользователь — полем «Исследовать…».
Ход учителя после вызова не ждёт результата: инструмент сразу отвечает «запущено». Готовый
результат учитель получает в следующем ходе как событие с изложением.

## §4. Результат — заметка Typst

**Decision**: модель сдаёт результат инструментом `submit_research { paragraphs[], sources[{
title, url? , pages? }] }`; ядро собирает заметку Typst с экранированием текста (не
доверяя разметке модели) в `<lessons_folder>/Исследования/<вопрос>.typ`: вопрос, пометка
«найдено моделью», абзацы, список источников ссылками. Конституция: записи модели — файлы
vault.

## §5. PDF

**Decision**: текст страниц — модуль 055 `pdf_text`; файл — через `check_access_in` 050;
оценка объёма и стоимости до отправки (FR-003), как оценка импорта 055. Источники — номера
страниц.

## §6. Прерывание

**Decision**: задание, оставшееся `Running` в файле урока без итога при открытии, становится
`Interrupted` (FR-007); повтор — новое задание с тем же вопросом.

## §7. Сверка инструментов поиска с документацией (T002, 2026-11-04)

Источники: документация Anthropic «Web search tool»
(`platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool`) и OpenAI «Web search»
(`developers.openai.com/api/docs/guides/tools-web-search`).

**Anthropic** (API сообщений, `anthropic-version` 050):

- Инструмент: `{"type": "web_search_20250305", "name": "web_search", "max_uses": N,
  "allowed_domains"|"blocked_domains": [...]}` — базовый поиск, вызывается моделью напрямую,
  поддерживается всеми моделями и платформами. Версии `web_search_20260209`/`20260318` добавляют
  динамическую фильтрацию через среду выполнения кода на стороне провайдера: не
  поддерживаются на части платформ и не подпадают под нулевое хранение данных —
  **Decision**: использовать `web_search_20250305` (`max_uses` = 5 на исследование).
- Ответ: блоки `server_tool_use` (`name: web_search`, `input.query`), `web_search_tool_result`
  (`content` — список `web_search_result {url, title, page_age, encrypted_content}`, либо при
  ошибке объект `web_search_tool_result_error {error_code}`: `too_many_requests`,
  `invalid_tool_input`, `max_uses_exceeded`, `query_too_long`, `request_too_large`,
  `unavailable`; HTTP при этом 200), текст с `citations` типа `web_search_result_location
  {url, title, cited_text (до 150 символов), encrypted_index}`.
- Поток: `content_block_start` с `server_tool_use` и `input_json_delta` запроса, затем
  `content_block_start` с `web_search_tool_result` целиком; дальше обычный текст.
- `stop_reason: "pause_turn"` — продолжить, отправив ответ ассистента обратно без изменений.
  Если поиск отключён администратором организации — 400 `invalid_request_error`.
- Учёт: `usage.server_tool_use.web_search_requests`; цена — **$10 за 1000 поисков** плюс
  токены (результаты поиска идут во входные токены); ошибочный поиск не оплачивается.
- Источники результата берутся из `citations` (url, title) и `web_search_result` (url, title).

**OpenAI**:

- В Chat Completions поиск есть только у отдельных моделей поиска; инструмент поиска —
  только в **API ответов** (`POST /responses`): `{"model": …, "tools": [{"type":
  "web_search", "filters": {"allowed_domains": [...]}}], "input": …}`.
- Вывод: элемент `web_search_call {id, status, action {type: search|open_page|find_in_page,
  queries}}`, затем `message` с `content[].annotations` типа `url_citation {url, title,
  start_index, end_index}`.
- Цена поиска на странице документации не названа — **Decision**: стоимость поиска OpenAI
  «неизвестно» (050 FR-014), токены — по справочнику.
- **Decision**: для OpenAI исследование идёт отдельным запросом к API ответов (не поток
  `chat/completions`), со своим разбором вывода; свой адрес поиска не получает.

## §8. Решения ядра (T001–T008)

**Decision**:

- Реестр заданий вынесен в `ai/jobs.rs` (054/055 — те же имена через `ai/knowledge/jobs.rs`).
  Очередь исследований — по `research_parallel` на vault (1–4, по умолчанию 2); не больше 8
  идущих и ждущих на vault, 30 на урок, 2 запуска учителем за ход. На сервере исследование
  занимает фоновое место аккаунта (одно, общее с 054/055).
- Третья настройка `research_agent_pdf` (по умолчанию выкл.): учитель сам предлагает изучить
  PDF (`study_pdf`) только с явного разрешения — иначе модель могла бы отправлять PDF vault без
  выбора пользователя.
- Исследование запускает клиент по признаку `launch_due` карточки (как автопополнение 054):
  инструмент учителя пишет `ResearchStarted` и отвечает модели «запущено»; не запущенное за
  2 минуты становится `Interrupted`; PDF от учителя требует подтверждения стоимости
  (`confirm_cost`).
- Инструмент поиска появляется только из одной проверки доступности, перед каждым запросом,
  включая продолжения после `pause_turn` (не больше 4 запросов на исследование); запрос с
  поиском при выключенном поиске ядро не отправит.
- Новые отказы `SearchDisabled`, `SearchUnavailable`. Заметка: экранирование всех
  спецсимволов Typst, ссылки только `#link("…")` по проверенным `http(s)` адресам, пометка
  «найдено моделью» / «составлено по тексту PDF», при отсутствии источников — явная пометка.
- В запрос из PDF уходит не больше 300 тыс. символов с метками страниц; длиннее — пометка
  «прочитано не целиком».

## §9. Ревью безопасности (T012)

`security-review-agent`, 2026-11-04: CRITICAL и HIGH нет. Исправляется (T014–T021):

- **M1** — повторный старт с id идущего исследования отменял чужое задание, а гонка двух
  окон рабочего стола отправляла платный запрос дважды. Решение: отказ повтора не трогает
  задание; повтор разрешён только как проба места в очереди; id и место занимаются атомарно
  под замком реестра; «уже идёт» — без нового запроса.
- **M2** — журнал 050 ограничен 500 записями, но не байтами, а исследование кладёт в него
  до мегабайтов текста PDF и продолжений. Решение: предел журнала в байтах (32 МиБ) с
  вытеснением старых записей; тела запросов остаются дословными (050 FR-011).
- **L1** — поиск идущих заданий и ожидающих запусков — только в своём vault (на сервере
  чужое задание с тем же id и путём гасило запуск).
- **L2** — PDF, запрошенный учителем, ядро запускает только при `research_agent_pdf`, пока
  запуск ждёт, и с явным подтверждением стоимости от клиента.
- **L3** — веб-исследования учителя без подтверждения — принятое поведение (включается
  явно); настройка в интерфейсе прямо говорит, что учитель сам формулирует поисковые
  запросы по материалам урока и что они уходят в интернет; предел — 2 за ход, 30 за урок.
- **L4** — адреса, пути заметок и PDF в виде исследований из файла урока проверяются
  (`clean_url`, нормализация путей); негодное отбрасывается.
- **L5** — заметка исследования пишется атомарно, без следования ссылке; существование —
  по метаданным.
- **L7** — уборка брошенных заданий в очереди; живые ожидающие продлевают срок.
- **I1** — продолжение после `pause_turn` проверяет подключение с `allow_custom`
  вызывающего; время итога — время итога, а не старта.

Не исправляется в 056: **L6** — разбор PDF под замком vault и двойной разбор (оценка и
старт) — часть открытого вопроса 069, добавлено туда.

## §10. Вёрстка: расхождения и что переносится в ядро (T007, T009)

**Decision** — намеренные расхождения:

- PDF-диалог получил поле «Вопрос к PDF»; «Повторить» есть и у неудавшегося исследования;
  у PDF-карточки пометка «составлено моделью» — в самой заметке.

Переносится в ядро (T022–T025), чтобы интерфейс не повторял логику (принцип I):

- список PDF vault, открытых для агента, для выбора в диалоге — вместо ввода пути;
- доступность веб-поиска для урока — от ядра, а не копией условия в интерфейсе;
- события исследования, дописанные в файл урока, не считаются расхождением при ответе
  пользователя (`LessonChanged`) — повтор ответа в интерфейсе убирается;
- «Отклонить» исследование PDF, предложенное учителем — событие отказа в файле урока.
- Ограничение: в оболочке рабочего стола нет способа открыть внешнюю ссылку в браузере
  системы (нет плагина открытия), поэтому ссылки источников на рабочем столе могут не
  открываться; в web работают. Общая для приложения задача — кандидат в отдельную фичу.
