# Research: Синхронизация на своём сервере

## §1 Перенос команд в `packages/host`

**Решение**: состояния `SyncState`, `SyncCancel`, `SyncProgressSlot` и окружение `SyncHome`
переезжают в `typsidian_host::sync`; команды — в `commands.rs`, обёртки Tauri и `dispatch`
строит `gen-host-dispatch.mjs` (как 037). В оболочке остаются руками написанные `sync_open`
(открытие сессии + наблюдатель Syncthing), `sync_syncthing_*`, наблюдатель и
`sync_clone_vault` (путь папки на устройстве) — им сервер не нужен.

**Почему**: FR-004 — одна реализация; копия тонких обёрток разошлась бы при первой правке 011.

**Отвергнуто**: отдельный модуль синхронизации в `apps/server` — две реализации одного контракта.

## §2 Окружение `SyncHome`

`SyncHome { device: Arc<Mutex<Option<NativeStore>>>, device_place, mirrors: Option<PathBuf>,
secrets: DynSecrets, capabilities }`.

- Настройки устройства — тот же `Mutex`, что у состояния `Device` оболочки (оно становится
  `Device(Arc<…>)`): одно открытое хранилище на файл, иначе две копии теряли бы записи друг
  друга. На сервере — один `SyncHome` на аккаунт (общий для его открытых vault), хранилище в
  `<данные>/sync/<аккаунт>/device/`.
- Секреты — `DynSecrets(Arc<dyn DynSecretStore>)`: object-safe вариант `SecretStore` с
  `Send`-будущими (команды Tauri и обработчики axum требуют `Send`). Реализации: keyring
  оболочки и `FileSecrets` (файл JSON, запись через временный файл с правами 0600, fsync,
  rename; повреждённый откладывается в `.corrupt.json`) — перенесён из Android-ветки оболочки,
  Android пользуется им же.
- `SyncHome::default()` — синхронизация недоступна (нет места хранения): команды отвечают
  `SyncError::Io`, а не паникой.

## §3 Возможности сервера и адреса

`ShellCapabilities { ssh: false, direct_remote: true, syncthing_status: false,
secure_secrets: true, server: true }`. Новое поле `server` (`#[serde(default)]`):

- ядро (`parse_remote`) при `server` отклоняет `Scheme::File` и `Scheme::HttpLoopback` —
  `UnsupportedScheme`; проверка стоит и при подключении, и при каждом обмене (`remote_spec`);
- UI показывает подсказку «хранится на сервере».

Внутренние адреса HTTPS (IP loopback, частные, link-local, `localhost`, `*.localhost`) сервер
отклоняет до вызова ядра в `sync_connect_remote`, если в настройках нет
`sync_private_remotes = true`.

**После ревью безопасности** (находки К1, В1–В3, С2–С4, Н1–Н5) — режим процесса
`sync::engine::server_policy::restrict_to_server`, который сервер включает при запуске:

- транспорт HTTP: только `https`; свой резолвер отбрасывает внутренние адреса после
  разрешения имени на каждом соединении (DNS rebinding, `*.nip.io`); адрес числом — проверка
  в транспорте;
- транспорт ssh отказывает; libgit2 не читает системную и пользовательскую конфигурацию git
  (`insteadOf` и автор администратора); адрес безымянного удалённого сверяется с проверенным;
- получение — не больше 2 ГБ и не дольше 30 минут; одна сетевая операция на сессию
  (`ExchangeGate`, отказ `ExchangeRunning`), не больше 32 на сервер.

Отдельно — граница ядра для всех оболочек: `vault::is_inside` отклоняет пути через `.git`
(запись `.git/config` и файла `.git` со ссылкой `gitdir:` командами файлов). Сервер убирает
каталог данных из текстов отказов; удаление vault отменяет идущий обмен и закрывает сессию до
удаления секретов; создание и переименование vault забывают устаревший id с тем же именем;
повреждённым файл секретов считается только при ошибке разбора; ветка в настройках vault
проверяется как имя ссылки.

Остаётся: обмен внутри `sync_connect_remote`/`sync_restore_history` идёт под замком vault
(ждут только команды этого vault); `user delete` при работающем сервере не закрывает его
открытые vault — README велит останавливать сервер.

## §4 Постоянный id vault

Ключ секретов и зеркала — id vault. На сервере клиент его не выбирает: `sync_open` в
`invoke.rs` перехватывается, аргумент `vaultId` клиента отбрасывается, id берётся из таблицы
`vault_sync_ids (account_id, name) → id` (32 hex, создаётся при первом открытии). Переименование
vault переносит строку, удаление — удаляет строку, секреты vault (`FileSecrets::forget_vault`)
и зеркало. Удаление аккаунта (`user delete`) удаляет `<данные>/sync/<аккаунт>/`; строки —
каскадом от `accounts`.

## §5 Значения устройства в UI

Клиент Tauri читает автора через `device_settings`/`apply_device_settings`, а их нет в белом
списке сервера (там вся конфигурация устройства). Новые команды host `sync_device_values` и
`sync_set_author` — только значения синхронизации открытого vault; клиент сервера пользуется
ими, клиент оболочки — прежними командами (панель настроек устройства их же и показывает).

## §6 Проверка обмена в тестах сервера

Удалённый HTTPS в тесте недоступен (сети нет), а `file://` на сервере запрещён — тест
сервера проверяет: историю (включение, снимок, история, возврат), отказ `file://`,
`http://localhost`, `ssh`, внутренних HTTPS; изоляцию секретов на двух аккаунтах (токен A не
виден B ни в ответах, ни в файлах vault, ни в журнале — журнал перехватывается). Обмен с
удалённым по существу — те же функции ядра, что на рабочем столе, и покрыт тестами ядра 011.
