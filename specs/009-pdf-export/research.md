# Research: PDF Export

**Feature**: 009-pdf-export · **Date**: 2026-09-28

## §1 Чем получать PDF

**Decision**: крейт `typst-pdf = "0.15.1"`, та же версия, что `typst`, `typst-layout` и
`typst-svg`. Вызов — `typst_pdf::pdf(&PagedDocument, &PdfOptions) -> SourceResult<Vec<u8>>`.

**Rationale**: это штатный экспорт самого Typst, тот же, что у `typst compile`. Вёрстка
приходит из того же `PagedDocument`, из которого предпросмотр рендерит SVG, поэтому FR-001
(«совпадает с предпросмотром») выполняется построением, а не сверкой. Шрифты встраиваются
подмножеством всегда (FR-002), текстовый слой и теги доступности есть по умолчанию (FR-003).

**Проверено зондом** (2026-09-28, отдельный крейт в scratchpad, `cargo build --target
wasm32-unknown-unknown`): `typst-pdf 0.15.1` вместе с транзитивными `krilla 0.8.2`,
`krilla-svg`, `subsetter`, `hayro` собирается под wasm32 без правок и без новых системных
зависимостей. Это было главное условие принципа II для всей фичи. Нативная сборка того же
крейта у Typst CLI штатная.

**Alternatives considered**:
- Склеивать PDF из уже готовых SVG страниц предпросмотра — отдельный конвертер SVG→PDF,
  второй путь вёрстки и потеря текстового слоя. Отклонено.
- Печать в PDF средствами браузера/ОС — разный результат на трёх клиентах (принцип II),
  нет на Android, не подходит для пакета. Отклонено.

## §2 Параметры `PdfOptions`

**Decision**:
- `ident: Smart::Custom(<путь заметки в vault>)` — стабильный идентификатор документа между
  экспортами одной заметки, как требует документация крейта.
- `creator: Smart::Custom(Some("Typsidian (Typst 0.15.1)"))` — метка из FR-004.
- `timestamp: None` — дата берётся только из `set document(date: …)`. Часы в wasm доступны
  лишь через JS, а детерминированный результат удобен для тестов.
- `standards`: по умолчанию, `tagged: true`, `pretty: false`, `page_ranges: None`.

Название документа (FR-004) Typst кладёт в метаданные сам из `set document(title: …)`.

## §3 Где в ядре появляется PDF

**Проблема**: `preview::compile::compile_with` рендерит страницы в SVG прямо в проходе и
выбрасывает `PagedDocument`. Цикл резолва (`compile_collecting_failures`) и доустановка
шаблонов (`compile_note_with_templates`) возвращают только `CompiledDocument` со страницами.

**Decision**: провести через проход сборки «что получить на выходе». Внутренний перечислитель
`Render { Pages, Pdf(PdfMeta) }` передаётся от публичной функции вниз до `compile_with`;
результат прохода несёт либо страницы, либо байты PDF. Для `Render::Pages` поведение и
публичные сигнатуры предпросмотра не меняются. Новая публичная функция —
`export::export_note_pdf`, использующая тот же цикл резолва и доустановки шаблонов.

**Rationale**: второй цикл резолва для экспорта был бы вторым источником истины о том, как
собирается заметка (принцип I), и разошёлся бы с предпросмотром при первой же правке. Кроме
того, промежуточные проходы экспорта не рендерят SVG впустую.

**Alternatives considered**: хранить `PagedDocument` в `CompiledDocument` — тип пересекает
границу wasm (`Tsify`) и сериализуется, а документ Typst не сериализуем. Отклонено.

## §4 Атомарная запись (FR-019, FR-030, SC-006)

**Проблема**: `NativeBackend::write_bytes` — это `std::fs::write`, то есть усечение и
запись. Прерывание посередине оставит обрезанный PDF на месте прежнего.

**Decision**: сделать `write_bytes` атомарной на обоих таргетах как свойство трейта:
- **native**: запись во временный файл в `.typsidian/tmp/`, `sync_all`, затем `rename` на
  место назначения. Служебная папка лежит в корне vault, то есть на той же файловой системе,
  и `rename` атомарен. Остатки `.typsidian/tmp/` от прерванного процесса удаляются при
  открытии vault. Если `rename` вернул `EXDEV` (внутри vault смонтирована другая ФС), то
  временный файл создаётся рядом с целью под скрытым именем `.<имя>.typsidian-tmp`.
- **web**: `FileSystemWritableFileStream` уже атомарен по спецификации File System Access:
  запись идёт в swap-файл, который заменяет оригинал только на `close()`, а при сбое
  отбрасывается. Код не меняется; в контракт трейта записывается гарантия и тест на неё.

Заодно атомарной становится установка внешних шаблонов (фича 007), которая тоже пишет через
`write_bytes`.

**Alternatives considered**: отдельный метод `write_bytes_atomic` — два метода с разными
гарантиями, из которых неатомарный никому не нужен. Отклонено.

## §5 Кто ведёт очередь пакета

**Decision**: состояние пакета — чистая структура ядра `export::batch::BatchState`
(сериализуемая, `Tsify`) и чистые переходы: `start`, `next`, `record`, `skip`, `cancel`.
Оценку оставшегося времени, правило «остановить при ошибке», итог и допустимость переходов
считает ядро. UI держит значение состояния и крутит цикл: взял следующее задание → вызвал
экспорт одной заметки → записал результат → уступил цикл событий → повторил.

**Rationale**:
- Принцип I: правила очереди — бизнес-логика, их надо покрыть тестами на обоих таргетах.
- Чистые функции «состояние на входе → состояние на выходе» не требуют держать объект в
  оболочке. На web это свободные функции wasm-bindgen, на desktop/Android синхронные команды
  Tauri. Так уже устроены `embeds_changed` и `plan_embed`.
- Отмена между заметками естественна: цикл просто не берёт следующее задание. Текущий
  экспорт либо дописывает файл атомарно, либо ничего не пишет (§4), что и требует FR-019.

**Alternatives considered**:
- Весь пакет одним вызовом ядра с потоком событий — нужен канал событий и токен отмены
  через границу wasm, а на web вызов держал бы заимствование `WebBackend` на всё время
  пакета, и цикл опроса vault падал бы «recursive use of an object». Отклонено.
- Очередь целиком в UI — правила пакета без тестов ядра, нарушение принципа I. Отклонено.

## §6 Неблокирующий пакет (принцип X, FR-018, SC-004)

**Desktop/Android**: команда Tauri асинхронная и исполняется в пуле tokio, вне потока окна.
Интерфейс не блокируется. Сборка держит `Mutex` vault столько же, сколько сборка
предпросмотра, то есть автосохранение может подождать одну сборку заметки. Это уже принятое
поведение фичи 005.

**Web**: сборка идёт в главном потоке. Исполнителя в Web Worker у предпросмотра нет:
задача T022 фичи 005 открыта. Пока её нет, пакет на web блокирует поток на время сборки
**одной** заметки. Между заметками цикл уступает цикл событий (`setTimeout(0)`), поэтому
ввод, отмена и перерисовка обрабатываются после каждой заметки. Для типичной заметки это
десятки–сотни миллисекунд.

**Это отклонение от принципа X на web**, оно записано в plan.md → Complexity Tracking.
Устраняется той же задачей, что и для предпросмотра (005 T022): после неё форма вызова не
меняется, меняется только место исполнения. SC-004 проверяется на desktop; на web
фиксируется измеренное значение.

## §7 Папка экспорта в настройках vault

**Decision**: новое поле `VaultOverrides::export_folder: Option<String>`; `None` означает
`export`. Проверка — в `write_vault_settings`, до записи, как у адресов шаблонов (фича 007):
путь относительный, без `..`, без корня и префиксов диска, не пустой, не `.typsidian` и не
внутри неё. Ошибка — новый вариант `VaultSettingsError::InvalidExportFolder { reason }`.
Хранится в `.typsidian/vault.json`, значит доступна всем трём оболочкам. Это единственное
хранилище настроек, до которого добираются все три (память проекта, фича 004).

## §8 Что показывать в Центре экспорта

**Decision**: список строится из тех же записей `Note`, что и дерево (заметки и доски), через
чистую функцию ядра `export::candidates(notes, export_folder)`. Она помечает каждую запись
«экспортируется» либо «не экспортируется» с причиной: «доска», «внутри папки экспорта».
Служебная папка в дерево не попадает и так.

PDF в дерево не добавляются. Дерево по FR-021 фичи 002 и FR-022 фичи 006 показывает только
`Note | Board`, и новый вид записей в `list()` задел бы граф, поиск и индекс. Спека
поправлена: путь называется в сообщении и в Центре экспорта (см. spec.md → Clarifications).

## §9 Сочетания клавиш

**Decision**: две новые команды в `CommandId`: `ExportPdf` (`Mod+P`) и `ExportCenter`
(`Mod+Shift+P`). `Mod+Shift+E` из макета занят `ElementParams` (фича 008). `Mod+P` — жест
печати, и перехват через `preventDefault` работает в браузерах и в окне Tauri. «Печать» и
«в PDF» для пользователя редактора документов — один жест.

## §10 Время сборки и размер

Время одной заметки меряет UI: `performance.now()` вокруг вызова экспорта. Часов в ядре на
wasm нет, а это время представления, а не правило. Число миллисекунд UI передаёт в
`batch::record`, и из него ядро считает оценку оставшегося времени. Размер файла — длина
байтов PDF, её возвращает ядро.
