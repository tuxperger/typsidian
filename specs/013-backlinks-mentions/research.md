# Research: Обратные ссылки и упоминания

Все решения приняты по коду репозитория на 2026-10-10. Сборка и тесты на этапе
планирования не запускались (общий бриф P2) — пункты, которые подтверждает только прогон,
помечены «проверить при реализации».

## §1. Что уже есть в коде и чего не хватает

- `packages/core/src/graph/mod.rs`: `extract_links` (сырые цели `[[…]]`),
  `resolve_link_target`, `links_in` (цели без повторов и без ссылки на себя). Мест вхождений
  разбор не возвращает.
- `packages/core/src/vault/cache.rs`: таблица `links` хранит пары «источник → цель» без
  повторов; `backlinks(target)` отдаёт пути источников. Мест и числа ссылок в ней нет.
- `VaultBackend::backlinks` (`packages/core/src/vault/backend.rs`) — список `Note`; биндинг
  wasm `backlinks`, команда Tauri `backlinks`, метод `VaultClient.backlinks` уже существуют и
  используются диалогом удаления (`ui/src/vault-tree/BacklinksConfirmDialog.tsx`).
- Таблица ссылок заполняется при открытии vault и при каждой записи (`record_links`), на
  native переживает перезапуск (SQLite). К моменту, когда `Workspace` получил клиента, она
  готова; отдельной фазы «индекс строится» у backend нет — есть только массовое внешнее
  изменение (`BulkChangeStarted`/`BulkChangeSettled`).
- `search::LineSegment`/`HitLine` — строка, разрезанная на куски с пометкой подсветки;
  `preview::diagnostics::DiagnosticLocation` — `line`/`column` с единицы и байтовый диапазон.
- `Workspace.tsx`: одна открытая заметка (`openNote`), переход к месту — `revealDiagnostic`
  (`{path, line, column}` → открыть заметку → каретка → прокрутка).
- Автосохранение: `useNoteAutoSave`, пауза 600 мс, запись через `write` без `expected`;
  несохранённый буфер объявляется ядру через `begin_edit`.

## §2. Места вхождений ссылок — в `graph`, одним разбором

**Decision**: добавить `graph::link_sites(content) -> Vec<LinkSite { raw, byte_start,
byte_end }>` и переписать `extract_links` как `link_sites(..).map(raw)`. Диапазон — вся
запись вместе со скобками `[[…]]`.

**Rationale**: принцип I — второго разбора `[[…]]` быть не должно; индекс ссылок и панель
обязаны видеть одни и те же ссылки. Существующие тесты `extract_links`/`links_in` остаются
регрессией.

**Alternatives considered**: хранить места в таблице `links` — меняет схему SQLite и
`IndexCache` на обоих таргетах ради данных, которые устаревают при каждой правке (спека,
Assumptions: места вычисляются по текущему тексту). Разбор через `typst-syntax` (модуль
`structure/` фичи 015) — `[[…]]` не конструкция Typst, сквозное решение 2 брифа оставляет её
за `graph`.

## §3. Ссылка на доску

**Decision**: `resolve_link_target` сохраняет расширение `.excalidraw`
(`vault::BOARD_EXTENSION`), как сейчас сохраняет `.typ`; ко всему остальному по-прежнему
дописывает `.typ`.

**Rationale**: спека (Edge Cases) требует показывать ссылки на доску в её панели. Сейчас
`[[схема.excalidraw]]` разрешается в `схема.excalidraw.typ`, то есть ссылка на доску
невыразима вовсе. Изменение сужено до одного известного расширения; ссылка, которая раньше
указывала на несуществующую `….excalidraw.typ`, была битой и перестаёт ею быть.

**Alternatives considered**: не показывать связи досок — противоречит спеке. Сохранять любое
расширение — меняет смысл существующих ссылок вида `[[глава.1]]`.

## §4. Обратные ссылки: страница из индекса + текущий текст

**Decision**: `links::backlinks_page(backend, target, open_texts, offset, limit)`:

1. источники — `backend.backlinks(target)` (индекс, без чтения файлов), без самой цели
   (FR-006);
2. порядок — близость папки к папке цели (число шагов по дереву папок), затем путь;
3. для заметок страницы (`limit` ≤ 50) читается текст, по `link_sites` +
   `resolve_link_target` отбираются вхождения, ведущие на цель, для каждого строится
   фрагмент (§6);
4. источник больше предела или нечитаемый — группа без строк с `problem`
   (`TooLarge`/`Unreadable`);
5. источник, в текущем тексте которого ссылки уже нет (индекс отстал), в страницу не
   попадает.

Ответ несёт `total_sources` (точное, из индекса) и `next_offset`.

**Rationale**: SC-001 (300 мс на 5 000 заметок) — читаются не более 50 файлов; FR-005 —
порции; «ближайшие по пути первыми» — Edge Cases. Число ссылок по всему vault без чтения
всех источников неизвестно, поэтому счётчик раздела — см. §13.

**Alternatives considered**: вернуть всё одним ответом — сотни чтений на открытие заметки.
Сортировка по имени — спека прямо называет близость по пути.

## §5. Что считается упоминанием

**Decision** (`links::mentions`):

- название — имя файла цели без расширения (`title_of`); короче трёх знаков (по символам,
  не байтам) → `MentionsAvailability::TitleTooShort`, поиск не запускается (FR-011);
- совпадение — экранированное название через `regex` без учёта регистра (тот же крейт и тот
  же приём, что у `search::Matcher`), в пределах одной строки;
- граница слова проверяется вручную: символ перед и после совпадения не буква, не цифра и
  не `_`. `\b` не годится: у названия, которое само кончается не буквой (`C++`), он не
  срабатывает;
- совпадение, пересекающееся с любым диапазоном `link_sites`, отбрасывается (AS5);
- просматриваются только `FileKind::Note`, без самой цели (FR-006); нечитаемые и слишком
  большие заметки пропускаются и считаются в `skipped`;
- код и формулы не исключаются (Edge Cases).

**Rationale**: FR-010; правило платформенно нейтрально и проверяется таблицей случаев на
обоих таргетах.

**Alternatives considered**: нормализация пробелов и переносов внутри названия
(«Проект␣␣Альфа», перенос строки) — расширяет понятие «название стоит текстом» сверх спеки
и усложняет проверку «текст на месте»; не делается.

## §6. Места и фрагменты наружу

**Decision**: место — `SitePlace { line, column, byte_start, byte_end }` в тех же единицах,
что `DiagnosticLocation` (строка и колонка с единицы, байтовый диапазон в тексте заметки);
фрагмент — `Vec<search::LineSegment>`: строка вхождения, обрезанная окном до 48 символов по
обе стороны от вхождения по границе слова, с «…» на месте обрезки; подсвечено ровно одно
вхождение — то, которому принадлежит строка панели. Многострочная запись `[[…\n…]]`
(разбор её допускает) показывается первой строкой.

**Rationale**: сквозное решение 4 брифа — новых соглашений о позициях не вводить.
`revealDiagnostic` уже умеет `{path, line, column}`. Колонка обязана совпасть с тем, что
отдаёт диагностика (`Lines::byte_to_line_column` + 1) — **проверить при реализации** тестом
на строке с кириллицей и символом вне BMP.

**Alternatives considered**: смещения UTF-16 — третья система координат на границе;
`HitLine` с соседними строками — колонка 248px их не вмещает, макет показывает одну строку.

## §7. Поиск упоминаний — проход порциями без объекта между вызовами

**Decision**: по образцу `export::batch` (сквозное решение 5), но состояние маленькое:
`MentionScan { target, after: Option<String>, scanned, total, skipped, phase }`.

- `mentions::start(backend, target)` считает `total` и возвращает состояние (или причину
  недоступности);
- `mentions::step(backend, state, open_texts)` заново берёт `backend.list()`, упорядочивает
  так же, как §4 (близость, путь), пропускает всё до `after` включительно и обрабатывает
  порцию: не более `MENTION_STEP_NOTES = 64` заметок и не более `MENTION_STEP_BYTES = 1 МиБ`
  прочитанного текста; возвращает новое состояние и найденные группы порции;
- `mentions::cancel(state)` — чистый переход в `Cancelled`; `step` после него ничего не
  читает;
- UI копит группы, между шагами уступает циклу событий, сворачивание списка = отмена.

**Rationale**: принцип X; курсор-путь вместо индекса переживает появление и исчезновение
заметок между шагами; очередь из 5 000 путей не гоняется через границу wasm/Tauri на каждом
шаге (у пакета экспорта очередь — десятки заметок, здесь — весь vault). Часов в ядре под
wasm нет (009 research.md §10), поэтому бюджет шага — в заметках и байтах, а не во времени.

**Alternatives considered**: один вызов на весь vault (как `search`) — не отменяется и на web
держит главный поток; объект-итератор в ядре — оболочкам пришлось бы хранить его между
командами Tauri, чего 009 сознательно избежал. Индекс слов — новое производное состояние
ради списка, который строится только по запросу (FR-012).

**Риск**: SC-004 (3 с на 5 000 заметок) на web зависит от скорости чтения через File System
Access API; план не может это измерить. Замер — quickstart.md §6; при промахе подбирается
бюджет шага, форма вызова не меняется.

## §8. Точечное обновление упоминаний

**Decision**: `mentions::in_notes(backend, target, paths, open_texts)` — упоминания только в
названных заметках. Панель с раскрытым списком на событие об одной заметке заменяет её
группу, на удаление — убирает, на переименование, массовое изменение и смену цели —
запускает проход заново.

**Rationale**: автосохранение пишет файл каждые 600 мс набора; перезапускать проход по всему
vault на каждую запись (после 014 — на запись в соседней вкладке) нельзя.

## §9. «Связать»: чистая замена и одна точка решения в ядре

**Decision**:

- `graph::link_text(source, target) -> Option<String>` — самая короткая запись, которая из
  папки `source` разрешается в `target`: `[[название]]` для соседа, иначе
  `[[/путь/название]]`; расширение `.typ` опускается, `.excalidraw` остаётся. Результат
  проверяется обратным `resolve_link_target`; путь с `]]` или не прошедший проверку —
  `None`.
- `links::plan_link(text, request, link) -> Result<LinkPlan, Stale>` — чистая функция: текст в
  диапазоне `request.place` обязан побайтно совпасть с `request.text`, оставаться
  упоминанием по правилам §5 (границы, вне ссылки) — иначе `Stale`. `LinkPlan` несёт новый
  текст и `elements::edit::TextEdit` (UTF-16) той же замены.
- `links::link_mention(backend, request, editor_text: Option<&str>) -> LinkOutcome`:
  1. vault не `ReadWrite` → `ReadOnly`;
  2. `link_text` = `None` → `Unexpressible`;
  3. `editor_text` передан (заметка открыта в редакторе) → `plan_link` по нему →
     `EditorEdit { edit }` или `Stale`; на диск ничего не пишется;
  4. иначе `backend.has_unsaved_edits(source)` → `UnsavedElsewhere` (буфер есть, редактора
     нет — например, неразрешённый конфликт); на диск ничего не пишется;
  5. иначе: отпечаток заметки из индекса (`list_folder` её папки) → `read` → `plan_link` →
     `write(new_text, Some(expected))`. Нет записи в индексе, отказ чтения, `Stale`,
     `WriteError::Conflict` → `Stale`; `AccessDenied` → `ReadOnly`; `Io` → `Failed`.

**Rationale**: FR-013…FR-018, SC-005, SC-006. Отпечаток берётся из индекса backend, а не
строится из прочитанного текста: native сравнивает полный `FileStamp` с диска (включая
время), web — хэш содержимого с нулевым временем, и только отпечаток самого backend
сравним на обоих. Если файл изменили между индексом и чтением или между чтением и записью,
`write` отвечает `Conflict` — файл не тронут, пользователь видит «устарело», список
обновляется. Это строже буквы AS3 (правка в другом месте файла, пойманная в этом окне, тоже
даст «устарело»), но окно — миллисекунды, а повтор после обновления списка проходит.

**Alternatives considered**: искать упоминание заново поблизости при сдвиге — «Связать»
могло бы попасть в другое вхождение того же названия; спека требует «на прежнем месте».
Писать без `expected` — молчаливая перезапись внешней правки (001 FR-021). Решать «открыта
ли заметка» в UI и вызывать две разные функции — правило FR-016 оказалось бы в UI
(принцип I).

## §10. Тексты открытых редакторов

**Decision**: функции панели принимают `open_texts: &[OpenText { path, text }]` — тексты
заметок, открытых в редакторе; для таких заметок места и фрагменты считаются по тексту
редактора, а не по диску. В 013 `Workspace` держит одну заметку, и она же — цель панели,
поэтому список фактически пуст; параметр есть сразу, чтобы FR-016 проверялся тестами ядра и
чтобы 014 только наполнила его текстами вкладок.

**Rationale**: без этого место упоминания, посчитанное по диску, не совпадает с текстом
редактора с несохранёнными правками, и «Связать» в открытой заметке всегда давало бы
«устарело».

## §11. Правка открытой заметки — через порт (принцип V)

**Decision**: применение `EditorEdit` к открытой заметке идёт только через порт
`OpenNoteEditors` (contracts/editor-edit-port.md) с единственной реализацией для обычного
режима ввода (транзакция CodeMirror, как у 008 `ParamForm`). Реализации для режимов,
работающих через мост к Neovim, не планируются; без редактора нужного режима порт отвечает
`NoEditor`, панель показывает отказ, файл не меняется.

**Rationale**: мост к Neovim в коде отсутствует (`NoteEditor.tsx`: «моста к Neovim в
web-сборке не существует»), но правка текста открытой заметки извне редактора — ровно та
операция, которую 003 вынесла за порт `InsertionTarget` из-за незакрытого гейта принципа V.
Гейт внутри `/speckit-plan` не проходится — см. plan.md → Complexity Tracking.

**Alternatives considered**: переиспользовать `InsertionTarget` 003 — его контракт «вставить
в точку курсора, заменив выделение»; здесь замена диапазона без движения курсора и без
кражи фокуса. Дёрнуть `view.dispatch` из панели напрямую — стирает границу гейта.

## §12. Колонка заметки и её состояние

**Decision**:

- `ui/src/note-panel/NotePanel.tsx` — оболочка колонки: шапка с переключателем режимов и
  счётчиком, тело активного режима. Режимы описываются реестром
  `NotePanelModeSpec { id, title, badge, render }`; 013 регистрирует один — `links`. 015
  добавляет `outline`, 017 — `sources`, не меняя оболочку. При одном режиме переключатель —
  просто заголовок.
- Подача: колонка 248px между деревом и редактором; при ширине окна ≤ 720px (тот же порог,
  что у существующих `@media (max-width: 720px)` в `app.css`) — шторка снизу на скриме.
  Решает ширина окна, а не таргет (принцип II: ветвления по платформе в общем UI нет).
- Состояние — новое поле `Settings.note_panel: NotePanelState { shown, mode,
  mentions_expanded }` в настройках устройства (004), меняется через `SettingsChange` и
  всегда уходит в устройство (как `language` в `apply::route`); в `VaultOverrides` не
  попадает; сброс настроек к умолчаниям его не трогает; негодное значение в файле →
  умолчание (`lenient`). `mode` — перечисление `NotePanelMode { Links }`; неизвестное
  значение из более новой версии читается как умолчание.
- Шторка: `shown` на неё не действует — она открывается действием и закрывается после
  перехода, по Escape и по тапу на скрим; открыта ли она, не сохраняется. `mode` и
  `mentions_expanded` у колонки и шторки общие.
- Окно читает состояние один раз при монтировании и дальше пишет своё (с паузой 400 мс);
  чужие записи в текущее окно не приезжают.
- Клиент настроек устройства приходит в `Workspace` новым необязательным пропом `device`
  (три оболочки его уже создают); без него состояние живёт в памяти окна.

**Rationale**: спека (Assumptions) и сквозное решение 1 брифа называют это состоянием
устройства (004). Типизированное поле ядра проверяется на обоих таргетах и расширяется 015
(виды пунктов оглавления) и 017 без нового хранилища.

**Alternatives considered**: `localStorage`, как у ширины колонок (`usePaneLayout.ts`), —
там это сознательное «состояние окна», но спека 013 требует состояния устройства, а на
Android `localStorage` веб-вида не входит в то, что 004 обещает сохранять. Отдельный файл
состояния — второе хранилище устройства рядом с `settings.json`.

**Для 015 и 017**: добавить вариант в `NotePanelMode`, свои поля — в `NotePanelState`
(с `#[serde(default)]`), режим — в реестр `ui/src/note-panel/modes.ts`.

## §13. Счётчики

**Decision**: счётчик раздела «Обратные ссылки» показывает число ссылок, когда загружены все
источники, и число ссылающихся заметок, пока загружена часть (тогда рядом строка «показано
N из M заметок»). Тег в шапке колонки и сегмент статус-бара («5 ссылок · 2 упоминания») —
те же числа; число упоминаний появляется только после завершённого прохода. У группы с
`problem` числа ссылок нет.

**Rationale**: макет 1a показывает «5» при трёх заметках (ссылки), макет 1b — «312» рядом с
«показано 50 из 312 заметок» (заметки). Точное число ссылок по всему vault требует прочесть
все источники, что отменяет смысл порций (§4).

## §14. Что заставляет панель обновиться

**Decision**: один счётчик-триггер в `Workspace`, который увеличивают: события vault
(`NoteCreated`, `NoteUpdated`, `NoteRenamed`, `NoteDeleted`, `LinksInvalidated`,
`BulkChangeSettled`), удачная запись автосохранения (`NoteEditor` получает проп
`onSaved(path)`) и итог «Связать». Панель перезапрашивает первую страницу обратных ссылок с
паузой 150 мс; во время массового изменения (`bulkChangeDepth > 0`) ждёт его конца и
показывает «идёт сбор». Ответ, пришедший для уже сменившейся цели, отбрасывается по номеру
запроса (FR-009). Скрытая колонка ничего не запрашивает.

**Rationale**: FR-007 (2 с): 600 мс автосохранения + 150 мс + запрос. `write` события наружу
не публикует, а ссылающаяся заметка могла измениться, не изменив набора целей (вторая
ссылка на ту же заметку, текст вокруг), поэтому `LinksInvalidated` недостаточно. Триггер —
не решение о vault, а «спроси ядро ещё раз», как `refresh` дерева после операций.

**Alternatives considered**: публиковать событие из `write` обоих backend — меняет контракт
записи 001 и заставляет редактор открытой заметки разбирать «обновление», которое он сам и
сделал.

## §15. Команда и сочетание

**Decision**: `CommandId::ToggleNotePanel` (`"toggle-note-panel"`, `Mod+Shift+L`) — в конец
`COMMANDS`. Команда показывает и скрывает колонку целиком, а не режим «Связи»: 015 получает
своё сочетание (`Mod+Shift+O`), которое открывает колонку сразу в режиме «Структура». На
узком окне та же команда открывает и закрывает шторку.

**Rationale**: таблица сочетаний брифа. `Shortcut` хранит клавишу строкой, буква `l`
представима; `Mod+Shift+L` среди умолчаний не занято; `CodeEditor.tsx` подключает только
`defaultKeymap` и `historyKeymap` — `Mod-Shift-l` там нет (оно в `searchKeymap`, который не
подключён). **Проверить при реализации**: тест уникальности умолчаний в `keybindings.rs` и
что браузер отдаёт сочетание странице (Edge использует `Ctrl+Shift+L` для «вставить и
перейти» только в адресной строке).

## §16. Расхождения с макетом

| Макет | Решение | Почему |
|---|---|---|
| 1a: в шапке колонки два режима — «Структура» и «Связи» | до 015 в шапке один заголовок «Связи» | режима «Структура» ещё нет; оболочка готова его принять (§12) |
| 1a: у группы «Архив_2024» (сверх предела) тег «1» | у группы с `problem` числа нет | файл не читается, число ссылок неизвестно (§13) |
| 1a/1b: счётчик раздела — то ссылки, то заметки | правило §13 | точное число ссылок при порциях недоступно |
| 1b: «Показать ещё 50» только у обратных ссылок | та же подача порциями у упоминаний | FR-005 и «сотни совпадений» относятся к обоим спискам |
| 1b: текст «Список обновлён, файл не тронут» у устаревшего упоминания | строка «устарело» живёт до следующего обновления списка этой заметки | после обновления самой строки уже нет; сообщение показывается на месте группы |
| 1c: кнопка в шапке телефона подписана «Связи» | на узком окне кнопка «Панель заметки» подписана названием активного режима | с 015 режимов два, кнопка одна |
| статус-бар «5 ссылок · 2 упоминания» | сегмент есть только при показанной колонке | скрытая колонка ничего не запрашивает (§14) |

## §17. Развилки, закрытые консервативно

- **Буфер без редактора** (`UnsavedElsewhere`): «Связать» отказывает и ничего не пишет.
  Спека требует не терять правок; применить замену некуда.
- **Обновление сбрасывает порции**: после обновления показана первая порция обратных ссылок,
  даже если до него было раскрыто больше.
- **Название, отличающееся пробелами или разорванное переносом строки**, упоминанием не
  считается (§5).
- **Проверка в оболочках**: desktop и Android на этапе планирования не запускались; iOS-
  оболочки нет — шаги quickstart для неё фиксируются как «не проверено».
