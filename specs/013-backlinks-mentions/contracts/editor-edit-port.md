# Contract: порт правки открытой заметки

Граница гейта принципа V (plan.md → Complexity Tracking, research.md §11). Устроен по
образцу `specs/003-templates-snippets/contracts/insertion-target.md`.

Модуль `ui/src/note-panel/links/openNoteEditors.ts`. Панель связей меняет текст открытой
заметки **только** через этот порт, даже пока реализация одна.

```ts
export interface OpenNoteEditors {
  /** Текст заметки в редакторе; `null` — заметка в редакторе не открыта. */
  textOf(path: string): string | null;
  /** Применить готовую замену из ядра (`LinkOutcome.EditorEdit`). */
  applyEdit(path: string, edit: TextEdit): { ok: true } | { ok: false; error: "NoEditor" };
}
```

Порт принимает **готовую правку**: что и на что заменить, считает ядро (`plan_link`).

## Обязательства любой реализации

1. Замена — одна единица истории отмены; предыдущие правки пользователя остаются
   откатываемыми.
2. Курсор и выделение пользователя не переносятся к месту замены; фокус не отбирается.
3. Правка проходит обычным путём редактора: буфер объявляется ядру (`begin_edit`),
   автосохранение пишет его в свой срок. Порт сам на диск не пишет.
4. Замена применяется к тому тексту, который вернул `textOf` в том же такте; если текст
   успел измениться, реализация отвечает `NoEditor`, а не применяет правку со сдвигом.
