# Feature Specification: Конспект урока в заметку

**Feature Branch**: `061-ai-lesson-to-note`

**Created**: 2026-11-02

**Status**: Draft

**Priority**: P2

**Summary**: Пройденный урок можно превратить в заметку Typst — связный конспект по шагам плана с моими ответами, схемами и итогами, который читается как глава учебника и живёт в vault как обычная заметка.

**Input**: User description: "Из LearnHarness (vision: «сессия компилируется в долговечный артефакт», «переписка становится документом урока»; release 0.3: экспорт сессии): урок превращается в перечитываемую страницу — разделы по шагам, мои заметки и результаты, схемы; граф знаний ссылается на разделы."

## Clarifications

### Session 2026-11-02

Вопросы закрыты без обращения к пользователю: ответы следуют из конституции и спек 051–057.

- Q: Пишет ли конспект модель или его собирает приложение? → A: Собирает приложение из
  файла урока — без запроса к модели и без расходов: разделы по шагам плана 052, реплики
  учителя, ответы пользователя, схемы 057. Улучшить текст моделью — отдельное явное
  действие «Отредактировать с учителем», которое идёт обычным ходом урока и видно в журнале.
- Q: Обновляется ли конспект, когда урок продолжается? → A: Да, по кнопке «Обновить
  конспект»; правки пользователя в конспекте не затираются молча — при расхождении
  предлагается сохранить конспект под новым именем.
- Q: Где лежит конспект? → A: Рядом с уроком, заметкой Typst с тем же именем; путь можно
  выбрать.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Собрать конспект (Priority: P1)

Пользователь в уроке нажимает «Конспект». Появляется заметка Typst: заголовок — цель,
разделы — шаги плана (или части переписки, если плана нет), в каждом — объяснения учителя,
вопросы с ответами пользователя и итогом проверки, схемы. Заметка открывается рядом.

**Why this priority**: суть фичи — урок становится перечитываемым документом vault.

**Independent Test**: собрать конспект урока из 10 шагов с планом и схемой и открыть его
предпросмотр.

**Acceptance Scenarios**:

1. **Given** урок с планом, **When** пользователь нажимает «Конспект», **Then** появляется
   заметка с разделом на каждый пройденный шаг плана в порядке прохождения.
2. **Given** урок без плана, **When** собирается конспект, **Then** разделы идут по
   вопросам учителя в хронологическом порядке.
3. **Given** в уроке есть схема 057, **When** собирается конспект, **Then** схема вставлена
   в соответствующий раздел и собирается в предпросмотре.
4. **Given** конспект собран, **When** пользователь смотрит журнал отправленного, **Then**
   в журнале нет записей от сборки конспекта.

---

### User Story 2 - Мои ответы и рассуждения (Priority: P2)

Пользователь выбирает, включать ли в конспект свои ответы, уверенность и рассуждения
«думаю вслух», оборванные реплики и служебные строки (чтение заметок, сжатие).

**Why this priority**: конспект для себя и конспект «для других» различаются.

**Independent Test**: собрать конспект без рассуждений и убедиться, что их текста в заметке
нет.

**Acceptance Scenarios**:

1. **Given** снят флажок «Мои рассуждения», **When** собирается конспект, **Then** текста
   «думаю вслух» в заметке нет, а ответы остаются.
2. **Given** снят флажок «Мои ответы», **When** собирается конспект, **Then** вопросы
   остаются, а ответы и итоги проверок — нет.

---

### User Story 3 - Обновить конспект (Priority: P2)

Урок продолжился; пользователь нажимает «Обновить конспект». Новые шаги дописываются. Если
пользователь правил конспект руками, приложение не затирает правки.

**Why this priority**: урок длиннее одного вечера.

**Independent Test**: собрать конспект, пройти ещё шаг, обновить; затем поправить заметку
руками и обновить снова.

**Acceptance Scenarios**:

1. **Given** конспект не правился руками, **When** пользователь обновляет его, **Then**
   заметка пересобирается с новыми шагами.
2. **Given** конспект правился руками, **When** пользователь обновляет его, **Then**
   приложение предлагает сохранить новую версию под другим именем или перезаписать с
   подтверждением; без выбора ничего не меняется.

---

### User Story 4 - Ссылки графа на разделы (Priority: P3)

Утверждение графа знаний 054, извлечённое из урока с конспектом, ссылается и на раздел
конспекта.

**Why this priority**: удобство навигации; граф полезен и без этого.

**Independent Test**: выбрать утверждение в графе и перейти в раздел конспекта.

**Acceptance Scenarios**:

1. **Given** у урока есть конспект, **When** пользователь открывает источник утверждения,
   **Then** доступны переход в урок и переход в раздел конспекта.

### Edge Cases

- Заметка с таким именем уже есть и не является конспектом этого урока: имя получает
  суффикс, существующая заметка не трогается.
- Текст учителя содержит символы разметки Typst: в конспекте он показывается как текст и
  не ломает сборку.
- Урок очень длинный: конспект собирается без зависания интерфейса, прогресс виден.
- Конспект удалён: «Обновить» собирает его заново.
- Урок — практика 053: разделы — задачи с условием, ответом, итогом и решением.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Конспект MUST собираться приложением из файла урока без запросов к модели.
- **FR-002**: Конспект MUST быть заметкой Typst в vault, собираемой предпросмотром без
  ошибок при любом тексте урока.
- **FR-003**: Разделы MUST идти по пройденным шагам плана 052, а без плана — по вопросам
  учителя; практика 053 — по задачам.
- **FR-004**: Пользователь MUST выбирать, включать ли свои ответы, рассуждения, оборванные
  реплики и служебные строки.
- **FR-005**: Схемы 057 MUST вставляться в свои разделы.
- **FR-006**: Обновление MUST NOT затирать ручные правки без явного подтверждения.
- **FR-007**: Существующая чужая заметка с тем же именем MUST NOT перезаписываться.
- **FR-008**: Утверждения графа 054 из урока с конспектом SHOULD ссылаться на раздел.
- **FR-009**: «Отредактировать с учителем» MUST идти обычным ходом урока с записью в журнал
  050 и только по явному действию.
- **FR-010**: Все тексты интерфейса MUST быть локализованы; заголовки разделов — на языке
  урока.

### Key Entities

- **Конспект**: заметка Typst, ссылка на урок, отметка о сборке (что включено, по какое
  событие урока собран), признак ручной правки.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Конспект урока из 50 шагов собирается менее чем за 2 секунды.
- **SC-002**: 100% конспектов собираются предпросмотром без ошибок (проверка на наборе
  уроков со спецсимволами Typst).
- **SC-003**: Сборка конспекта даёт 0 записей в журнале отправленного.
- **SC-004**: 0 случаев потери ручных правок при обновлении без подтверждения.

## Assumptions

- Зависит от 051; разделы по плану — 052, практика — 053, схемы — 057, ссылки графа — 054.
- Экспорт конспекта в PDF или HTML — существующие экспорты заметок 009 и 034.
