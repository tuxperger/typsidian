# Feature Specification: Глубина размышления модели

**Feature Branch**: `067-ai-thinking-level`

**Created**: 2026-11-02

**Status**: Draft

**Priority**: P3

**Summary**: Для сложной темы можно попросить модель думать дольше, а для простой — отвечать быстрее и дешевле, переключая глубину размышления прямо в уроке.

**Input**: User description: "Из LearnHarness (keyboard.md: «переключить уровень размышления» в сессии; уровни размышления моделей влияют на качество и стоимость)."

## Clarifications

### Session 2026-11-02

Вопросы закрыты без обращения к пользователю: ответы следуют из спек 050, 060.

- Q: Показывается ли ход размышления модели? → A: Нет, в первой версии показывается только
  отметка «модель размышляла» и объём; текст размышлений провайдеры отдают не всегда и не
  целиком. Объём размышлений входит в стоимость.
- Q: Где хранится выбор? → A: По умолчанию — в настройках роли (060); в уроке его можно
  сменить, и выбор урока хранится в файле урока.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Сменить глубину в уроке (Priority: P1)

В шапке урока пользователь выбирает глубину: «Быстро», «Обычно», «Глубоко». Следующие ходы
учителя идут с этой глубиной; стоимость отражает размышления.

**Why this priority**: суть фичи.

**Independent Test**: выбрать «Глубоко» и найти в журнале запрос с соответствующей
настройкой размышлений.

**Acceptance Scenarios**:

1. **Given** модель поддерживает размышления, **When** пользователь выбирает глубину,
   **Then** следующий запрос учителя идёт с ней, журнал это показывает.
2. **Given** модель не поддерживает размышления, **When** пользователь открывает выбор,
   **Then** он недоступен с пояснением.
3. **Given** модель размышляла, **When** ответ получен, **Then** у реплики есть отметка и
   объём размышлений, а стоимость их учитывает.

---

### User Story 2 - Глубина по умолчанию для роли (Priority: P3)

В настройках ролей (060) пользователь задаёт глубину по умолчанию: например, «Быстро» для
извлечения графа.

**Why this priority**: тонкая настройка.

**Independent Test**: задать «Быстро» извлечению и найти это в теле запроса извлечения.

**Acceptance Scenarios**:

1. **Given** роли задана глубина, **When** выполняется её запрос, **Then** он идёт с этой
   глубиной.

### Edge Cases

- Глубина требует больше выходного объёма, чем позволяет модель: приложение снижает её до
  допустимой и говорит об этом.
- Свой адрес: уровень передаётся, только если пользователь включил «сервер поддерживает
  размышления»; иначе недоступен.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Урок MUST давать выбор глубины размышления из трёх уровней для моделей, где
  это поддерживается; иначе выбор MUST быть недоступен с пояснением.
- **FR-002**: Выбор урока MUST сохраняться в файле урока и применяться со следующего хода.
- **FR-003**: Роли 060 MUST иметь глубину по умолчанию.
- **FR-004**: Объём размышлений MUST показываться у реплики и входить в стоимость.
- **FR-005**: Журнал 050 MUST показывать глубину запроса.
- **FR-006**: Все тексты интерфейса MUST быть локализованы.

### Key Entities

- **Глубина**: `Быстро` / `Обычно` / `Глубоко`; соответствие настройкам каждого провайдера.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Смена глубины — 1 действие.
- **SC-002**: 100% запросов идут с выбранной глубиной (проверка по журналу).

## Assumptions

- Зависит от 050, 051; роли — 060. Соответствие уровней настройкам провайдеров
  определяется при планировании по живой документации.
