# Feature Specification: Отказ от внешнего модального редактора

**Feature Branch**: `026-drop-external-editor`

**Created**: 2026-10-21

**Status**: Implemented

**Priority**: P1

**Summary**: В настройках, диагностике и статус-баре больше нет режима редактирования, который ничего не делает: редактор один, и интерфейс не обещает другого.

**Input**: User description: "Отказ от моста к внешнему модальному редактору. Приложение не будет поддерживать внешний модальный редактор: из настроек убирается выбор режима редактирования («полноценный режим» / «упрощённая эмуляция») и путь к конфигу редактора, из диагностики — сведения о режиме редактирования и его недоступности, из статус-бара редактора — надпись режима «NORMAL», которая ничего не переключает. Файлы настроек устройства и vault, где эти значения уже записаны, по-прежнему открываются без ошибок, а лишние значения не мешают. Редактор и вставка заготовок работают как прежде. Из документации, конституции и инструментов разработки исчезают упоминания этого редактора."

## Термины

- **Режим редактирования** — прежняя настройка 004: «полноценный режим» через внешний
  редактор, «упрощённая эмуляция» и «ввод без раскладки» при отказе внешнего процесса.
  Ни один из режимов не был реализован: внешнего редактора в приложении не было, а
  надпись режима в статус-баре не менялась.
- **Старый файл настроек** — файл настроек устройства или vault, записанный до этой фичи
  и содержащий выбор режима и путь к конфигу редактора.

## Clarifications

### Session 2026-10-21

- Q: Что делать с принципом V конституции, посвящённым мосту? → A: Принцип остаётся под
  тем же номером, но говорит о внешних процессах и встраиваемых движках вообще (системный
  `ssh`, Syncthing, Excalidraw) — они уже есть и рискуют так же. Номера принципов VI–X в
  спеках 001–025 не сдвигаются. Решение пользователя «внешний редактор не нужен» + сохранение
  нумерации; поправка — через `/speckit-constitution`.
- Q: Убирать ли упоминания из спек 001–025? → A: Да, пользователь просил убрать все
  упоминания. Абзацы о мосте в артефактах прежних фич переписываются или удаляются так,
  чтобы смысл остальных решений не менялся; принцип V в их Constitution Check читается
  по новой формулировке.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Настройки без несуществующего режима (Priority: P1)

Пользователь открывает настройки и не видит раздела выбора режима редактирования, пути к
конфигу внешнего редактора и кнопки «применить конфиг». В разделе «Дополнительно»
диагностика не упоминает режим редактирования и его недоступность. В статус-баре
редактора нет надписи «NORMAL».

**Why this priority**: Интерфейс сейчас обещает возможность, которой нет и не будет.

**Independent Test**: Открыть настройки и редактор в web и на рабочем столе — ни один
из перечисленных элементов не показан, остальные настройки на месте.

**Acceptance Scenarios**:

1. **Given** открыт vault, **When** пользователь открывает настройки, **Then** разделов и
   полей режима редактирования и конфига внешнего редактора нет, сочетания клавиш и
   остальные разделы на месте.
2. **Given** открыта заметка, **When** пользователь смотрит на статус-бар, **Then** там
   строка и столбец каретки, кодировка и прочие сведения, но нет надписи режима.
3. **Given** раздел «Дополнительно», **When** пользователь копирует диагностику,
   **Then** в ней нет сведений о режиме редактирования.

---

### User Story 2 - Старые файлы настроек открываются (Priority: P1)

У пользователя файлы настроек устройства и vault, где записан выбор «полноценного режима»
и путь к конфигу. После обновления приложение открывает их без ошибок, остальные
настройки из них действуют.

**Why this priority**: Иначе обновление сломало бы уже настроенные vault.

**Independent Test**: Положить файл настроек с этими значениями — vault открывается,
тема и сочетания из файла применены, сообщений об ошибке нет.

**Acceptance Scenarios**:

1. **Given** в файле настроек устройства записан выбор режима и путь к конфигу, **When**
   приложение запускается, **Then** настройки загружаются, остальные значения из файла
   действуют.
2. **Given** такой же файл настроек vault, **When** vault открывается, **Then** он
   открывается без ошибки и без предупреждений о конфиге.
3. **Given** пользователь меняет любую настройку, **When** файл перезаписывается,
   **Then** устаревших значений режима в нём больше нет.

---

### User Story 3 - Документация и инструменты без внешнего редактора (Priority: P2)

Разработчик читает README, конституцию и правила проекта и не находит упоминаний внешнего редактора;
среда разработки его не устанавливает.

**Independent Test**: Поиск по репозиторию названия внешнего редактора и его короткого имени программы вне каталогов сборки
ничего не находит.

**Acceptance Scenarios**:

1. **Given** репозиторий после фичи, **When** выполняется поиск названия внешнего редактора и его короткого имени программы без учёта
   регистра вне артефактов сборки, **Then** совпадений нет.
2. **Given** среда разработки, **When** она собирается, **Then** внешний редактор в неё не входит.

### Edge Cases

- Файл настроек содержит только устаревшие значения режима — он открывается как пустой,
  действуют умолчания.
- Устаревшие значения записаны с ошибкой типа (не строка, не известный вариант) — файл всё
  равно открывается: они не читаются вовсе.
- Вставка заготовки (003) и правки из панели заметки (013) продолжают работать в
  единственном редакторе.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Настройки MUST NOT показывать выбор режима редактирования, путь к конфигу
  внешнего редактора и действия с ним.
- **FR-002**: Диагностика MUST NOT содержать сведений о режиме редактирования и его
  доступности.
- **FR-003**: Статус-бар редактора MUST NOT показывать надпись режима.
- **FR-004**: Файлы настроек устройства и vault с устаревшими значениями режима и пути к
  конфигу MUST открываться без ошибок и предупреждений; остальные значения из них MUST
  действовать.
- **FR-005**: При следующей записи файла настроек устаревшие значения MUST NOT
  записываться.
- **FR-006**: Вставка заготовок и правки из панели заметки MUST работать как до фичи.
- **FR-007**: Документация, конституция, правила и инструменты разработки MUST NOT
  упоминать этот редактор; среда разработки MUST NOT его устанавливать.
- **FR-008**: Поведение MUST быть одинаковым во всех оболочках (принцип II).

### Key Entities

- **Настройки устройства и vault** — теряют два значения: выбор режима и путь к конфигу.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Поиск названия внешнего редактора и его короткого имени программы без учёта регистра по репозиторию вне артефактов
  сборки — 0 совпадений.
- **SC-002**: Старый файл настроек с устаревшими значениями открывается в 100% случаев,
  остальные настройки из него действуют.
- **SC-003**: В настройках, диагностике и статус-баре — 0 элементов режима редактирования.

## Вне скоупа

- Vim-раскладка внутри встроенного редактора — отдельная возможность, если понадобится.

## Assumptions

- Внешнего редактора в приложении никогда не было: удаляется только описание
  несуществующего режима и его заготовки, работающее поведение не меняется.
- Зависит от 004 (настройки) и 006 (настройки vault): меняется их формат.
