# Feature Specification: Оболочка интерфейса по дизайну Typsidian.pdf

**Feature Branch**: `043-ui-redesign`

**Created**: 2026-10-28

**Status**: Implemented

**Priority**: P2

**Summary**: Рабочая область, стартовый экран и экраны телефона перестраиваются по новому дизайну: короткая шапка с переключателем vault, поиском команд и видом «Текст / Рядом / Документ», действия у дерева, статус сборки и масштаб над листом, стартовый экран с недавними vault.

**Input**: User description: "Переделай дизайн под это" — дизайн Typsidian.pdf (4 экрана: рабочая область, стартовый экран, дерево и документ на телефоне). Холст Claude Design с этим дизайном прочитать не удалось; эталон — PDF, недостающее — временный макет того же направления. Развивает 001 (дерево, открытие vault), 004 (vault в настройках), 005 (предпросмотр), 013/015/017 (колонка заметки), 014 (раскладка), 025 (граф).

## Clarifications

### Session 2026-10-28

- Q (закрыто по коду): Плашка режима ввода «NORMAL» из PDF? → A: Не рисуется: режима
  Vim в редакторе нет (026), а плашка без поведения вводила бы в заблуждение.
- Q (закрыто по умолчанию): Куда уходят кнопки, убранные из шапки? → A: Граф, источники,
  оглавление и настройки — значками внизу дерева; «Сегодня», показ слайдов, колонка
  заметки и остальное — командами палитры, как и раньше, с теми же сочетаниями клавиш.
- Q (закрыто по коду): Давность открытия («сегодня», «вчера») в списке недавних? → A: Не
  показывается: время открытия ядро не хранит; последний открытый выделен полосой.
- Q (закрыто по умолчанию): Объём фичи? → A: Только экраны PDF и общая оболочка вокруг
  них. Палитра, настройки, граф, доска, синхронизация, экспорт и диалоги сохраняют свой
  вид; их переделка — следующие фичи.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Рабочая область по новому дизайну (Priority: P1)

Пользователь видит короткую шапку: знак, имя vault с меню переключения, путь открытой
заметки, поле «Команды и заметки», переключатель «Текст / Рядом / Документ», статус
синхронизации и главную кнопку «Экспорт PDF». Внизу дерева — «+ Заметка» и значки графа,
оглавления, источников и настроек. Над листом — номер страницы, статус сборки и масштаб.

**Why this priority**: это основной экран, на котором проходит вся работа.

**Independent Test**: открыть vault и заметку — шапка, низ дерева, полоса предпросмотра и
строка состояния выглядят как экран 1 PDF; каждое убранное из шапки действие доступно.

**Acceptance Scenarios**:

1. **Given** открыта заметка, **When** пользователь выбирает «Текст», **Then** виден только
   текст; «Документ» — только лист; «Рядом» — оба; выбор переживает перезапуск.
2. **Given** шапка, **When** пользователь нажимает на имя vault, **Then** открывается
   список известных vault с текущим и недоступными, «Открыть папку…» и переход к
   управлению vault в настройках; выбор другого vault переключает на него.
3. **Given** шапка, **When** пользователь нажимает «Команды и заметки», **Then** открывается
   палитра команд — то же, что её сочетание клавиш.
4. **Given** заметка собрана, **Then** над листом видно «стр. N» и «собрано»; во время
   сборки — «собирается», при ошибке — «ошибка сборки».
5. **Given** внизу дерева, **When** пользователь нажимает «+ Заметка», **Then** начинается
   создание заметки в корне vault; значки открывают граф, оглавление, источники, настройки.
6. **Given** открыта доска, **Then** переключатель вида недоступен — у доски одна колонка.

---

### User Story 2 - Стартовый экран (Priority: P2)

Без открытого vault пользователь видит знак, короткое объяснение, что такое vault, кнопку
«Открыть папку…», дополнительные способы начать (импорт из Obsidian, vault из удалённого
репозитория — где оболочка их даёт), «Настройки приложения» и справа список недавних vault.

**Why this priority**: первый экран при каждом запуске без открытого vault.

**Independent Test**: запустить приложение без vault — экран соответствует экрану 2 PDF;
недоступный vault показан с причиной и действием «Указать заново».

**Acceptance Scenarios**:

1. **Given** есть известные vault, **Then** справа список «Недавние»: имя и расположение;
   последний открытый выделен; нажатие открывает vault.
2. **Given** папка vault недоступна, **Then** строка показывает причину и «Указать заново»,
   который предлагает выбрать папку заново.
3. **Given** известных vault нет, **Then** правая колонка не показывается — экран не пустой,
   кнопки слева остаются.

---

### User Story 3 - Телефон (Priority: P3)

На телефоне дерево — отдельный экран: имя vault с меню вверху, поиск, дерево, внизу
«Быстрая заметка» и значки графа и настроек. Заметка — экран с «Назад», названием и путём,
переключателем «Текст / Документ» и строкой со страницей и статусом сборки.

**Independent Test**: открыть приложение на ширине телефона — экраны 3 и 4 PDF.

**Acceptance Scenarios**:

1. **Given** экран дерева, **When** пользователь выбирает заметку, **Then** открывается экран
   заметки; «Назад» возвращает к дереву.
2. **Given** экран заметки, **Then** переключатель «Текст / Документ» меняет вид, внизу —
   «стр. N» и статус сборки.

### Edge Cases

- Длинное имя vault или путь сокращаются многоточием, полный текст — в подсказке.
- Узкое окно рабочего стола: поле «Команды и заметки» сжимается до значка; переключатель
  вида и «Экспорт PDF» остаются.
- Ход экспорта и импорта, пока идёт, по-прежнему виден в шапке.
- Нет открытой заметки: «Экспорт PDF» недоступен, путь пуст.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Шапка рабочей области MUST содержать знак, переключатель vault, путь открытой
  заметки, поле вызова палитры команд с её сочетанием, переключатель вида, статус
  синхронизации (если она есть) и главную кнопку «Экспорт PDF» — и ничего сверх того, кроме
  хода экспорта или импорта, пока он идёт.
- **FR-002**: Переключатель вида MUST давать три вида — только текст, текст и лист рядом,
  только лист — и запоминать выбор на устройстве.
- **FR-003**: Переключатель vault MUST показывать известные vault (текущий отмечен,
  недоступный — с причиной), открывать выбранный и давать «Открыть папку…».
- **FR-004**: Низ дерева MUST содержать «+ Заметка» и значки графа, оглавления, источников
  и настроек с подсказками и доступными названиями.
- **FR-005**: Каждое действие, убранное из шапки, MUST оставаться доступным командой палитры
  с прежним сочетанием клавиш.
- **FR-006**: Полоса над листом MUST показывать номер видимой страницы, статус сборки
  (собрано, собирается, ошибка) и масштаб с шагами «−» и «+»; линейки не показываются.
- **FR-007**: Строка состояния MUST показывать позицию курсора, кодировку, число слов, язык
  и, при включённой истории, вход «История» в историю открытой заметки.
- **FR-008**: Стартовый экран MUST показывать способы открыть или создать vault и список
  недавних vault по US2.
- **FR-009**: На ширине телефона дерево и заметка MUST быть отдельными экранами по US3.
- **FR-010**: Все тексты MUST быть на языке интерфейса (010); цвета, шрифты и размеры —
  только токены «Спецформы».
- **FR-011**: Новые сочетания клавиш MUST NOT добавляться.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В шапке рабочей области на ширине 1200 px не больше 7 элементов управления в
  обычном состоянии (было 14).
- **SC-002**: Каждое из действий, убранных из шапки, вызывается не больше чем двумя
  действиями пользователя.
- **SC-003**: Снимки экранов 1–4 при сверке с PDF совпадают по составу, порядку и
  состояниям элементов.

## Assumptions

- Холст Claude Design недоступен для чтения; эталон — Typsidian.pdf. Расхождения с холстом
  исправляются по его выгрузке отдельной правкой.
- Ядро не меняется: список vault, раскладка, история и сборка уже есть.
- Вид «Текст / Рядом / Документ» — показ раскладки 014: одна группа редактора и предпросмотр.
