# Quickstart: проверка дополнения меток и ссылок

Все команды — из корня репозитория через `nix develop` (cargo-команды строго по одной, без
таймаутов). Если wasm-тесты падают с «http status: 404» — запускать через
`env -u LD_LIBRARY_PATH`.

## Ядро

```sh
nix develop --command cargo test -p typsidian-core --lib completion
nix develop --command cargo test -p typsidian-core --test completion_native --test preview_native --test settings_native
nix develop --command cargo build -p typsidian-core --target wasm32-unknown-unknown
nix develop --command bash -c "cd packages/core && wasm-pack test --headless --chrome -- --test completion_wasm --test preview_wasm --test settings_wasm"
nix develop --command cargo bench -p typsidian-core --bench completion_scale
```

Что доказывают тесты (`completion_cases`, оба таргета):

- контекст каретки: `@` в разметке и в блоке содержимого — предлагать; в коде, строке,
  комментарии, `raw`, формуле, адресе почты — нет (FR-004);
- кандидаты: вид и текст помеченного элемента, метка из связанного файла с именем файла,
  совпадение по любой части имени, ближайшие к каретке первыми, не больше 50 строк с общим
  числом, ключи источников отдельной группой (FR-001, FR-003, US1 №5);
- заметки: ближайшие по папке первыми, подставляемая запись разрешается в выбранную заметку
  из текущей — проверяется обратным вызовом `graph::resolve_link_target` (FR-002);
- переход: метка в заметке, в связанном файле, ссылка на заметку, все причины отказа
  (FR-005);
- отметки: отсутствующая метка и заметка, повтор; **нет отметок** на собирающихся документах
  с метками из цикла, из функции и при `show ref` (FR-007, SC-002); удержание; нечитаемый
  связанный файл (Edge Cases);
- `preview_cases`: `evidence` есть только у удачной сборки и содержит метку, созданную кодом.

Бенчмарк: 10 000 строк, 500 меток — `completions` ≤ 20 мс, `reference_marks` ≤ 50 мс на
нативном таргете (SC-001, FR-006).

## UI

```sh
nix develop --command bash -c 'cd ui && pnpm typecheck'
scripts/check-i18n.sh
nix develop -c pnpm dev                      # в фоне, :3000
nix develop -c node scripts/dev/browser.mjs http://localhost:3000 \
    scripts/dev/scenarios/completion.mjs --opfs-vault --shot /tmp/completion.png
```

Сценарий создаёт vault с заметками `Результаты.typ`, `Методология.typ` (подключена через
`#include`), `План.typ` в двух папках и снимает три экрана макета: список по `@рис`, список по
`[[пл`, отметки с пояснением. Консоль без ошибок и исключений.

## Вручную (web)

1. **US1.** В заметке с `<введение>` и рисунком `<рис-схема>` набрать `@рис` — предложена
   `рис-схема` с пометкой «рисунок»; Enter подставляет. Набрать `@` внутри `#let x = "…"` и в
   адресе `a@b.c` — списка нет. Набрать `[[пл` — «План» из этой папки первым; выбрать второй —
   подставлено `[[/…/План]]`.
2. **FR-009.** Выключить «Предлагать при наборе» — по `@` списка нет; `Mod+Alt+P` после `@`
   открывает его.
3. **US2.** Каретка на `@рис-схема` (метка в подключённом файле), `Mod+Alt+D` — открыт
   `Методология.typ`, каретка у метки; «Назад» (014) возвращает. На `@нет-такой` — ничего не
   открыто, причина в строке состояния.
4. **US3.** Набрать `@нет-такой` — отмечена не позже секунды; объявить `<нет-такой>` — отметка
   исчезла. `[[Журнал]]` без такой заметки — отмечена, «Создать заметку» создаёт файл и
   снимает отметку. Две метки `<профиль>` — отмечены обе.
5. **FR-007.** Заметка с `#for i in range(3) [#figure([], caption: [x]) #label("рис-" + str(i))]`
   и `@рис-1` — после сборки отметки нет и при дальнейшем наборе она не мигает.
6. **SC-004.** Быстрый набор текста без `@` и `[[` в заметке на 10 000 строк — вызовов
   `completions` в профиле нет.

## Оболочки

- Desktop: пункты 1–5 вручную (`tauri-driver` в проекте нет).
- Android: пункт 1 касанием — список над строкой набора, строка не перекрыта; пункт 3 через
  контекстное меню редактора.
- iOS: **не проверено** — оболочки нет.
