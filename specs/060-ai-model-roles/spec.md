# Feature Specification: Разные модели для разных задач

**Feature Branch**: `060-ai-model-roles`

**Created**: 2026-11-02

**Status**: Draft

**Priority**: P3

**Summary**: Для урока можно выбрать сильную модель, а для фоновых задач — извлечения графа, сжатия, исследования — дешёвую или локальную, и при желании настроить, как долго провайдер держит повторяющийся контекст.

**Input**: User description: "Model slots и prompt-cache retention из LearnHarness: модели выбираются отдельно по ролям; для каждой роли можно задать предпочтение хранения кэша контекста у провайдера, по умолчанию — поведение провайдера."

## Clarifications

### Session 2026-11-02

Вопросы закрыты без обращения к пользователю: ответы следуют из решений 050.

- Q: Могут ли роли использовать разных провайдеров? → A: Да. Каждая роль выбирает одно из
  подключений vault (050) и модель; по умолчанию все роли используют основное подключение.
- Q: Что при выборе хранения кэша? → A: По умолчанию — поведение провайдера. Более долгое
  хранение может удорожать запись кэша; это предупреждение показывается рядом с выбором,
  а журнал показывает объём, записанный в кэш, и прочитанный из него.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Модели по ролям (Priority: P1)

В настройках обучения с ИИ пользователь видит роли: учитель, замер, практика, извлечение
графа, сжатие переписки, исследование. Для каждой выбирает подключение и модель или
оставляет «как у основной».

**Why this priority**: фоновые задачи дешевле на простой модели, а локальная модель для них
не тратит деньги вовсе.

**Independent Test**: назначить извлечению графа локальную модель, пройти шаг урока и
увидеть в журнале запрос извлечения к локальной модели.

**Acceptance Scenarios**:

1. **Given** роль не настроена, **When** выполняется её запрос, **Then** используется
   основное подключение и модель.
2. **Given** роли назначена другая модель, **When** выполняется её запрос, **Then** журнал
   050 показывает эту модель.
3. **Given** у назначенного подключения нет ключа на этом устройстве, **When** выполняется
   запрос роли, **Then** отказ «ключ не задан» с названием роли, остальные роли работают.

---

### User Story 2 - Хранение кэша (Priority: P3)

Продвинутый пользователь раскрывает дополнительные настройки и задаёт для роли
предпочтение хранения кэша контекста у провайдера.

**Why this priority**: тонкая настройка стоимости для длинных уроков.

**Independent Test**: выбрать долгое хранение для учителя и увидеть в журнале объёмы кэша.

**Acceptance Scenarios**:

1. **Given** выбрано «по умолчанию провайдера», **When** идут запросы, **Then** приложение
   не меняет поведение провайдера.
2. **Given** выбрано долгое хранение, **When** провайдер его не поддерживает, **Then** выбор
   недоступен с пояснением.
3. **Given** провайдер вернул объёмы кэша, **When** пользователь открывает журнал, **Then**
   видит записанный и прочитанный объём, а примерная стоимость их учитывает, если цены
   известны.

### Edge Cases

- Назначенная модель исчезла у провайдера: отказ «модель не найдена» с названием роли.
- Подключение роли удалено: роль возвращается к основному с пометкой.
- Серверный режим: свой адрес для роли подчиняется тем же разрешениям администратора, что
  в 050 FR-019.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Каждая роль агентов линейки MUST иметь выбор подключения и модели с
  умолчанием «как у основной».
- **FR-002**: Журнал 050 MUST показывать для каждого запроса роль и фактическую модель.
- **FR-003**: Отказ подключения роли MUST называть роль и MUST NOT мешать остальным ролям.
- **FR-004**: Для роли MUST быть доступно предпочтение хранения кэша; умолчание MUST
  сохранять поведение провайдера; варианты, не поддерживаемые провайдером, MUST быть
  недоступны.
- **FR-005**: Рядом с выбором долгого хранения MUST показываться предупреждение о
  возможном удорожании.
- **FR-006**: Журнал MUST показывать объёмы записи и чтения кэша, если провайдер их
  вернул; примерная стоимость MUST их учитывать при известных ценах.
- **FR-007**: Все тексты интерфейса MUST быть локализованы.

### Key Entities

- **Роль**: учитель, замер, практика, извлечение, сжатие, исследование, распознавание.
- **Назначение роли**: подключение, модель, предпочтение кэша.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% запросов идут к модели, назначенной их роли (проверка по журналу).
- **SC-002**: Настройка модели для одной роли — не больше 3 действий.
- **SC-003**: При умолчаниях запросы к провайдеру не отличаются от запросов 051.

## Assumptions

- Зависит от 050 (подключения, журнал, цены) и 051; роли остальных фич появляются по мере
  их готовности.
- Несколько подключений в одном vault вводятся этой фичей; 050 даёт одно основное.
