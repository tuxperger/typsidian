# Research: Модели по ролям

## §1. Несколько подключений

**Decision**: `AiSettings.connections[]` — дополнительные подключения `{ id, provider,
endpoint?, insecure_confirmed_for? }`; основное — поля 050 без изменений (старые vault
читаются как раньше). Ключ и одобрение адреса дополнительного подключения — секреты с
id подключения: `SecretKind::AiConnectionKey(id)`, `AiConnectionOrigin(id)` (строка
секрета `ai-conn-<id>-key` / `-origin`). Одобрение — по правилам M1 050.

## §2. Роли

**Decision**: `AiSettings.roles: { role → { connection?: id, model?, cache? } }`, роли:
`Teacher`, `Probe`, `Practice`, `Extract`, `Compact`, `Research`, `Speech`. Пусто —
основное подключение и модель. Ядро: `resolve_role(role)` → подключение, модель, кэш;
все ходы 051–058 берут подключение только так. Удалённое подключение — роль возвращается
к основному с пометкой `fallback` (Edge Case).

## §3. Журнал

**Decision**: `Sent` получает `role`; `Done` — `cache_write_tokens?`, `cache_read_tokens?`
из ответа провайдера. Цена учитывает кэш, когда справочник цен 050 знает цены кэша модели.

## §4. Хранение кэша

**Decision**: предпочтение `cache`: `Provider` (по умолчанию — ничего не добавлять к
запросу) / `Short` / `Long`. Для Anthropic — пометки кэширования на инструкции и истории с
нужным сроком; для OpenAI — параметр хранения кэша запроса. Точные имена полей и
поддерживаемые сроки сверяются с живой документацией при реализации (T002) и
записываются сюда. Свой адрес — только `Provider` (FR-004).
