# Contract: `EditorModeBridge` (шов к мосту редактирования)

**Feature**: `specs/004-app-settings/spec.md` | **Plan**: `../plan.md`

> **Моста к Neovim в кодовой базе не существует.** В `packages/core` сегодня есть только
> `vault` и `graph`; ни одного упоминания nvim в коде нет. Этот контракт описывает шов, через
> который раздел «Кейбиндинги» наблюдает и переключает подсистему, которая будет построена
> позже отдельной фичей — со своим `/speckit-clarify`, как требует принцип V конституции.
>
> Назначение контракта: позволить реализовать и полностью протестировать фичу 004 **до**
> появления моста и гарантировать, что его появление не изменит публичный API настроек, а лишь
> добавит вторую реализацию трейта.

## Реализации

| Реализация | Когда | Поведение |
|---|---|---|
| `NullBridge` | Веб-таргет постоянно; native — до появления моста | Полноценный режим всегда недоступен с явной причиной |
| `FakeBridge` | Только тесты | Управляемо воспроизводит все три состояния и отказные переходы |
| Реальный мост | Будущая фича | Добавляется рядом, API настроек не меняет |

Веб-клиент не может порождать внешние процессы, поэтому `NullBridge` остаётся там постоянной
реализацией. Это честная недоступность с причиной, а не заглушка (FR-034).

## Форма трейта

| Операция | Обязательство |
|---|---|
| `current_mode()` | Вернуть текущее состояние: `FullBackend`, `SimplifiedEmulation` или `PlainInput` (data-model.md) |
| `availability()` | Доступен ли полноценный режим на этом устройстве и почему нет (FR-034) |
| `request_mode(preference)` | Запросить переход к выбранному пользователем режиму |
| `apply_config(path)` | Применить конфиг по указанному пути (FR-026, FR-028) |
| `poll_events()` | Забрать события изменения состояния с прошлого вызова |

## Обязательства, проверяемые тестами

1. **Отказ не откатывает на эмуляцию.** При отказе или завершении внешнего процесса состояние
   становится `PlainInput`, и **никогда** — `SimplifiedEmulation` (FR-035). Отсутствие
   vim-раскладки должно быть однозначно отличимо от штатного режима.
2. **Выход из `PlainInput` только по явному действию.** Самопроизвольное восстановление
   запрещено: мост не пытается перезапуститься сам (FR-035).
3. **Текст пользователя не теряется при отказе.** Мост не владеет содержимым заметки: буфер
   остаётся у вызывающей стороны, поэтому отказ процесса не может унести с собой введённый
   текст (FR-035).
4. **Недоступность не выдаётся за работу.** Если полноценный режим недоступен, `current_mode()`
   не возвращает `FullBackend` ни при каких обстоятельствах (FR-034, FR-004).
5. **Конфиг не перечитывается сам.** `apply_config` вызывается только по явному действию
   пользователя; мост не следит за файлом и не применяет его самостоятельно (FR-026).

## Разделение ответственности

| Забота | Чья |
|---|---|
| Обнаружить, что файл конфига изменился на диске | Настройки (`FileStamp`, research.md §8) |
| Применить конфиг по команде | Мост |
| Решить, можно ли сейчас менять режим | Настройки (`ApplyPlan`, research.md §9) |
| Сохранить открытую заметку перед сменой режима | Вызывающая сторона через `VaultBackend::write` |
| Породить и обслуживать внешний процесс | Мост (будущая фича) |

Отслеживание файла конфига намеренно оставлено настройкам, а не мосту: та же семантика «файл
действительно изменился» уже реализована в ядре для обнаружения конфликтов vault, и вторая
реализация была бы вторым источником истины (принцип I).

## Что этот контракт НЕ фиксирует

Протокол общения с внешним процессом, формат сообщений, стратегию перезапуска, разбор конфига,
таймауты и версионирование — всё это принадлежит будущей фиче моста и её собственному
`/speckit-clarify` (принцип V). Здесь зафиксированы только **наблюдаемые состояния и переходы
между ними**, потому что именно их показывает и переключает раздел «Кейбиндинги».
