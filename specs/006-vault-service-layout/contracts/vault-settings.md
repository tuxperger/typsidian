# Контракт: настройки уровня vault

**Фича**: `006-vault-service-layout` | **Модули**: `packages/core/src/vault/vault_settings.rs`,
`vault/service_dir.rs`, `vault/sections.rs`, `settings/mod.rs`

> **Формат файла пересмотрен 2026-09-09: JSON (`vault.json`), а не TOML.** Развёрнуто вместе с
> `settings.json` фичи 004 по прямому указанию владельца проекта — см.
> [004/research.md §2](../../004-app-settings/research.md). Цена та же и здесь не замалчивается:
> **комментариев в файле больше нет**, а порядок ключей задаёт приложение (алфавитный).
> Уцелевшее из прежней гарантии: дописанное пользователем руками переживает запись из панели,
> неизвестные ключи не являются ошибкой разбора, сломанный синтаксис по-прежнему называется
> ошибкой, а не подменяется молча умолчаниями (FR-034).
>
> **Переноса с прежнего формата нет.** `.typsidian/vault.toml`, написанный прежней версией,
> новой не читается: папка выглядит ненастроенной, и всё берётся с устройства (FR-023). Прежний
> файл при этом **не трогается** — ни удаления, ни переименования, — так что перенести значения
> руками возможно. Это наблюдаемая потеря настроек уровня vault при обновлении, и названа она
> здесь прямо, а не спрятана в реализацию.

## Почему здесь нет трейта

Функции поверх `VaultBackend`, а не третья реализация `SettingsStore` — тот же приём, что в
`boards/store.rs`. Обоснование в [research.md §3](../research.md); повторять его здесь незачем,
но нарушать нельзя: реализация, заведшая под `vault.json` собственный платформенный шов,
контракт нарушает.

## Раскладка служебного места

```rust
pub const SERVICE_DIR_NAME: &str = ".typsidian";

pub fn service_dir() -> &'static Path;                  // ".typsidian"
pub fn vault_settings_path() -> PathBuf;                // ".typsidian/vault.json"
pub fn cache_path() -> PathBuf;                         // ".typsidian/cache.sqlite"
pub fn packages_dir() -> PathBuf;                       // ".typsidian/packages"
pub fn is_inside_service_dir(path: &Path) -> bool;
```

Пути **относительны корню vault** — абсолютных путей на web не существует, и контракт не имеет
права их требовать.

## Формат `vault.json`

```json
{
  "assets": {
    "placement": "next-to-note",
    "sections": ["Работа", "Личное/Дневник"]
  },
  "settings": {
    "theme": "dark",
    "editor_font_size": 16,
    "editor_mode_preference": "fullBackend",
    "editor_config_path": "/home/user/.config/editor/init.lua"
  }
}
```

`placement` — одно из `"next-to-note"`, `"vault-root"`, `"section-root"`; все ключи объекта
`settings` необязательны.

Отсутствующий ключ — не значение по умолчанию, а «спросить устройство». Отсутствующий объект
эквивалентен пустому. Объект, из которого вычистили все ключи, **не остаётся пустым** в файле:
приложение убирает его целиком, чтобы не оставлять в пользовательском файле собственный мусор.

## Операции

```rust
pub async fn read_vault_settings<B: VaultBackend>(backend: &B)
    -> Result<VaultOverrides, VaultSettingsError>;

pub async fn write_vault_settings<B: VaultBackend>(
    backend: &mut B,
    overrides: &VaultOverrides,
) -> Result<(), VaultSettingsError>;
```

| Исход | Когда |
|-------|-------|
| `Ok(VaultOverrides::default())` | файла нет — штатное состояние, не ошибка (FR-023) |
| `Err(Unreadable)` | файл есть, но не разбирается: **не перезаписывается**, откладывается рядом (FR-034) |
| `Err(NotWritable)` | vault недоступен на запись: служебное место не создаётся (FR-025) |
| `Err(Io)` | отказ диска |

**Запись сохраняет чужое**: тот же приём, что в `settings/format.rs` — разбор идёт через
`serde_json::Value`, а не через форму файла, и ключи, которых приложение не знает, остаются в
объекте нетронутыми. Комментариев в JSON нет, и переживать записи им нечем; порядок ключей
задаёт приложение — алфавитный, свойство `BTreeMap` под `serde_json::Map`, и от записи к записи
он стабилен.

**Момент создания папки**: при открытии vault, **доступного на запись**, — на обоих таргетах
одинаково ([research.md §12](../research.md)). Создание идёт отдельным `ensure_folder`, как это
делает `write_snapshot`. Vault только на чтение папки не получает нигде (FR-025).

## Разрешение слоёв

```rust
pub fn resolve(device: &Settings, overrides: &VaultOverrides) -> Settings;
```

Чистая функция, поле за полем: `Some` из vault перекрывает, `None` пропускает значение
устройства. Список известных vault и текущий vault перекрытию не подлежат — в `VaultOverrides`
этих полей нет физически (FR-028).

## Маршрутизация записи

| Действие пользователя | Куда пишется | Требование |
|----------------------|--------------|-----------|
| Тема, шрифт, режим, путь к конфигу при открытом vault | `vault.json` | FR-029 |
| «Сделать значениями по умолчанию» | `settings.json` устройства | FR-031 |
| Политика ассетов, пометки разделов | `vault.json` | FR-002, FR-015 |
| Добавить/забыть vault, выбрать текущий | `settings.json` устройства | FR-028 |

**Запрещено**: писать одно действие в оба хранилища. Проверяется тестом, сверяющим содержимое
`settings.json` до и после смены темы при открытом vault.

**Vault не открыт**: изменение темы пишется в устройство — перекрывать нечего.

## Разделы

```rust
pub fn nearest_section<'a>(sections: &'a [SectionMark], note_path: &Path)
    -> Option<&'a SectionMark>;

pub fn rename_section(sections: &mut Vec<SectionMark>, from: &Path, to: &Path) -> bool;

pub fn prune_missing(sections: &[SectionMark], existing_folders: &[PathBuf])
    -> Vec<SectionMark>;   // возвращает утратившие адресата, НЕ удаляет их
```

| Обязательство | Требование |
|---------------|-----------|
| `nearest_section` сравнивает по компонентам пути, не по строке | FR-016 |
| `rename_section` переносит пометку и все вложенные пометки под переименованным префиксом | FR-018 |
| `prune_missing` только **сообщает** об утративших адресата | FR-019 — молчаливое удаление скрыло бы от пользователя, что пометка потеряна |
| Розыска папки по новому расположению нет ни в одной функции | FR-019, то же правило, что в `settings/folder_ref.rs` |

## Уборка наследия

```rust
pub const LEGACY_CACHE_FILE: &str = ".typsidian-cache.sqlite";
```

При открытии vault на native: если файл есть в корне — удалить, кэш строить заново
(FR-021, research §11). Отказ удаления не блокирует открытие: vault открывается, файл остаётся,
пользователь получает сообщение. На web операция отсутствует — файла там никогда не было.

## Утрата служебного места (FR-024)

Сообщение об утрате настроек показывается **только** если папка заметок уже открывалась на этом
устройстве, а служебного места в ней больше нет. Признак «открывалась» берётся из уже
существующего списка известных vault (`Settings::known_vaults`) — нового состояния для этого не
заводится. Папка, открываемая впервые, сообщения не вызывает: терять было нечего, а ложное
сообщение об утрате хуже его отсутствия.

## Обязательства границы

Каждая операция обязана дойти до UI обоими путями:

| Ядро | `#[tauri::command]` | `#[wasm_bindgen]` | Клиент TS |
|------|--------------------|--------------------|-----------|
| `read_vault_settings` | `vault_settings` | `vaultSettings` | `vaultSettings()` |
| `write_vault_settings` | `set_vault_settings` | `setVaultSettings` | `setVaultSettings()` |
| `nearest_section` | не нужен | не нужен | — вызывается внутри расчёта пути |
| пометить/снять раздел | `mark_section` / `unmark_section` | `markSection` / `unmarkSection` | одноимённые |

Операция, дошедшая только до ядра, считается несделанной.
