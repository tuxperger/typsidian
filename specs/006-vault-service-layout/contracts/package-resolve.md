# Контракт: разрешение внешних шаблонов Typst

**Фича**: `006-vault-service-layout` | **Модуль**: `packages/core/src/preview/resolve.rs`

Снимает ограничение фичи 005, где любой пакет отвергался как выход за пределы vault
(`resolve.rs:60`). Сетевого пути не появляется — только чтение того, что пользователь положил
локально.

## Отображение идентификатора в путь

```text
FileId { root: VirtualRoot::Package(spec), vpath }
  ->  .typsidian/packages/<spec.namespace>/<spec.name>/<major>.<minor>.<patch>/<vpath>
```

Раскладка `<namespace>/<name>/<version>/` совпадает с каталогом пакетов самого Typst: папку,
уже скачанную штатным `typst`, пользователь копирует как есть.

```rust
pub fn package_path(spec: &PackageSpec, vpath: &VirtualPath) -> PathBuf;
```

`FileId::root() == VirtualRoot::Project` по-прежнему отображается в путь внутри vault — эта
ветка не меняется.

## Отказы

```rust
pub enum ResolveError {
    NotFound,
    Unreadable,
    AccessDenied,
    OutsideVault,
    TooLarge,
    PackageMissing { spec: String },              // НОВЫЙ
    PackageVersionMismatch { spec: String, available: Vec<String> },  // НОВЫЙ
}
```

| Проверка | Исход | Требование |
|----------|-------|-----------|
| Папки `packages/<ns>/<name>/` нет | `PackageMissing` | FR-037 |
| Папка есть, папки версии нет | `PackageVersionMismatch` с перечислением имеющихся | FR-038 |
| Папка версии есть, файла внутри нет | `NotFound` | FR-037 — причина иная, сообщение иное |

**`spec` — строка, а не структура.** Берётся у `Display for PackageSpec`, который печатает
`@preview/codly:1.3.0`. Собирать этот текст вручную запрещено: он обязан совпадать с тем, что
пользователь написал в `#import`.

**`PackageMissing` — отдельный вариант, а не `OutsideVault`.** «Шаблон не установлен» и «ссылка
за пределы vault» — разные факты и разные сообщения; FR-037 запрещает общий отказ.

## Сверка версии

Точная. `@preview/codly:1.3.0` требует папку `1.3.0`. Подстановка «совместимой» версии
запрещена (FR-038): так работает сам Typst, и молчаливая подмена дала бы пользователю документ,
собранный не тем шаблоном, о котором он просил.

## Диагностика

`describe()` расширяется двумя формулировками, называющими шаблон:

```text
PackageMissing          -> «шаблон @preview/codly:1.3.0 не найден в папке заметок»
PackageVersionMismatch  -> «шаблона @preview/codly:1.3.0 нет; локально есть версии: 1.2.0, 1.4.0»
```

Существующий контракт фичи 005 — «имя файла подставляет вызывающая сторона, здесь только
причина» — здесь неприменим: имя шаблона несёт сама причина, а вызывающая сторона его не знает.

## Обязательства

1. **Сети нет.** Чтение только через `VaultBackend`, у которого сетевого пути не существует
   (FR-039, принцип VII). Проверяется тем, что модуль не получает новых зависимостей.
2. **Предел размера наследуется.** Файл шаблона читается тем же путём, что связанный файл
   заметки, и подчиняется тому же `TooLarge`.
3. **Паритет таргетов.** Отображение пути — чистая функция, проверяемая таблицей на обоих
   таргетах; чтение идёт через уже существующий шов.
4. **Заметка без подключений не задета.** Отсутствие `.typsidian/packages/` не влияет ни на
   один документ, который пакетов не подключает (FR-039).

## Проверяемые сценарии

| Сценарий | Ожидание |
|----------|----------|
| `#import "@preview/codly:1.3.0"`, папка версии на месте | документ собран |
| Той же папки нет, есть `1.2.0` | `PackageVersionMismatch`, в тексте видны и `1.3.0`, и `1.2.0` |
| Папки `codly` нет вовсе | `PackageMissing` с текстом `@preview/codly:1.3.0` |
| Папка версии есть, но нужного файла внутри нет | `NotFound` |
| Документ без `#import` пакетов, `.typsidian/packages/` отсутствует | документ собран |
| `#import "@local/мой:0.1.0"` | тот же путь, namespace `local` — специального случая для `preview` нет |
