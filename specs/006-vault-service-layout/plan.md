# Implementation Plan: Vault Service Layout

**Branch**: `006-vault-service-layout` | **Date**: 2026-09-07 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/006-vault-service-layout/spec.md`

## Summary

Всё, что приложение хранит для конкретного vault, съезжает в одну скрытую папку `.typsidian/`
внутри него, а расположение файлов вставленных досок становится выбором пользователя из трёх
вариантов: рядом с заметкой, в корне vault, в корне помеченного раздела. Раскладка внутри
выбранного корня единая — `assets/<имя заметки>/`.

Технически это четыре независимых куска, соединённых одной папкой:

1. **Расчёт пути снимка** — чистые функции в `boards/placement.rs` поверх политики и списка
   разделов; `snapshot_path`/`plan_embed`/`embeds_of` начинают их вызывать вместо жёсткого
   правила «`<имя>.assets` рядом с заметкой».
2. **Настройки уровня vault** — `.typsidian/vault.json`, читается и пишется **функциями поверх
   `VaultBackend`**, без третьей реализации трейта (research §3). Слой поверх значений
   устройства: `resolve(&Settings, &VaultOverrides)`.
3. **Классификация** — `FileKind::Service` для `.typsidian/**` и расширенное правило снимка,
   сохраняющее распознавание старых `*.assets` (research §5).
4. **Внешние шаблоны** — `preview/resolve.rs` перестаёт отвергать `VirtualRoot::Package` и
   отображает его в `.typsidian/packages/…` (research §8).

Скрытие служебной папки в дереве кода не требует: оба backend уже исключают записи, начинающиеся
с точки (research §1). Миграция настроек кода тоже не требует: существующий `settings.json` и
есть значения устройства (research §4).

## Technical Context

**Language/Version**: Rust 2021 (ядро), TypeScript 5 strict (UI), React 19 / Next.js (web)

**Primary Dependencies**: `typst` 0.15.1 (+`typst-syntax` для `PackageSpec`), `sqlx`/SQLite
(кэш, native), `serde_json` через `settings/format.rs` (запись, сохраняющая чужие ключи),
`wasm-bindgen`/`tsify-next` (граница WASM), `tauri` (native-биндинг)

**Storage**: файлы vault через `VaultBackend`; `.typsidian/vault.json` (JSON — формат
пересмотрен 2026-09-09, см. [contracts/vault-settings.md](./contracts/vault-settings.md));
`.typsidian/cache.sqlite` (SQLite, только native); `settings.json` в каталоге ОС остаётся
хранилищем значений устройства

**Testing**: `cargo test` + `wasm-bindgen-test` для каждой единицы логики ядра (принцип I),
`cargo test --target wasm32-unknown-unknown` для гейта принципа II

**Target Platform**: Linux/macOS/Windows desktop (Tauri), браузер (WASM + File System Access
API), задел под mobile

**Project Type**: монорепо — Rust-ядро + общий UI-код + три клиента

**Performance Goals**: открытие vault не деградирует относительно бюджетов фичи 001 (дерево
пригодно для навигации ≤3 с, полный обход ≤10 с при 10 000 заметок). Первое открытие после
обновления делает один дополнительный полный обход — цена уборки кэша прежней версии
(research §11)

**Constraints**: offline-capable без исключений (принципы VII, IX — сеть не задействуется даже
для шаблонов, FR-039); паритет таргетов NON-NEGOTIABLE; TypeScript strict без `any`

**Scale/Scope**: до 10 000 заметок на vault (`SUPPORTED_NOTE_COUNT`); список разделов —
рабочая граница десятки записей, как и список известных vault

| **VI. Local-first** | Vault остаётся набором обычных файлов. Удаление `.typsidian/` не теряет ни заметок, ни досок, ни снимков (FR-023). Приложение открывает vault без служебной папки | ✅ |
| **VII. Деградация в офлайне** | Сеть не задействуется вовсе. Отсутствующий шаблон — названный отказ, а не спиннер (FR-037) | ✅ |

**Structure Decision**: раскладка существующая, новых пакетов и слоёв не вводится. Новые модули
ядра встают рядом с теми, чью ответственность продолжают: расчёт пути снимка — в `boards/`,
раскладка служебной папки и настройки vault — в `vault/`, разрешение слоёв — в `settings/`.

Обязательная цепочка для каждой новой операции ядра: **ядро → биндинг (`#[tauri::command]` и
`#[wasm_bindgen]`) → клиент (`vault-client.ts` / `tauriVaultClient.ts`) → компонент**. Логика,
дошедшая только до ядра, считается несделанной — `/speckit-tasks` разбивает по этой цепочке.

## Известные ограничения, принятые сознательно

| Ограничение | Причина |
|-------------|---------|
| Правка `.typsidian/vault.json` руками при работающем приложении подхватывается только при следующем открытии vault | Служебная папка исключена из обхода, вотчер на неё не вешается (research §10). После `/speckit-analyze` это перестало быть молчаливым ограничением и закреплено требованием **FR-040** |
| `.typsidian/` создаётся при открытии vault, доступного на запись, — в том числе на web, где кэша в файле нет | Иначе одно действие пользователя давало бы разный результат на двух клиентах (research §12) |
| Сообщение об утрате настроек не показывается при первом открытии папки на этом устройстве | Отличить «удалили» от «никогда не было» неоткуда; ложное сообщение хуже его отсутствия (FR-024) |
| **Найдено при реализации.** `VaultEvent::VaultSettingsLost` в интерфейсе пока не наступает: решение в ядре готово и покрыто тестами, но факт «эту папку уже открывали» до места решения не доходит | Список известных vault принадлежит панели настроек, а открытие папки идёт мимо неё. Протаскивать хранилище устройства в путь открытия ради одного предупреждения — отдельное решение. Вторая половина FR-025 (`VaultSettingsReadOnly`) подключена и работает |
| **Найдено при реализации.** Диагностика отсутствующего шаблона не перечисляет имеющиеся локально версии, как обещает FR-038 | Перечисление требует обхода произвольного каталога, которого у `VaultBackend` нет: он знает только индекс заметок, куда служебное место не попадает. Существенная часть FR-038 выполнена — запрошенная версия названа, подстановки другой не происходит |
| **Найдено при реализации.** Команды Tauri для настроек не заводились | У рабочего стола нет собственного хранилища настроек вовсе, и панель настроек там не показывается — ограничение фичи 004, не этой |
| Первое открытие vault после обновления делает один дополнительный полный обход | Кэш прежней версии удаляется, а не мигрируется (research §11) |
| Заметки-тёзки из разных папок делят подпапку при вариантах «в корне» и «в корне раздела» | Файлы не сталкиваются: имя выводится из полного пути заметки (research §12). Разделение — вне скоупа спеки |
| Адрес снимка при политике «в корне» может содержать цепочку `../` | Цена чистоты разбора вставок (research §7) |
| Кэш предпросмотра только зарезервирован в раскладке, папка не создаётся | Дискового кэша предпросмотра не существует (research §2) |
