# Data Model: Vault Service Layout

**Фича**: `006-vault-service-layout` | **Дата**: 2026-09-07

Сущности, их поля, правила валидации и переходы состояний. Формы, пересекающие границу
WASM/JS, помечены — для них порождаются типы TypeScript (принцип IV).

## AssetsPlacement

Вариант расположения файлов вставок. Пересекает границу.

```rust
pub enum AssetsPlacement {
    NextToNote,   // по умолчанию (FR-003)
    VaultRoot,
    SectionRoot,
}
```

| Правило | Требование |
|---------|-----------|
| Значение по умолчанию — `NextToNote` | FR-003 |
| Значение принадлежит vault, не устройству | FR-002 |
| Смена значения не двигает файлы и не правит заметки | FR-007 |

## SectionMark

Пометка папки как корня раздела.

```rust
pub struct SectionMark {
    pub path: PathBuf,   // относительно корня vault, нормализован
}
```

| Правило | Требование |
|---------|-----------|
| Путь относителен корню vault; абсолютные пути и `..` отвергаются | принцип VI, FR-035 |
| Пустой путь допустим — помечен сам корень vault | Edge Cases спеки |
| Дубли в списке недопустимы | инвариант хранилища |
| Ближайший помеченный предок — самый длинный подходящий префикс | FR-016 |
| Переименование средствами приложения обновляет `path` | FR-018 |
| Внешнее исчезновение папки помету не переносит и не разыскивает | FR-019 |

**Переходы**: `отсутствует → помечена` (действие пользователя) → `отсутствует` (снятие) либо
`утратила адресата` (внешнее исчезновение; наблюдаемое состояние, не хранимое поле — выводится
сверкой с индексом при открытии vault).

## VaultOverrides

Настройки уровня vault. Каждое поле `Option`: `None` — «спросить устройство» (research §4).
Пересекает границу.

```rust
pub struct VaultOverrides {
    pub assets_placement: Option<AssetsPlacement>,
    pub sections: Vec<SectionMark>,
    pub theme: Option<Theme>,
    pub editor_font_size: Option<u8>,
    pub editor_mode_preference: Option<ModePreference>,
    pub editor_config_path: Option<PathBuf>,
}
```

| Правило | Требование |
|---------|-----------|
| `editor_font_size` проверяется тем же `is_valid_font_size`, что и у устройства | принцип II — диапазон не имеет права разойтись |
| `sections` — не `Option`: пустой список и «не задано» неразличимы по смыслу | упрощение без потери выразительности |
| Испорченный файл не перезаписывается; откладывается рядом с меткой UTC | FR-034 |
| Файл отсутствует — все поля `None`, это штатное состояние, не ошибка | FR-023 |

**Связь с `Settings`** (устройство, существующий тип): `resolve(&Settings, &VaultOverrides) ->
Settings` — чистая функция, поле за полем. Список известных vault и текущий vault в
`VaultOverrides` отсутствуют физически (FR-028): их там не может быть даже по ошибке.

## VaultServiceDir

Раскладка служебного места. Не хранимая сущность — набор чистых функций над корнем vault.

```text
.typsidian/                 SERVICE_DIR_NAME
├── vault.json              vault_settings_path()
├── cache.sqlite            cache_path()            (native)
├── packages/               package_path(spec, vpath)
└── preview/                зарезервировано, не создаётся
```

| Правило | Требование |
|---------|-----------|
| Единственное место служебных файлов внутри vault | FR-020 |
| Скрыто в дереве автоматически: имя начинается с точки | FR-022, research §1 |
| Удаление целиком допустимо и не ломает vault | FR-023 |
| Не создаётся, если vault недоступен на запись | FR-025 |
| Не является признаком тождества vault | FR-035 |

## FileKind (расширение существующего)

```rust
pub enum FileKind {
    Note,
    Board,
    Snapshot,
    Service,   // НОВЫЙ: всё внутри .typsidian/
    Other,
}
```

`FileKind::is_listed()` для `Service` возвращает `false` — как и для `Snapshot` и `Other`.

**Правило классификации снимка** после фичи (research §5):

```text
Service  ⟸ путь начинается с «.typsidian/»
Snapshot ⟸ внутри папки «*.assets»                               (прежнее, FR-009)
         ∨ внутри «…/assets/<любая>/» И имя вида «board-<hex>.svg» (новое)
```

Порядок проверок значим: `Service` проверяется первым — файл `.typsidian/assets/…`, если он
когда-нибудь появится, остаётся служебным, а не снимком.

## AssetPath

Расчётный путь снимка. Не хранится — выводится при каждом обращении.

```text
вход:  policy, note_path, sections, embed_id
выход: snapshot_path  — от корня vault, для записи файла
       markup_path    — от папки заметки, попадает в текст (research §7)
```

| Правило | Требование |
|---------|-----------|
| Подпапка называется по имени заметки без расширения | FR-004 |
| Раскладка одинакова для всех трёх вариантов; различается только корень | FR-004 |
| Имя файла выводится из полного пути заметки и пути доски | без изменений с 002; отсюда отсутствие столкновений у заметок-тёзок |
| Обновление вставки пишет по адресу, записанному в тексте, а не по расчётному | FR-008 |

## PackageRef

Ссылка на внешний шаблон. Не хранится — приходит от компилятора.

```text
FileId{ root: Package(PackageSpec{namespace,name,version}), vpath }
  -> .typsidian/packages/<namespace>/<name>/<major.minor.patch>/<vpath>
```

| Состояние | Наблюдаемое поведение | Требование |
|-----------|----------------------|-----------|
| Файл найден | документ собирается | FR-036 |
| Папки `<namespace>/<name>/` нет | «шаблон `@preview/codly:1.3.0` не найден» | FR-037 |
| Папка есть, нужной версии нет | «версия не совпадает», с перечислением имеющихся | FR-038 |
| Сеть | не задействуется ни в одном состоянии | FR-039 |

Текст спецификации берётся у `Display for PackageSpec` — `@namespace/name:version`
(research §8), а не собирается вручную.

## Инварианты

1. **Служебное место — единственное.** Приложение не создаёт файлов в vault вне `.typsidian/` и
   папок ассетов. Проверяется тестом, сверяющим список созданного после сценария (SC-007).
2. **Кэш ничего не хранит авторитетно.** Удаление `.typsidian/cache.sqlite` не меняет ни одного
   наблюдаемого пользователем факта, кроме времени первого открытия (FR-023, принцип
   «производное состояние восстановимо» из конституции).
3. **Прежняя раскладка распознаётся всегда.** Ни одно значение `AssetsPlacement` не отключает
   ветку распознавания `*.assets` (FR-009, FR-010).
4. **Ни одна запись настроек не идёт в оба хранилища.** Изменение при открытом vault пишет
   только в vault; «сделать по умолчанию» — только в устройство (FR-029, FR-031).
5. **Расчёт пути — чистая функция.** Ни одна ветка расчёта не читает файлов, поэтому вся
   таблица «политика × расположение × разделы» проверяется одинаково на обоих таргетах.
