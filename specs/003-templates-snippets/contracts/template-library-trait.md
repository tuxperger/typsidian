# Contract: TemplateLibrary (внутренний контракт ядра)

**Feature**: `specs/003-templates-snippets/spec.md` | **Plan**: [../plan.md](../plan.md)

Публичный API фичи со стороны `packages/core`. Одна реализация на оба таргета: платформенных
различий у фичи нет — всё, что различается, уже скрыто трейтом `VaultBackend` из 001.

## Форма

```rust
pub trait TemplateLibrary {
    /// Состав библиотеки: все заметки внутри `templates/`, включая вложенные папки.
    /// Проекция уже построенного индекса заметок, а не отдельный обход диска.
    fn library(&self) -> TemplateLibraryView;

    /// Состояние папки шаблонов (FR-004, FR-009).
    fn folder_state(&self) -> TemplateFolderState;

    /// Проверить имя будущей заготовки ДО любых изменений на диске (FR-029).
    fn check_name(&self, name: &str) -> NameCheck;

    /// Сохранить содержимое как заготовку. Перезапись существующей — только при
    /// `confirm_overwrite: true` (FR-028).
    fn save_as_template(
        &mut self,
        name: &str,
        content: &str,
        confirm_overwrite: bool,
    ) -> Result<Template, SaveTemplateError>;

    /// Прочитать содержимое заготовки для применения — создания заметки или вставки.
    fn read_template(&self, path: &Path) -> Result<String, ReadTemplateError>;

    /// Фрагмент исходного текста для карточки: начало содержимого, обрезанное по границе
    /// строки (data-model.md «PreviewState»).
    fn excerpt(&self, content: &str) -> String;
}
```

## Правила

**Библиотека не обходит диск отдельно.** `library()` строится из того же индекса заметок, что
питает дерево (research.md §3). Второй обход означал бы второй момент времени и расхождение
между тем, что показывает дерево, и тем, что показывает галерея, — на одних и тех же файлах.

**Создание заметки из заготовки в трейте отсутствует, и это намеренно.** Операция сводится к
`read_template` плюс существующие `VaultBackend::create` и `write` (research.md §7). Заводить
для неё метод здесь значило бы продублировать валидацию имени и расположения новой заметки,
которую FR-022 требует выполнять «теми же средствами». Композиция вызывается из UI, но
правил в ней нет — только порядок.

**`save_as_template` создаёт папку шаблонов, если её нет** (FR-002), и это единственная новая
операция фичи над файловой системой. Отдельного действия от пользователя не требуется.

**`check_name` — обязательный шаг перед сохранением, а не подсказка.** `save_as_template` без
`confirm_overwrite` на занятом имени возвращает `SaveTemplateError::NameTaken` даже если UI
проверку пропустил: правило живёт в ядре, а не в диалоге (research.md §8). Это же снимает
гонку «файл появился между проверкой и записью».

**Отказы называются причиной.** `SaveTemplateError` перечисляет `NameTaken`,
`InvalidName { reason }`, `FolderNotWritable`, `Io` — не общий «не удалось» (FR-030). То же
для `ReadTemplateError`: `NotFound`, `Unreadable`, `Io`.

**Нечитаемая заготовка не перезаписывается.** `read_template` на нечитаемом файле возвращает
`Unreadable`, и из этого состояния нет пути к записи (FR-017) — тот же принцип, что у
повреждённого `settings.json` в 004 и повреждённой доски в 002.

## Что этот контракт не фиксирует

- **Компиляцию превью.** Она за портом `PreviewSource` (contracts/preview-source.md), потому
  что компилятора Typst в проекте пока нет и фича не должна его ждать.
- **Вставку в текст.** Она за портом `InsertionTarget` (contracts/insertion-target.md),
  граница которого совпадает с границей гейта принципа V.
- **Виртуализацию галереи, момент построения превью, фокус и курсор.** Это UI: проверяется
  сценариями `quickstart.md`, а не тестами ядра (research.md §9).

## Тестируемость

Каждый метод покрывается `cargo test` и `wasm-bindgen-test` (принципы I, II). Отдельно
фиксируются:

- заметка, положенная в `templates/` любым способом, попадает в `library()` (FR-007);
- отсутствие папки даёт `Absent`, а не ошибку (FR-009);
- `check_name` отклоняет недопустимое имя, и при этом на диске ничего не меняется (FR-029);
- `save_as_template` без подтверждения на занятом имени не трогает существующий файл (FR-028);
- `excerpt` не разрывает строку посередине;
- содержимое, сохранённое как заготовка, не меняется при последующей правке исходной заметки
  (FR-027, инвариант 3).
