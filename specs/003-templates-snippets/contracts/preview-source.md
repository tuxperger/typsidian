# Contract: PreviewSource (порт превью)

**Feature**: `specs/003-templates-snippets/spec.md` | **Plan**: [../plan.md](../plan.md)

Порт, за которым живёт построение превью заготовки. Существует по одной причине: **FR-011
требует отрисованный вид документа, а компилятора Typst в проекте нет** — проверено по
`packages/core/Cargo.toml`, зависимости `typst` там отсутствуют (research.md §1).

## Форма

```rust
pub trait PreviewSource {
    /// Доступен ли конвейер отрисовки в этой сборке.
    fn availability(&self) -> PreviewAvailability;

    /// Построить превью для содержимого заготовки.
    fn preview(&self, content: &str) -> PreviewState;
}

pub enum PreviewAvailability {
    /// Компилятор есть: возможен `PreviewState::Rendered`.
    Available,
    /// Компилятора в сборке нет: любое содержимое даёт `SourceExcerpt`
    /// с причиной `CompilerUnavailable`.
    CompilerUnavailable,
}
```

## Две реализации

| Реализация | Когда | Поведение |
|---|---|---|
| `ExcerptOnlySource` | сегодня, пока компилятора нет | всегда `SourceExcerpt { reason: CompilerUnavailable }` |
| `TypstPreviewSource` | когда компилятор появится в ядре | `Rendered` при успехе, `SourceExcerpt { reason: DoesNotCompile }` при ошибке компиляции |

Переключение — выбор реализации при сборке, а не ветвление внутри галереи. Когда компилятор
появится, меняется одна строка сборки; `TemplateLibrary`, модель данных, карточки и сценарии
`quickstart.md` не трогаются.

## Правило, которое нельзя нарушить

**`CompilerUnavailable` и `DoesNotCompile` — разные причины и показываются по-разному.**

FR-012 требует помечать карточку с текстовым превью и объяснять причину, «чтобы разница между
карточками не выглядела произвольной». Если обе причины схлопнуть в одну пометку, пользователь
в сегодняшней сборке увидит, что **все** его заготовки «не компилируются», и сделает
единственный доступный вывод — что сломаны они, а не конвейер. Это не косметика: это разница
между «у тебя ошибка в Typst» и «мы пока не умеем показывать отрисованный вид».

В `strict` TypeScript оба варианта приходят как размеченное объединение и обрабатываются
исчерпывающе (принцип IV) — забыть один нельзя.

## Что порт не решает

**Некомпилируемость — не ошибка.** FR-013 и clarification 2026-08-08 фиксируют: фрагмент кода
сам по себе обычно не компилируется, и это штатный случай. Поэтому `PreviewState` не имеет
варианта «ошибка»: `SourceExcerpt` — полноценный результат, а не отказ. Заготовка с таким
превью доступна и для вставки, и для создания заметки наравне с остальными (SC-005).

**Кэш — не забота порта.** Ключ `BLAKE3` содержимого и хранение результата живут в
`packages/core/src/templates/preview.rs` (research.md §4). Порт вызывается только при промахе
кэша, и это позволяет заменить реализацию, не трогая политику кэширования.

**Момент построения — не забота порта.** Ленивость, видимая область, порядок — UI
(FR-014, SC-004). Порт получает содержимое и возвращает состояние.

## Тестируемость

- `ExcerptOnlySource` на любом содержимом даёт `CompilerUnavailable`, а не `DoesNotCompile` —
  `cargo test` и `wasm-bindgen-test`.
- Промах и попадание в кэш дают одинаковый `PreviewState` для одного содержимого.
- Изменение содержимого меняет `content_hash` и вызывает пересчёт (SC-010).
- Нечитаемый файл даёт `Unavailable`, а не `SourceExcerpt` с пустым фрагментом (FR-017).
