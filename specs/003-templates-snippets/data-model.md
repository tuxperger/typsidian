# Data Model: Templates and Snippets

**Feature**: `specs/003-templates-snippets/spec.md` | **Plan**: [plan.md](./plan.md)

Сущности Phase 1. Именование следует «Key Entities» спеки. Всё, что пересекает границу
WASM/JS, порождается через `tsify` из этих определений — ручных копий на TypeScript нет
(принцип IV).

## Template

Заготовка — обычная заметка, лежащая в папке шаблонов.

| Поле | Тип | Смысл |
|---|---|---|
| `path` | `PathBuf` | путь относительно корня vault, всегда внутри `templates/` |
| `name` | `String` | имя файла для показа в карточке и поиска (FR-015) |
| `group` | `Option<PathBuf>` | вложенная папка внутри `templates/`, если есть — группировка галереи |
| `stamp` | `FileStamp` | отпечаток файла; тип из 001 |
| `content_hash` | `Option<[u8; 32]>` | BLAKE3 содержимого; ключ кэша превью (research.md §4) |

`Template` не хранит содержимое: оно читается по требованию — при построении превью, при
создании заметки и при вставке. Держать 200 файлов в памяти ради галереи, которая показывает
десяток карточек, незачем (research.md §4, §10).

`content_hash` — `Option`, потому что файл может быть нечитаем: тогда хэша нет, а карточка
помечается недоступной (FR-017).

**Отдельного типа для «сниппета» не существует.** Спека это фиксирует прямо (FR-019,
clarification 2026-08-08): библиотека одна, деления на виды нет, способ применения не зависит
от содержимого.

## TemplateLibrary

Состав библиотеки — проекция дерева заметок на папку `templates/`.

| Поле | Тип | Смысл |
|---|---|---|
| `templates` | `Vec<Template>` | все заметки внутри `templates/`, включая вложенные папки |
| `folder_state` | `TemplateFolderState` | состояние самой папки шаблонов |

Библиотека **не является отдельным реестром**: она пересчитывается из того же индекса
заметок, что питает дерево (research.md §3). Отсюда FR-007 — заметка попадает в галерею
независимо от того, как она там оказалась, — и FR-008: заготовки участвуют в поиске и графе
ссылок, потому что остаются обычными заметками.

## TemplateFolderState

| Вариант | Когда | Поведение |
|---|---|---|
| `Present` | папка существует и читается | обычная работа |
| `Absent` | папки нет | пустая галерея как штатное состояние, не ошибка (FR-009, FR-016) |
| `Unreadable { reason }` | папка есть, но недоступна на чтение | сообщение с причиной, остальное приложение работает (FR-004) |
| `NotWritable { reason }` | чтение есть, записи нет | галерея работает, сохранение заготовки отклоняется с причиной (FR-004, US2 AS6) |

`Absent` отделён от `Unreadable` намеренно: «папки ещё нет» — нормальное состояние нового
vault, которое чинится первым же сохранением (FR-002), а «папка есть, но не читается» —
проблема, о которой нужно сказать. Схлопывание этих двух состояний превратило бы штатный путь
в ошибку.

## PreviewState

Состояние превью одной заготовки. Ключевая сущность фичи: именно она несёт последствия того,
что компилятора Typst в проекте пока нет (research.md §1).

| Вариант | Когда | Что показывает карточка |
|---|---|---|
| `Rendered { .. }` | компилятор доступен и содержимое скомпилировалось | отрисованный вид документа (FR-011) |
| `SourceExcerpt { reason: DoesNotCompile, excerpt }` | компилятор доступен, содержимое не компилируется | фрагмент текста + пометка «не компилируется» (FR-012, FR-013) |
| `SourceExcerpt { reason: CompilerUnavailable, excerpt }` | компилятора в сборке нет | фрагмент текста + пометка о причине |
| `Unavailable { reason }` | файл заготовки не читается | карточка помечена недоступной; галерея не прерывается (FR-017) |
| `Pending` | превью ещё не построено | карточка выбираема, место превью занято плейсхолдером (FR-014) |

Три запрета, проверяемые тестами:

1. **`CompilerUnavailable` не схлопывается в `DoesNotCompile`.** Иначе пользователь решит, что
   сломаны все его заготовки, тогда как сломан только конвейер превью.
2. **`Unavailable` не схлопывается в `SourceExcerpt`.** Нечитаемый файл и некомпилируемое
   содержимое требуют разных действий: первый нужно чинить, второй — штатная заготовка.
3. **`Pending` не блокирует выбор.** FR-014 требует, чтобы галерея была пригодна для выбора
   до построения превью; `Pending` — это состояние карточки, а не состояние галереи.

`excerpt` — фрагмент исходного текста, извлекаемый ядром: начало содержимого, обрезанное по
границе строки, чтобы карточка не показывала обрубок посреди слова.

## InsertionPoint

Точка вставки в открытой заметке.

| Поле | Тип | Смысл |
|---|---|---|
| `offset` | `usize` | позиция курсора в тексте |
| `selection` | `Option<Range<usize>>` | выделенный фрагмент, если есть |

Если `selection` присутствует, вставка заменяет его (FR-035) — как обычная вставка из буфера
обмена. Если нет, содержимое попадает в `offset`, не затрагивая остальной текст (FR-031).

**`InsertionPoint` — единственное место фичи, зависящее от режима редактора**, и потому
единственное, что упирается в гейт принципа V (research.md §5). Для `PlainInput` смещения
берутся из DOM-элемента редактора; что они означают в `FullBackend`, где буфер принадлежит
внешнему редактору, — вопрос, вынесенный в будущую сессию `/speckit-clarify`.

## NameCheck

Результат проверки имени будущей заготовки, до записи на диск (FR-029).

| Вариант | Когда | Реакция UI |
|---|---|---|
| `Ok` | имя допустимо и свободно | сохранять |
| `Invalid { reason }` | имя недопустимо для файловой системы | объяснить причину, на диск не ходить |
| `NameTaken` | заготовка с таким именем уже есть | спросить подтверждение перезаписи (FR-028) |

Проверка выполняется в ядре и переиспользует валидацию имён 001 (research.md §7, §8).
`NameTaken` — отдельный вариант, а не разновидность `Invalid`: имя корректно, вопрос только
в подтверждении.

## Инварианты

1. Применение заготовки — созданием заметки или вставкой — не изменяет файл заготовки ни при
   каком исходе (FR-023, SC-008).
2. Изменение заготовки не изменяет ранее созданные из неё заметки: связи между ними не
   существует (FR-025, spec.md Assumptions).
3. Сохранение заметки как заготовки фиксирует содержимое на момент сохранения; последующие
   правки заметки заготовку не меняют (FR-027).
4. Содержимое вставляется дословно: подстановок нет, потому что параметризация вне скоупа
   (FR-032).
5. Невозможность построить превью — в любом из вариантов — не ограничивает применение
   заготовки (FR-013, SC-005).
6. Запись на диск не выполняется, пока `NameCheck` не вернул `Ok` либо пользователь не
   подтвердил перезапись (FR-028, FR-029).
7. Ни одна операция фичи не обращается к сети (FR-036, SC-011).
