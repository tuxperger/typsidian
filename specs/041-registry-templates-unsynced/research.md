# Research: 041

## §1. Как отличить скачиваемое

- **Decision**: по происхождению — скачанное приложение кладёт в `.typsidian/downloads/`
  (та же раскладка `<namespace>/<name>/<version>/`, там же перечень `installed.json`), ручное
  остаётся в `.typsidian/packages/`. Правила: `/.typsidian/downloads` и
  `/.typsidian/packages/preview` (пространство имён реестра скачать можно всегда, даже если
  его положили руками), плюс `/.typsidian/packages/installed.json` прежних версий.
- **Rationale**: правила исключения статичны и проверяются чистыми функциями
  (`ignore::check`/`restore_block` зовутся из редактора правил на каждое нажатие, без
  vault). Правила по списку `templates.sources` из `vault.json` потребовали бы передавать
  настройки vault в эти функции на трёх транспортах и пересматривать блок при каждой правке
  настроек. Отдельная папка даёт одно правило на любое пространство имён и любой адрес.
- **Alternatives**: исключать только `packages/preview` — шаблоны прочих пространств имён со
  своим адресом продолжали бы ездить; правила из `vault.json` — см. выше.

## §2. Поиск шаблона

- **Decision**: `installed_root(backend, spec)` — сначала `packages/…` (ручное и скачанное
  прежними версиями), затем `downloads/…`; признак установленного — манифест, как в 006.
  `install` пишет в `downloads/…`. Отпечаток и сверка (007 FR-023) читаются из того места, где
  шаблон найден.
- **Rationale**: FR-004 (ручное важнее), FR-005 (старые установки без переноса).

## §3. История

- **Decision**: уже сохранённые в истории файлы не вычищаются: правило git не снимает
  отслеживание, а переносить файлы автоматически — трогать то, что пользователь мог положить
  намеренно. Записано в Assumptions спеки.

Макет — не требуется (интерфейса нет; меняется только текст подсказки 007 о ручной папке).
