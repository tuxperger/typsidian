# Feature Specification: Скачиваемые шаблоны не синхронизируются

**Feature Branch**: `041-registry-templates-unsynced`

**Created**: 2026-10-26

**Status**: Implemented

**Priority**: P2

**Summary**: Внешние шаблоны Typst, которые можно снова скачать из интернета (реестр Typst или свой адрес), больше не попадают ни в историю, ни в Syncthing: каждое устройство скачивает их само, а синхронизируются только шаблоны, положенные пользователем.

**Input**: User description: "Не надо тащить вещи, которые можно загрузить из интернета. Внешние шаблоны Typst из реестра (и по своему адресу) не должны попадать в правила синхронизации git и Syncthing; другое устройство скачивает их само." Развивает 006 (раскладка `.typsidian/packages`), 007 (загрузка шаблонов) и 011 (правила исключения, FR-003, FR-026).

## Clarifications

### Session 2026-10-26

- Q: Что считается «можно загрузить из интернета»? → A: Шаблон, у которого есть источник в
  сети: пространство имён общего реестра Typst (всегда) и любой шаблон, скачанный приложением
  по указанному пользователем адресу. Шаблоны прочих пространств имён, положенные вручную,
  скачать неоткуда — они синхронизируются, как раньше.
- Q (закрыто по 007): Как другое устройство получит шаблон? → A: Автозагрузка включена по
  умолчанию (007 §FR-001): недостающий шаблон скачивается при первой сборке. При выключенной
  автозагрузке остаётся явное действие «скачать» (007 §FR-010).
- Q (закрыто по умолчанию): Что с шаблонами, уже сохранёнными в истории? → A: Остаются в
  прежних снимках; приложение их из истории не вычищает. Новые и обновлённые скачанные шаблоны
  в историю не попадают.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Скачанное не едет на другие устройства (Priority: P1)

Пользователь подключает в заметке шаблон из реестра Typst. Приложение скачивает его. Ни
снимок истории, ни Syncthing этот шаблон не переносят; на втором устройстве при открытии той
же заметки шаблон скачивается заново, и предпросмотр собирается.

**Why this priority**: шаблоны со шрифтами и картинками весят мегабайты и раздувают историю и
трафик Syncthing, хотя их всегда можно получить из источника.

**Independent Test**: в vault с историей скачать шаблон — список изменений для снимка его не
показывает; правила Syncthing его исключают; на втором устройстве без шаблона заметка
собирается после автозагрузки.

**Acceptance Scenarios**:

1. **Given** vault с историей, **When** приложение скачало шаблон из реестра или по своему
   адресу, **Then** в списке изменений для снимка файлов шаблона нет.
2. **Given** vault, доставляемый Syncthing, **When** правила исключения приложения применены,
   **Then** скачанные шаблоны и шаблоны пространства имён реестра исключены из доставки.
3. **Given** шаблон прочего пространства имён положен вручную, **Then** он попадает в снимок
   и доставляется, как раньше.
4. **Given** второе устройство без шаблона и включённая автозагрузка, **When** открыта
   заметка с его подключением, **Then** шаблон скачивается и документ собирается.
5. **Given** vault со старыми правилами приложения, **When** открыта панель синхронизации,
   **Then** приложение показывает, что правил не хватает, и предлагает дописать их одним
   действием (011 §FR-027).

### Edge Cases

- Шаблон, скачанный прежней версией приложения, остаётся на своём месте и продолжает
  собираться; если он из реестра — он тоже исключается.
- Один и тот же шаблон и положен вручную, и скачан — используется положенный вручную.
- Перечень скачанных шаблонов принадлежит устройству и не синхронизируется.
- Пространство имён реестра, положенное вручную, исключается: его всегда можно скачать.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Шаблоны, полученные приложением из сети, MUST храниться отдельно от шаблонов,
  положенных пользователем вручную.
- **FR-002**: Правила исключения истории и Syncthing, которые ведёт приложение, MUST
  исключать скачанные шаблоны, перечень скачанного и шаблоны пространства имён общего реестра.
- **FR-003**: Шаблоны прочих пространств имён, положенные пользователем, MUST по-прежнему
  включаться в историю и доставку.
- **FR-004**: Сборка MUST находить шаблон и среди положенных вручную, и среди скачанных;
  при наличии обоих MUST использоваться положенный вручную.
- **FR-005**: Шаблоны, скачанные прежними версиями приложения, MUST продолжать работать без
  переноса.
- **FR-006**: Сообщения, советующие положить шаблон вручную, MUST называть папку для ручных
  шаблонов.

### Key Entities

- **Скачанный шаблон** — шаблон, полученный приложением из реестра или по адресу; принадлежит
  устройству, восстановим из источника.
- **Ручной шаблон** — положенный пользователем; синхронизируется.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После скачивания шаблона число файлов в списке изменений для снимка не растёт.
- **SC-002**: На втором устройстве заметка с подключением шаблона реестра собирается без
  действий пользователя при включённой автозагрузке и доступной сети.

## Assumptions

- Автозагрузка по умолчанию включена (007); выключившему её пользователю остаётся явная
  загрузка.
- Чистка уже сохранённых в истории шаблонов — вне фичи.
- Интерфейса не добавляется.
