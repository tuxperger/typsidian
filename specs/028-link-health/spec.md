# Feature Specification: Битые ссылки и заметки-сироты

**Feature Branch**: `028-link-health`

**Created**: 2026-10-21

**Status**: Implemented

**Priority**: P2

**Summary**: Один экран показывает все ссылки на несуществующие заметки и заметки, на которые никто не ссылается, — и чинит их в один шаг: создать заметку, перенаправить ссылку на существующую, убрать ссылку.

**Input**: User description: "Битые ссылки и заметки-сироты: отдельный экран со списком и правкой в один шаг."

## Термины

- **Битая ссылка** — ссылка `[[…]]` (или ссылка на файл), чья цель в vault не находится.
- **Заметка-сирота** — заметка, на которую не ссылается ни одна другая.
- **Починка** — одно действие над битой ссылкой: создать заметку-цель, перенаправить на
  существующую, убрать ссылку (оставив текст).

## Clarifications

### Session 2026-10-22

- Q: Где живёт экран? → A: Наложение «Состояние ссылок» как расширенный поиск: две вкладки
  «Битые ссылки» и «Без входящих». Открывается из палитры команд и счётчиком в подвале
  дерева. Закрыто по существующим экранам без вопроса пользователю.
- Q: Что считается ссылкой? → A: Тот же разбор, что у индекса ссылок, связей 013 и графа
  025: записи `[[…]]` и вставки файлов (`#image`). Ссылка внутри кода или комментария
  считается так же, как в графе, — два разных определения «ссылки» разошлись бы.
- Q: Как хранится «намеренно без ссылок»? → A: Список путей в настройках vault, рядом с
  прочими значениями папки; переименование заметки переносит отметку.
- Q: Как отменяется починка? → A: Одной кнопкой «Отменить» сразу после действия — тем же
  механизмом, что отмена замены 027 (текст до и отпечаток после по каждой заметке).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Найти и починить битые ссылки (Priority: P1)

Пользователь открывает «Состояние ссылок» и видит группы по цели: «[[Методика]] — 4 ссылки
из 3 заметок». Для группы он выбирает «Перенаправить на…», выбирает «Методология» — все
четыре ссылки исправлены. Для другой цели — «Создать заметку».

**Why this priority**: После удалений и переименований (001) битые ссылки копятся, а
найти их можно только открывая каждую заметку.

**Independent Test**: Vault с тремя битыми целями — экран показывает три группы с верными
числами; перенаправление меняет ровно эти ссылки.

**Acceptance Scenarios**:

1. **Given** в vault битые ссылки, **When** пользователь открывает экран, **Then** видит
   группы по цели с числом ссылок и заметок и строками-примерами.
2. **Given** группа, **When** выбрано «Перенаправить на» и существующая заметка, **Then**
   все ссылки группы указывают на неё, подписи ссылок сохранены.
3. **Given** группа, **When** выбрано «Создать заметку», **Then** заметка создаётся там, где
   её создало бы открытие ссылки (013/018), и группа исчезает.
4. **Given** одна ссылка, **When** выбрано «Убрать ссылку», **Then** вместо ссылки остаётся
   её текст.
5. **Given** щелчок по строке-примеру, **Then** заметка открывается на месте ссылки.

---

### User Story 2 - Заметки-сироты (Priority: P2)

Во второй вкладке экрана — заметки без входящих ссылок, с датой изменения и размером;
можно открыть, переместить или удалить (через обычные операции 001 с их предупреждениями).

**Acceptance Scenarios**:

1. **Given** заметка без входящих ссылок, **Then** она в списке сирот; заметка-вход (дневная
   022, входящие) помечена и может быть скрыта фильтром.
2. **Given** пользователь отмечает заметку как «намеренно без ссылок», **Then** она больше
   не показывается среди сирот на этом vault.

---

### User Story 3 - Признак в интерфейсе (Priority: P3)

В строке состояния vault — счётчик битых ссылок; ноль не показывается.

### Edge Cases

- Цель — вложение или доска, которых нет, — тоже битая ссылка, группа помечена видом.
- Ссылка в коде или комментарии Typst считается так же, как в графе и связях (один разбор
  ссылок на всё приложение).
- Перенаправление на заметку с тем же именем в другой папке требует выбора папки.
- Открытая заметка с несохранёнными правками меняется через редактор (013).
- Большой vault: экран строится из индекса без обхода файлов.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Экран MUST показывать битые ссылки группами по цели с числом ссылок и заметок.
- **FR-002**: Для группы и для отдельной ссылки MUST быть действия: создать заметку,
  перенаправить на существующую, убрать ссылку с сохранением текста.
- **FR-003**: Починка MUST менять только ссылки группы и MUST отменяться одним действием.
- **FR-004**: Экран MUST показывать заметки-сироты с возможностью исключить заметку из списка
  (исключение хранится в настройках vault).
- **FR-005**: Списки MUST обновляться при изменениях vault без перезапуска.
- **FR-006**: Сведения MUST строиться ядром из индекса ссылок одним запросом (принципы I, IX).
- **FR-007**: Одинаково во всех оболочках; тексты — из переводов.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Экран на vault из 5 000 заметок открывается не дольше 1 с.
- **SC-002**: Перенаправление группы меняет 100% её ссылок и 0 прочих.
- **SC-003**: Счётчик битых ссылок совпадает с числом на экране в 100% случаев.

## Assumptions

- Зависит от 001 (индекс ссылок, операции над файлами), 013 (правка открытой заметки),
  018 (разрешение ссылок и создание заметок по ссылке).
