# Implementation Plan: Template Download

**Branch**: `007-template-download` | **Date**: 2026-09-07 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/007-template-download/spec.md`

## Summary

Фича 006 научила приложение **использовать** шаблоны Typst, лежащие в `.typsidian/packages/`, и
внятно отказывать, когда их нет. Эта фича закрывает вторую половину: недостающий шаблон
скачивается и устанавливается сам.

Технически это один новый модуль ядра и одна точка встраивания:

1. **`preview/packages.rs`** — получить архив, распаковать в память, проверить каждую запись,
   записать файлы, посчитать отпечаток. Всё, кроме записи, — чистые функции над байтами.
2. **`preview/resolve.rs`** — ветка `VirtualRoot::Package` перед локальным чтением: нет
   локально и автозагрузка включена → установить → прочитать.

Главный результат разведки: **платформенного шва не появляется вовсе**. `reqwest` собирается и
под native, и под wasm32 одним кодом, `.timeout()` есть в обоих бэкендах, а `flate2` + `tar`
работают в памяти без файловой системы (research §1, §2). Принцип II допускает трейт с двумя
реализациями — здесь не нужен и он.

## Technical Context

**Language/Version**: Rust 2021 (ядро), TypeScript 5 strict (UI)

**Primary Dependencies** (новые — три): `reqwest 0.12` (`default-features = false`, на native
`rustls-tls`), `flate2 1` (`rust_backend`), `tar 0.4` (`default-features = false`).
Переиспользуются: `blake3` (отпечаток, уже есть с фичи 002), `typst-syntax` (`PackageSpec`),
`VaultBackend` (запись), `VaultOverrides` (настройка).

**Storage**: `.typsidian/packages/<namespace>/<name>/<version>/` — раскладка фичи 006, эта фича
её только наполняет

**Testing**: `cargo test` + `wasm-bindgen-test`; сеть в тестах **не задействуется** — загрузчик
принимает уже полученные байты, а сетевой вызов остаётся тонкой оболочкой вокруг него

**Target Platform**: desktop (Tauri) и браузер (WASM). Исход попытки различается: браузер может
отказать по политике источника, и это названная причина, а не молчаливый провал

**Project Type**: монорепо — Rust-ядро + общий UI + три клиента

**Performance Goals**: попытка загрузки ограничена по времени (FR-014); повторное открытие
заметки с установленным шаблоном не делает ни одного запроса (SC-002)

**Constraints**: обмен односторонний — наружу уходят только имя и версия шаблона (FR-021,
принцип IX); офлайн не ломает ничего и проверяется тестами (принцип VII)

**Scale/Scope**: единицы шаблонов на папку заметок; параллельной установки одного и того же
шаблона фича не вводит

## Constitution Check

*GATE: пройден до Phase 0, перепроверен после Phase 1.*

| Принцип | Как соблюдается | Статус |
|---------|-----------------|--------|
| **I. Логика в ядре** | Разбор архива, проверка путей, отпечаток, решение «идти ли в сеть» — всё в `packages/core`. UI показывает диагностики и переключает настройку | ✅ |
| **II. Паритет таргетов** (NON-NEGOTIABLE) | Проверено зондами до планирования (research §1): `reqwest`, `flate2`, `tar` собираются под оба таргета. Платформенного шва не появляется — ни трейта, ни `cfg` в логике | ✅ |
| **III. Спека — только поведение** | Адрес реестра, формат архива и названия крейтов есть здесь и в research, в `spec.md` их нет (проверено грепом) | ✅ |
| **IV. TS strict, без `any`** | Новые типы границы порождаются `tsify-next`; ручных дубликатов нет | ✅ |
| **V. Внешние процессы** | Не затрагивается | ✅ |
| **VI. Local-first** | Загрузка **опциональна и выключаема** (FR-009). Без сети приложение полностью работоспособно, а шаблон можно положить руками. Своей инфраструктуры не заводится: прокси-сервер отвергнут на кларификации именно по этому принципу | ✅ |
| **VII. Деградация в офлайне** | **Основной принцип этой фичи.** FR-012…FR-014, SC-005, SC-006, SC-009 написаны проверяемыми; офлайн покрыт тестами, а не декларацией | ✅ |
| **VIII. Внешние движки** | Не затрагивается | ✅ |
| **IX. Локальность содержимого** | Обмен односторонний. Наружу уходит только имя и версия шаблона — то, что пользователь сам написал в тексте подключения. Закреплено FR-021 и проверяется тестом на состав запроса | ✅ |
| **X. Массовые операции** | Массовых операций фича не вводит: установка идёт по одному шаблону, по мере того как их запрашивает компилятор | ✅ |

**Нарушений нет.** Раздел Complexity Tracking пуст и удалён.

Отдельно: фича **дополняет**, а не пересматривает 006. Её FR-039 («система MUST NOT обращаться
в сеть за шаблонами **в рамках этой фичи**») был ограничением скоупа 006, а не запретом
навсегда — формулировка выбиралась именно так. Пересмотра не требуется.

## Известные ограничения, принятые сознательно

| Ограничение | Причина |
|-------------|---------|
| Архив скачивается целиком в память перед разбором | Иначе нельзя выполнить FR-019 и FR-020: проверить **все** записи до создания **первого** файла. Потоковая распаковка писала бы раньше, чем узнала бы об архиве всё |
| Подпись издателя не проверяется | Отпечаток фиксирует содержимое после установки, происхождение не подтверждает. Записано в Out of Scope спеки, чтобы гарантия не читалась шире |
| Устаревание установленного не отслеживается | Проверка «вышла ли новая версия» — обращение в сеть без запроса пользователя |
| Параллельный запрос одной версии дважды может привести к двум загрузкам | Компилятор запрашивает файлы последовательно; блокировка на этом объёме — усложнение без наблюдаемой пользы |
| Исход попытки на web зависит от политики источника | Возможность объявлена одинаково (FR-016), различается результат. Прокси-сервер отвергнут по принципу VI |
