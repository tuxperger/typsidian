**Status**: Draft

**Priority**: P1

**Summary**: Любой PDF в vault — даже присланный синхронизацией и специально испорченный — разбирается за ограниченное время и память и не роняет и не замораживает приложение или сервер.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Враждебный PDF не ломает приложение (Priority: P1)

В выбранной для импорта папке лежит PDF размером в несколько килобайт, который при разборе
разворачивается в гигабайты или порождает миллиарды операций. Пользователь запускает оценку
импорта — приложение показывает этот файл пропущенным («не удалось прочитать»), остальное
работает.

**Why this priority**: сейчас такой файл роняет приложение рабочего стола и процесс сервера
со всеми пользователями ещё до подтверждения отправки (055 H1) или навсегда занимает vault
(055 H2).

**Independent Test**: набор файлов-«бомб» (сжатие с огромным коэффициентом, вложенные формы с
ветвлением, огромный поток содержимого, циклы ссылок, порченые данные) — оценка завершается
за ограниченное время, каждый файл пропущен с причиной, память процесса не превышает предел.

**Acceptance Scenarios**:

1. **Given** PDF со сжатым потоком, разворачивающимся больше предела, **When** идёт оценка
   импорта, **Then** файл пропущен с причиной, приложение не падает.
2. **Given** PDF с экспоненциально вложенными формами, **When** идёт оценка, **Then** разбор
   прекращается по бюджету, файл пропущен, остальные команды vault не ждали.
3. **Given** PDF, вызывающий ошибку внутри разборщика, **When** идёт оценка папки, **Then**
   пропущен только этот файл, оценка остальных проходит.
4. **Given** серверный режим, **When** один пользователь оценивает папку с «бомбами»,
   **Then** другие пользователи не замечают замедления.

### Edge Cases

- Тот же разборщик используется для PDF-картинок в заметках (через Typst): защита не должна
  ломать их отрисовку.
- PDF, честно большой (книга на 300 страниц), читается в пределах, а не отбрасывается.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Разбор одного PDF MUST иметь предел памяти распакованных данных и предел
  работы (операций или времени); превышение MUST давать пропуск файла с причиной.
- **FR-002**: Разбор MUST NOT держать блокировку vault и MUST NOT занимать общий ресурс
  сервера дольше предела.
- **FR-003**: Ошибка внутри разборщика MUST давать пропуск файла, а не сбой команды или
  процесса.
- **FR-004**: Защита MUST действовать на всех таргетах: рабочий стол, Android, web, сервер.
- **FR-005**: Честные PDF в пределах 055 (до 10 МБ, 300 страниц) MUST читаться как раньше.

### Key Entities

- **Набор враждебных PDF**: фикстуры для проверки каждого класса «бомб».

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% файлов набора «бомб» пропускаются с причиной; ни одного падения процесса.
- **SC-002**: Оценка папки с «бомбами» укладывается в 10 секунд.
- **SC-003**: Память процесса при разборе любого файла набора не превышает 512 МБ сверх
  обычной.

## Assumptions

- Зависит от 055 (разбор PDF), касается 056 (чтение PDF в исследовании).
- До решения импорт и исследование работают с текущим разборщиком: риск принят пользователем
  2026-11-03 и записан в `specs/055-ai-notes-to-graph/research.md` §7.
- Ревью 056 (L6): изучение PDF в исследовании разбирает файл под блокировкой vault и дважды
  (оценка и старт), а предложить разбор может модель (`study_pdf`, при разрешении) — решение
  069 должно покрыть и этот путь (`specs/056-ai-background-research/research.md` §9).
