# Feature Specification: Демо-режим сервера

**Feature Branch**: `039-server-demo`

**Created**: 2026-10-25

**Status**: Implemented

**Priority**: P3

**Summary**: Сервер, запущенный с параметром демо, становится публичной площадкой: любой посетитель нажимает «Попробовать без регистрации» и получает на час собственный vault с примерами, который затем удаляется целиком; входа в профиль на демо-сервере нет.

**Input**: User description: "Демо-режим сервера (публичная площадка): на сервере, где администратор включил демо, экран входа предлагает «Попробовать без регистрации». Посетитель получает временный гостевой аккаунт с одним vault — копией демо-vault с примерами возможностей (ссылки и обратные ссылки, свойства и выборки, задачи, встраивание, доска, презентация, библиография). Гостевой аккаунт живёт не больше 1 часа с создания (срок настраивается), затем удаляется целиком вместе с данными. Гостю нельзя создавать другие vault, подключать удалённый репозиторий (история версий и шаблоны из реестра Typst доступны), есть квота на размер vault и предел создания гостевых аккаунтов с одного IP. Обычные аккаунты того же сервера работают без изменений. Зависит от 037 и 038; конституция XI."

## Clarifications

### Session 2026-10-25

- Q: Что такое демо-режим? → A: Публичная площадка: анонимный посетитель входит кнопкой и
  работает в своём временном vault. Быстрый локальный запуск одной командой — вне фичи.
- Q: Что в демо-vault? → A: Набор заметок, показывающих возможности: ссылки и обратные
  ссылки, свойства и выборки, задачи, встраивание, доска, презентация, библиография.
- Q: Сеть для гостей? → A: Урезана: история версий и шаблоны из реестра Typst — да,
  подключение удалённого репозитория — нет. Обычный сервер (без демо) — без изменений.
- Q: Как долго живёт гость? → A: Не больше 1 часа с создания (настройка сервера, по
  умолчанию 60 минут), независимо от активности; затем аккаунт, его vault и все данные
  удаляются. Интерфейс показывает, сколько осталось.
- Q: Какие пределы? → A: Квота на размер vault, предел создания гостевых аккаунтов с одного
  адреса, один vault на гостя (создать, переименовать, удалить vault гость не может).
  После ревью безопасности добавлен и общий предел живых гостей (`max_guests`): предел
  на адрес не держит IPv6 и общие адреса прокси.
- Q: Как включается демо и сосуществует ли оно с обычными аккаунтами? → A: Параметром
  запуска сервера (`serve --demo`). Демо-сервер — только для гостей: входа паролем и через
  провайдера нет, раздела «Аккаунт» и списка своих vault нет. Обычный сервер запускается
  без параметра и демо не предлагает.
- Q: Может ли гость закончить демо досрочно? → A: Нет, отдельного действия нет; vault живёт
  до конца срока.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Попробовать без регистрации (Priority: P1)

Посетитель открывает демо-сервер, нажимает «Попробовать без регистрации» и сразу попадает в
рабочую область своего vault с примерами: открывает заметки, правит, смотрит предпросмотр,
граф, задачи, доску и показ слайдов.

**Independent Test**: на сервере с включённым демо нажать кнопку — открыт vault с примерами;
правка сохраняется; второй посетитель (другой браузер) получает свой чистый vault и правок
первого не видит.

**Acceptance Scenarios**:

1. **Given** сервер запущен с параметром демо, **When** посетитель нажимает кнопку, **Then**
   за несколько секунд открывается его vault — копия демо-vault, без ввода логина и пароля.
2. **Given** два посетителя, **Then** их vault независимы.
3. **Given** сервер запущен без параметра демо, **Then** кнопки нет и вход гостем невозможен
   ни через интерфейс, ни прямым запросом.
4. **Given** демо-сервер, **Then** формы входа паролем, кнопки провайдера и раздела
   «Аккаунт» нет, а запросы входа паролем и через провайдера отклоняются.

---

### User Story 2 - Гость исчезает через час (Priority: P1)

Гость видит в рабочей области, сколько времени осталось. По истечении срока сессия
заканчивается, аккаунт и все данные удаляются; посетитель может начать заново.

**Acceptance Scenarios**:

1. **Given** гость создан, **Then** в рабочей области видно оставшееся время.
2. **Given** срок истёк, **Then** запросы гостя отклоняются, экран предлагает начать
   заново, а на сервере не остаётся его vault, секретов и сессий.
3. **Given** сервер был остановлен, когда срок истёк, **Then** после запуска просроченные
   гости удаляются.

---

### User Story 3 - Площадка не становится чужим ресурсом (Priority: P2)

Администратор открывает демо в интернет и не боится, что гости заполнят диск, будут
использовать сервер как посредника к чужим репозиториям или заведут тысячи аккаунтов.

**Acceptance Scenarios**:

1. **Given** гость, **When** он пытается подключить удалённый репозиторий, создать,
   переименовать или удалить vault, **Then** отказ с понятной причиной.
2. **Given** vault гостя достиг квоты, **When** запись увеличила бы его, **Then** отказ
   «превышен объём демо», прежние данные целы.
3. **Given** с одного адреса создано предельное число гостей за час, **Then** следующий
   получает отказ «попробуйте позже».

### Edge Cases

- Гость открыл несколько вкладок — это один гость; срок общий.
- Гость закрыл браузер и вернулся до истечения срока — попадает в свой vault (сессия
  жива), после — начинает заново.
- Квота и экспорт: файлы экспорта (PDF, HTML, презентация), история версий (`.git`) и
  корзина — тоже в квоте; удаление у гостя окончательное.
- За 5 минут до конца срока интерфейс предупреждает: правки после срока не сохранятся,
  экспорт можно скачать до него.
- Аккаунты, заведённые администратором, на демо-сервере не работают; демо-сервер держит
  свою папку данных, отдельную от обычного сервера.
- Демо-vault, заданный администратором, отсутствует или повреждён — демо не включается,
  сервер сообщает причину при запуске.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Демо MUST включаться параметром запуска сервера; без него сервер работает как
  обычный (037) и гостей не создаёт.
- **FR-002**: Экран входа демо-сервера MUST предлагать только «Попробовать без
  регистрации», создающее гостевой аккаунт с одним vault — копией демо-vault; вход паролем,
  через провайдера и раздел «Аккаунт» на демо-сервере MUST отсутствовать.
- **FR-003**: Гостевой аккаунт MUST удаляться целиком (vault, секреты, сессии, данные
  синхронизации) не позже срока жизни после создания; срок настраивается, по умолчанию 60
  минут; удаление MUST происходить и после перезапуска сервера.
- **FR-004**: Гостю MUST NOT быть доступны: создание, переименование и удаление vault,
  подключение удалённого репозитория, сведения и действия профиля (пароль, сессии, аккаунт).
- **FR-005**: Размер vault гостя MUST быть ограничен квотой (настройка, по умолчанию 50 МБ);
  запись сверх квоты отклоняется.
- **FR-006**: Создание гостей с одного адреса MUST быть ограничено (настройка, по умолчанию 5
  в час).
- **FR-007**: Интерфейс гостя MUST показывать оставшееся время и по истечении предлагать
  начать заново.
- **FR-008**: Сервер без параметра демо MUST работать без изменений; гости MUST NOT видеть
  и затрагивать данные других гостей (изоляция 037).
- **FR-009**: Поставка MUST включать демо-vault с примерами возможностей; администратор
  может указать свой.

### Key Entities

- **Гостевой аккаунт** — временный аккаунт без пароля: время создания, срок, адрес создания.
- **Демо-vault** — папка-образец, копия которой выдаётся каждому гостю.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: От нажатия кнопки до открытой рабочей области с примерами — не дольше 5 секунд.
- **SC-002**: Через срок жизни плюс 2 минуты на сервере 0 файлов и записей гостя.
- **SC-003**: 100% попыток гостя выйти за пределы (удалённый репозиторий, другие vault,
  квота, предел по адресу) отклоняются.

## Assumptions

- Зависит от 037 (серверный режим) и 038 (синхронизация на сервере).
- Демо — свойство запуска сервера целиком: демо-сервер обслуживает только гостей.
- Защита от автоматизированного создания (капча) — вне фичи; её заменяет предел по адресу.
- Конституция XI: `security-review-agent` перед «готово».
