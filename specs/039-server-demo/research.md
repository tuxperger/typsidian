# Research: Демо-режим сервера

## §1 Режим запуска

**Решение**: флаг `serve --demo` (и `TYPSIDIAN_DEMO=1`), настройки — таблица `[demo]` файла
(`ttl_minutes = 60`, `quota_mb = 50`, `per_ip_per_hour = 5`, `vault = "…"`). Без флага таблица
ничего не включает. Демо-сервер ведёт свою папку данных, как любой другой.

**Почему**: «демо» — решение о запуске конкретного процесса; настройка в файле легко
осталась бы включённой на рабочем сервере.

## §2 Гость

Гость — строка `accounts` с `expires_at` (секунды Unix) и `created_ip` (blake3 адреса):
логин `guest-<12 hex>`, без пароля. Сессия — обычная сессия 037 (cookie, CSRF); проверка
сессии отказывает просроченному гостю `401 {"kind":"DemoExpired"}` ещё до уборки. Предел по
адресу — `COUNT(*)` гостей с тем же хешем за последний час: переживает перезапуск.

## §3 Что закрыто на демо-сервере

`/api/login`, `/api/oidc/*` → `404`; `/api/password`, `/api/sessions*`, `/api/logout-all`,
`POST/PATCH/DELETE /api/vaults…` → `403`. Белый список команд прежний; удалённый репозиторий
закрыт возможностью ядра `ShellCapabilities.remote = false` (ядро отклоняет подключение и обмен
`RemoteUnavailable`, UI выключает кнопку), сервер дополнительно не принимает
`sync_connect_remote` у гостя.

## §4 Квота

Перед командой, которая может записать (список `GROWING` в `demo.rs`: запись, создание,
вложения, доски, снимки, экспорт, шаблоны, история), сервер считает размер папки vault (вся
папка, с `.git` и `.typsidian`) плюс размер тела запроса; больше квоты — `400
{"kind":"DemoQuota","quota_mb":50}`. Чтение, поиск, удаление и перенос не ограничены — гость
освобождает место. Одна операция может выйти за квоту на свой собственный выход (экспорт
большого PDF); следующая будет отклонена. Демо-vault маленький, обход папки дешёвый.

**Отвергнуто**: квота файловой системы — нужна настройка ОС, не переносимо.

## §5 Уборка

`spawn_housekeeping` раз в минуту и `serve` при запуске: просроченные гости → закрыть их
vault (с сессией синхронизации), удалить `users/<id>`, `sync/<id>`, `trash/notes/<id>`,
строку аккаунта (сессии и id синхронизации — каскадом). SC-002: не позже срока + 2 минуты.

## §6 Демо-vault

Встроен в бинарь таблицей `include_bytes!` из `apps/server/demo-vault/`; `[demo] vault` —
своя папка администратора (копируется целиком, без `.git`). Пустая или отсутствующая папка —
сервер не запускается с причиной.

## §7 Интерфейс

`/api/info` отдаёт `demo: {ttlMinutes, quotaMb}`, `/api/me` — `expiresAt`, `GET
/api/demo/usage` — `{used, quota}` байтами. Пилюля статуса — новым слотом `status` шапки
`Workspace`; объём показан в ней же, а не в подвале дерева, как на макете D2: подвал
принадлежит дереву, а сведение о демо — серверу (решение, расхождение с макетом).

## §8 Ссылки из досок (найдено на демо-vault)

**Решение**: `graph::links_in` возвращает ссылки только для заметок `.typ`. Доска — JSON
Excalidraw, и массив точек стрелки `"points":[[0,0],[120,0]]` разбирался как ссылка
`[[0,0],[120,0]]`: каждая стрелка или линия на доске давала ложную «битую ссылку» в
«Состоянии ссылок» (028) у всех пользователей. Свойства и вставки досок уже читались только у
заметок; ссылки теперь так же. Тест — `graph_cases::board_json_has_no_links` на обоих путях.

## §9 После ревью безопасности

Находки ревью (К1, В1–В4, С1–С5, Н1–Н6) и что сделано:

- **Квота (К1, С2, С3)**: в объём входят vault, корзина удалённых заметок и данные
  синхронизации гостя, плюс 4 КиБ на каждую запись папки (пустые файлы не бесплатны). Удаление
  у гостя окончательное — корзина чистится сразу, и освободить место можно. Проверка идёт под
  замком записи гостя (`OpenVault::demo_write`) до конца команды: записи по одной. Список
  команд сверх квоты — разрешающий (`WITHIN_QUOTA` в `demo.rs`), а не запрещающий, как было
  записано в §4: пропущенная в нём команда даёт неудобство, а не дыру.
- **Предел по адресу (В1, С5, Н2)**: ключ — IPv4 целиком или сеть IPv6 /64 (IPv4 в IPv6 — как
  IPv4), с секретом из `<данные>/demo-secret`; не адрес — один общий ключ. Старты лежат в
  `demo_starts` отдельно от гостей и чистятся через час; адрес гостя не хранится ни в
  аккаунте, ни в сессии. Сервер за прокси должен получать `X-Forwarded-For` от своего прокси
  (`trust_proxy`), иначе все посетители делят один адрес.
- **Общий предел (В2)**: `[demo] max_guests` (200, не больше 240 — ниже предела открытых vault
  256); сверх — `429 {"kind":"DemoFull"}`.
- **Память и CPU (В3, В4)**: тело запроса на демо-сервере не больше квоты; сессий подсветки на
  vault не больше 32 (старейшая закрывается); живых потоков сборки Typst на процесс не больше
  8, включая доработку после предела времени — сверх предела сборка отвечает как долгая.
- **Уборка (С1, Н3, Н4)**: просроченные гости убираются при запуске и раз в минуту в любом
  режиме; на демо-сервере — и папки без хозяина. Поток событий заканчивается со сроком
  гостя; на демо-сервере сессии обычных аккаунтов не работают.
- **Прочее (С4, Н1, Н5)**: свои адреса шаблонов на демо-сервере закрыты всегда; старт гостя —
  только JSON (CSRF входа); образец администратора проверяется на размер (меньше квоты) и
  глубину, копирование — в пуле блокирующих потоков.
- **§3 уточнение**: второго рубежа против `sync_connect_remote` на сервере нет — подключение
  закрывает возможность ядра `remote = false`, и проверка стоит и при обмене (`remote_spec`).

Остаётся: установка пакетов шаблонов из реестра Typst гостем не ограничена числом (кэш
пакетов — сервера, в квоту гостя не входит); сборка может идти до конца после предела
времени, но таких потоков не больше 8.
