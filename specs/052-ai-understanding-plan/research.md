# Research: Замер понимания и план урока

## §1. Стадии урока

**Decision**: шапка урока 051 получает поле `start` (`Probe` / `Teach`), события — `Phase`
(`Probe` → `Teach`). Пока стадия `Probe`, ход собирается с инструкциями замера и
инструментами замера; после `probe_done` — с инструкциями учителя 051. «Пропустить замер» —
событие `Phase { Teach, skipped: true }`.

**Rationale**: стадия — часть записи урока (clarify), переживает перезапуск и синхронизацию
(FR-007). Отдельный файл для замера — второй источник истины.

## §2. Инструменты замера

**Decision**:

- `probe_question { part, question, choices? }` — вопрос о части цели; как `ask_question`
  051, но с названием части; объяснять нечего — у замера нет инструмента-объяснения, а
  инструкции запрещают объяснять (FR-002).
- `probe_done { parts: [{ name, state: Known|Partial|Unknown, note }], start }` — итог;
  дописывается событием `ProbeResult`, стадия → `Teach`.

«Не знаю» — ответ пользователя с флагом `dont_know` (051 `User`), учитель получает его как
сведение (US1, сценарий 4).

## §3. План — инструмент учителя

**Decision**: `plan_set { steps: [{ id, title, after: [id], known }], goal, current, reason? }`
заменяет план целиком; ядро проверяет: id уникальны, ссылки существуют, циклов нет, шагов не
больше 40, `goal` и `current` — существующие шаги. Ошибка возвращается модели результатом
инструмента с причиной, урок не прерывается (FR-004, Edge Case). Больше 40 шагов — причина
«цель слишком широкая»: инструкции велят предложить сузить цель (Edge Case).

`plan_progress { current, done: [id] }` — отметки без смены структуры.

Каждый принятый `plan_set` — событие `Plan { version, steps, goal, current, reason }`;
`PlanProgress` — событие отметок. Прежние версии — прежние события (FR-006).

**Alternatives**: разбор Mermaid, как в LearnHarness, — лишний формат; структура JSON
проверяется проще.

## §4. Раскладка карты

**Decision**: раскладка слоями в ядре (`ai/lesson/plan.rs`): слой — длина самого длинного
пути от шагов без зависимостей, порядок в слое — по порядку объявления с одним проходом
уменьшения пересечений. Ядро отдаёт координаты в единицах сетки; UI рисует SVG.

**Rationale**: принцип I; план — до 40 шагов, силовая раскладка графа 025 избыточна.

## §5. Место урока для пройденного шага

**Decision**: при смене `current` ядро запоминает номер события, с которого шаг стал текущим;
`LessonView.plan.steps[].anchor` — этот номер. Нажатие в UI прокручивает ленту к событию.

## §6. Число вопросов замера

**Decision**: ориентир «до 10 вопросов» — в инструкциях замера; ядро не обрывает замер, но
после 15 вопросов замера инструкции следующего хода требуют завершить (`probe_done`).
