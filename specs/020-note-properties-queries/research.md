# Research: Свойства заметок и выборки

**Feature**: 020-note-properties-queries | **Date**: 2026-10-15

## §1. Запись свойств

**Decision**: первым элементом заметки (после пробелов и комментариев) — вызов
`#metadata((…)) <properties>`; ключи — идентификаторы Typst (кириллица допустима) или строки,
теги — ключ `tags`. Виды значений: строка → текст, целое/дробное → число,
`datetime(year:, month:, day:)` → дата, `true`/`false` → флажок, массив строк → список.

**Rationale**: `metadata` ничего не выводит в документ (US1 сценарий 2), собирается любым
`typst compile` (FR-003, SC-003), а `typst query <file> "<properties>"` даёт свойства и вне
приложения. Метка отделяет запись от прочих `metadata` (`<pdfpc>` 019).

**Alternatives considered**: YAML в комментарии — не видно Typst-средствам и требует второго
синтаксиса; `#let props = …` — переменная засоряет пространство имён заметки.

## §2. Разбор

**Decision**: `typst::syntax::parse`, первый `FuncCall` `metadata` с меткой `properties` в
разметке верхнего уровня. Запись **однозначна**, если аргумент — словарь из литералов §1 без
повторов ключей; иначе — значения-литералы читаются, прочие — «не определено», правка
формой выключена (FR-004, макет B2). Вторая запись `<properties>` в заметке — тоже
неоднозначность.

## §3. Правка

**Decision**: правка строит `EditOutcome` 008 — замену ровно записи `<properties>`, остальной
текст не меняется (FR-002). Порядок ключей сохраняется, новые — в конец, удаление
последнего свойства удаляет запись целиком. Записи нет — создаётся в начале заметки с
переводом строки после.

## §4. Индекс свойств

**Decision**: при каждом обновлении записи индекса (там же, где пересчитываются ссылки 013)
заметка разбирается §2, результат кладётся в `IndexCache`: на native — таблица
`properties(path, key, kind, value_text, value_num)` в `cache.sqlite`, в web — поле в
`MemoryCache` и IndexedDB. Встроенные сведения (имя, папка, даты) берутся из `Note`.

**Rationale**: SC-001 недостижим чтением файлов на каждый запрос (поиск 001 так и делает и
нужен только для текста).

## §5. Пересчёт

**Decision**: смена версии формата свойств или повреждение кэша → пакетный пересчёт по
образцу переиндексации 001: прогресс, отмена, запись по заметке.

## §6. Отбор

**Decision**: `Selection { conditions, sort, columns, limit }`, условия: `tag has`, `prop =/≠/</>/≤/≥`,
`prop exists`, `folder in`, `modified/created within N days | between`. Все условия — «и»
(US2 сценарий 2). Сравнение только внутри одного вида; несравнимое не проходит (Edge Cases).
Сортировка: несравнимые и пустые — в конце. «Создана» известна не везде: web File API
отдаёт только время изменения — там встроенное «создана» пусто, условие по нему не проходит,
а пункт условия в форме подписан «недоступно в браузере». Те же условия — фишки поиска (`SearchQuery.properties`).

## §7. Блок выборки

**Decision**: запись в заметке —
`#import "/.typsidian/lib/select.typ": select` (одна строка на заметку, добавляется формой)
и `#select(where: (…), sort: "-срок", columns: (…), limit: 20, view: "table")`.
`select` ищет результат в `sys.inputs.at("typsidian-select", default: none)` по ключу —
каноническому тексту аргументов; есть → таблица/список со ссылками, пусто → пояснение
(US3 сценарий 3); нет входа → замещающий текст с условиями (Clarifications).

## §8. Входы сборки

**Decision**: перед сборкой заметки ядро находит блоки `#select` (§7), считает выборки по
индексу и кладёт JSON `{ключ: {rows, columns}}` в `sys.inputs["typsidian-select"]` через
`Library::builder().with_inputs`. Экспорт 009 — тот же путь, поэтому PDF совпадает с
предпросмотром (US3 сценарий 4). Изменение индекса свойств помечает сборку заметок с
блоками устаревшей так же, как изменение зависимости 005 (SC-002).

## §9. Форма

**Decision**: схема элемента 008 для `select` с видами параметров «условия», «порядок»,
«столбцы» — новые виды полей формы; пункт «Выборка» в меню вставки 008; правка — `Mod+Shift+E`
на блоке.

## §10. Библиотека

**Decision**: текст `select.typ` — константа ядра с номером версии в первой строке
комментария. Приложение пишет файл, если его нет или версия старше; иначе не трогает.
Пользовательская правка файла (версия совпадает, текст другой) — файл не перезаписывается,
в колонке свойств предупреждение.

## §8 (уточнение при реализации). Откуда сборка берёт входы

**Decision**: входы считает само ядро внутри общего цикла сборки
(`preview::compile::compile_collecting_failures`), у которого уже есть `&B: VaultBackend`
и текст заметки: `properties::compile_inputs(backend, text)` находит блоки `#select`,
берёт сведения индекса (`VaultBackend::indexed_notes`) и возвращает одну JSON-строку. Строка
едет полем `CompileJob.inputs` — в воркере web она часть `JobHeader` (serde, `inputs`
необязателен) — и попадает в `PreviewWorld::with_inputs` →
`Library::builder().with_inputs({"typsidian-select": <JSON>})`. Предпросмотр, проверка
шаблонов и экспорт 009 идут через этот же цикл, поэтому PDF получает те же строки, что и
предпросмотр (тест `export_builds_with_the_same_inputs`).

**Rationale**: UI не обязан ничего передавать — запрос сборки (`previewCompile`,
`exportPdf`) не меняется ни на web, ни на desktop, ни в воркере. Логика отбора остаётся в ядре
(принцип I), второго пути «вычислить снаружи и передать» нет. Заметка без блоков индекс не
трогает (предфильтр по подстроке `select`).

**Устаревание сборки (SC-002)**: сам индекс события «свойства изменились» не публикует.
Вместо этого есть дешёвый отпечаток: `vaultSelectDigest(text)` / `vault_select_digest` —
blake3 от строки входов, `undefined`/`null`, если блоков нет. UI вызывает его для открытой
заметки с блоками при любом `NoteCreated/NoteUpdated/NoteDeleted/NoteRenamed` и после своих
записей и пересобирает, только если отпечаток сменился.

**Ограничение**: блоки ищутся в тексте самой собираемой заметки; `#select` внутри
`#include`/импортированного файла входа не получит и покажет замещающий текст.

## §11. Свойства в индексе

**Decision**: свойства лежат в `IndexCache` (`set_properties`, `all_properties`,
`properties_current`, `mark_properties_current`); пишутся в той же точке, что и ссылки
(`record_derived` = `set_links` + `set_properties`; `Derived::of(path, text)` выводит оба за
один проход). SQLite: таблица `properties(path, ord, key, kind, value_text, value_num)` +
`cache_meta(name, value)` с версией формата (`PROPERTIES_FORMAT_VERSION`) в
`migrations/0002_properties.sql`; поверх таблицы SqliteCache держит копию в памяти,
которой отвечает отбор (10 000 заметок: ~20 мс весь путь, ~2 мс сам отбор —
`benches/properties_scale.rs`). Кэш без отметки текущей версии (в том числе кэш до фичи 020)
**не годится для быстрого пути открытия**: `NativeBackend::open` делает холодный обход,
который заново наполняет ссылки и свойства. Backend отдаёт сведения вопросом
`VaultBackend::indexed_notes`; его умолчание читает все заметки и разбирает их (так работают
двойники в тестах).

**Web**: кэш индекса в web — только `MemoryCache` (IndexedDB используется для хранения
хендлов папок и секретов, не для индекса), поэтому свойства пересчитываются при открытии
вместе со ссылками, как и они. Отдельной персистентности свойств в IndexedDB не заводилось —
она не нужна, пока нет персистентного индекса.

**Даты**: «изменена» — время изменения файла: native из отпечатка заметки, web из последнего
опроса (`lastModified` в `poll_snapshot`; в отпечатке web оно намеренно 0). «Создана» не
хранится нигде (в `FileStamp` её нет), на всех таргетах: условие по ней не проходит, ячейка
пуста; без изменения отпечатка и схемы кэша это единственный паритетный вариант.

## §12. Язык аргументов блока и ключ

**Decision**: аргументы `#select` — литералы, ядро читает их без вычисления Typst.
`where` — массив словарей-условий: `(tag: "…")`, `(folder: "…")`, `(key:, exists: true)`,
`(key:, op: "="|"!="|"<"|">"|"<="|">=", value: …)` либо `(key:, op:, date: "ГГГГ-ММ-ДД")`,
`(modified: 30)` / `(modified: ("ГГГГ-ММ-ДД", "ГГГГ-ММ-ДД"))` (так же `created`); `sort` —
`"ключ"` или `"-ключ"`; `columns` — массив имён; `limit` — число; `view` — `"table"`/`"list"`.
Даты — строками, потому что ключ строится через `json.encode`, а Typst-даты в JSON не кодируются.

Ключ блока — JSON всех пяти аргументов с умолчаниями и ключами словарей по алфавиту.
`select.typ` строит его `json.encode(_canon(args), pretty: false)`, ядро — `serde_json` (карта
с сортировкой ключей; `preserve_order` в проекте включать нельзя). Порядок аргументов в
вызове и ключей в словарях на ключ не влияет (тест).

## §13. Правка записи и неоднозначность

**Decision**: правка — точечные замены (значение на месте, новое — в конец словаря, удаляемое —
вместе с запятой, многострочный вид сохраняется), а не пересборка всей записи: комментарии и
форматирование чужих свойств не теряются. Повтор ключа сам парсер Typst помечает ошибкой на
втором ключе — ядро называет его `DuplicateKey`, а не `Malformed`. Отказ правки
неоднозначной записи — новый вариант `PlanEditError::Properties { problem }`
(тип `EditOutcome` 008 общий).

## §14. Пересчёт и отмена

**Decision**: пересчёт идёт шагами по `REINDEX_BATCH` (50) заметок: `reindex_step(from, count)`
→ `{ done, total, finished }`, запись по заметке, отметка «актуально» ставится только после
последнего шага; `reindex_properties(backend, control)` — цикл поверх шагов с прогрессом и
отменой между шагами (`MoveControl` 023). Web: `vaultReindexProperties(onProgress, cancel)`.
Desktop: команда `vault_reindex_properties` сама ведёт цикл и **отпускает замок vault между
шагами**, ход — событие `properties://reindex-progress`, отмена — команда
`vault_cancel_reindex_properties` (флаг в состоянии оболочки): иначе единственный `Mutex`
vault держал бы все остальные команды на время пересчёта.

## §15. Форма блока в параметрах 008

**Decision**: `select` — не встроенная функция Typst, поэтому схему `call:select` задаёт ядро
(`properties::select::form_params`): `where`, `sort`, `columns`, `limit`, `view`. Три новых вида
`ParamKind` — `conditions`, `order`, `columns` (теги `type` в kebab-case). Значение поля формы
этих видов — JSON (`FieldValue.plain` и `ParamValue.plain`): список `Condition`, `null` или
`SortKey`, список имён. Запись Typst строит и читает ядро; параметры на умолчании в текст не
пишутся. Вычисляемые аргументы остаются полем «как есть» (`expression: true`).

## §16. Ячейки таблицы

**Decision**: ядро готовит ячейки как готовые строки (`{s, l}`): даты `ДД.ММ.ГГГГ`, флажок `✓`/пусто,
список через запятую, нет значения — `—`, число без `.0`; название — ссылка `l` в форме
vault `[[/путь/без/расширения]]`, которую `select.typ` кладёт в `link(...)`. Форматирование —
в ядре, потому что одинаковый вид в предпросмотре и PDF обязан задаваться одним местом.
