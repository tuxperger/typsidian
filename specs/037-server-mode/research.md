# Research: Серверный режим web

## 1. Одна реализация команд для Tauri и сервера

**Decision**: новый крейт `packages/host` без зависимости от Tauri: состояния открытого vault
(`Vault`, `Preview`, `Sources`, `Speller`, `HighlightSessions`, `TemplatePreviews`, …),
собранные в `Host`, помощники и тела команд ядра — `host::commands::<имя>(аргументы…, &Vault, …)`:
команда получает ровно те состояния, что брала через `State<'_, X>`, а `dispatch` берёт их из `Host`.
Перенос из `packages/shell/src/lib.rs` — один раз, скриптом (`scripts/dev/extract-host.mjs`):
каждая `#[tauri::command]`, которой нужны только аргументы и эти состояния, переезжает в
`host`, а в оболочке остаётся тонкая обёртка с прежним именем и аргументами — клиенты
desktop/Android не меняются. Команды с `AppHandle`, окнами и устройством (выбор папки,
настройки устройства, известные vault) остаются в оболочке.
Для сервера `scripts/dev/gen-host-dispatch.mjs` строит из `host::commands` таблицу
`dispatch(&Host, имя, JSON) -> JSON` (аргументы в camelCase, как их шлёт клиент), гейт
проверяет, что таблица свежая.
**Rationale**: конституция «Архитектурные ограничения → Сервер»: одна реализация команд.
**Alternatives**: mock-рантайм `tauri::test` на сервере — тестовая часть Tauri в
производстве и GTK в зависимостях сервера; переписать команды для HTTP — две реализации.

## 2. Сервер

**Decision**: `apps/server` — Rust, `axum` 0.8 + `tokio`, бинарь `typsidian-server`:
`serve` и команды администратора `user add|passwd|block|unblock|delete|list|link-oidc`.
Хранилище аккаунтов, сессий, привязок и попыток входа — SQLite (`sqlx`, уже в ядре) в папке
данных. Vault аккаунта — `<данные>/users/<id аккаунта>/<имя vault>/`, открывается
`NativeBackend`; `Host` на (аккаунт, vault) живёт, пока открыт хоть в одной вкладке, и
закрывается по простою. Корзина — `<данные>/trash/`.
Конфигурация — файл TOML и переменные окружения: адрес, папка данных, публичный URL, срок
сессии, провайдер OIDC (issuer, client id/secret, подпись кнопки).

## 3. Вход и сессии (конституция XI)

**Decision**:
- пароль — `argon2` (argon2id, параметры по умолчанию OWASP), ≥ 12 знаков;
- сессия — 32 случайных байта; в базе — только blake3 токена; cookie `__Host-typsidian`
  `HttpOnly; Secure; SameSite=Lax; Path=/` (Lax — ради возврата от провайдера входа);
  продление при действии, 30 дней простоя по умолчанию;
- CSRF — у каждой сессии свой токен; все изменяющие запросы и вызовы команд требуют
  заголовок `X-Typsidian-CSRF` с ним (выдаётся в `GET /api/me`);
- попытки — счётчик на логин в памяти: после 5 неверных — пауза 1, 2, 4… мин, до часа;
- OIDC — `openidconnect`: authorization code + PKCE; `nonce` и проверочный код PKCE — в
  памяти сервера под случайным `state` (10 мин), тот же `state` — в короткой cookie
  `__Host-typsidian-oidc` браузера, начавшего вход (подписывать нечего: секретов в cookie
  нет); аккаунт ищется по привязке `(issuer, sub)`;
- `Secure`-cookie требует HTTPS: без него сервер запускается только на loopback.

## 4. Изоляция и разрешённые команды

**Decision**: путь к vault строится сервером из id аккаунта сессии и имени vault (имя
проверяется: без `/`, `\`, `..`, управляющих знаков); клиенту не доступны команды, принимающие
путь файловой системы вне vault (`open_vault`, обзор папок, импорт из папки, ключи ssh) —
`dispatch` вызывается только для команд из белого списка `apps/server/src/allowed.rs`. Пути
внутри vault проверяет само ядро (`NativeBackend`), как на desktop.

## 5. События

**Decision**: SSE `GET /api/vaults/{vault}/events`: подписка на поток `VaultEvent` бэкенда
(тот же, что пересылает Tauri). Ошибка или обрыв — клиент переподключается; при
переподключении он перечитывает дерево (как при возвращении доступа 001).

## 6. Клиент

**Decision**: клиент серверного режима — тот же `tauriVaultClient`/предпросмотр Tauri, но с
`invoke` поверх HTTP (`POST /api/vaults/{vault}/invoke/{команда}`, тело — аргументы JSON):
клиент Tauri получает транспорт параметром. Подсветка, орфография, дополнение по буферу и
прочие чистые функции — в wasm браузера, как в web-режиме с папкой. События — SSE вместо
событий Tauri. Обрыв связи — баннер, правка остаётся в редакторе, повтор с нарастающей
паузой (FR-010).

## 7. Раздача приложения

**Decision**: `apps/web` собирается статикой (`output: "export"` при сборке для сервера);
`typsidian-server serve` раздаёт её и API с одного адреса (одна cookie, без CORS). В
разработке `next dev` проксирует `/api` на сервер (`rewrites`).

## 8. Ревью безопасности (`security-review-agent`, 2026-10-24)

Исправлено:
- **Пути команд выходили из vault** (критично): `NativeBackend` склеивал корень с путём
  клиента как есть — абсолютный путь или `..` давали файлы машины и vault других аккаунтов.
  Теперь каждая файловая операция бэкенда проверяет путь (`vault::is_inside`: относительный,
  только обычные компоненты); тест ядра на соседнюю папку и тест API на абсолютный путь и
  путь к vault другого аккаунта для `read`, `write`, `delete`, `rename`, `create`.
- **SSRF через свои адреса шаблонов**: `template_sources` из аргументов команд сервер
  обнуляет, пока администратор не разрешит их (`template_sources = true`).
- **Скачивание шаблона без предела в памяти**: тело читается частями до предела, запись
  архива — не больше остатка предела.
- **DoS входа**: невозможный логин и пароль длиннее 1 КиБ отклоняются до лимитера и argon2;
  argon2 — не больше 4 одновременно; попытки одного логина — строго по одной (проверка и
  счёт атомарны).
- **SSE после отзыва сессии**: поток перепроверяет сессию раз в 30 с.
- **Удалённые заметки в системной корзине ОС**: у бэкенда своя корзина,
  `<данные>/trash/notes/<аккаунт>/<vault>/`.
- **Глобальный замок при открытии vault**: замок на ячейку vault; обход списка — вне
  асинхронных потоков; не больше 256 открытых vault на сервер и 100 vault на аккаунт.
- JSON-аргументы команды — до 16 МБ; права папки данных 0700, базы 0600;
  `X-Forwarded-For` — правое значение; HSTS и CSP `frame-ancestors 'none'`; переименование
  vault без гонки (место занимается `create_dir`), уникальные имена в корзине;
  предупреждение, если сервер слушает не loopback.

Принято и записано как ограничение:
- Блокировка входа — по логину: перебором можно закрыть вход чужому логину на время паузы
  (clarifications). Защита от перебора важнее; лимит по адресу — при необходимости позже.
- CSP не ограничивает скрипты: статика Next.js несёт встроенные скрипты.
- Сессии подсветки и сборки Typst не квотируются по аккаунту; карта незавершённых входов
  OIDC ограничена 10 000 общих записей. Сервер рассчитан на команду, а не на открытый
  интернет с регистрацией (её нет).
- Ссылки (symlink) внутри vault, созданные снаружи, сервер не создаёт и не запрещает: их
  может положить только администратор сервера.
