# Quickstart: проверка библиографии vault

Все команды — из корня репозитория внутри `nix develop` (cargo-команды строго по одной, без
таймаутов). Если wasm-тесты падают с «http status: 404» — запускать через
`env -u LD_LIBRARY_PATH`.

## Ядро

```sh
nix develop --command cargo test -p typsidian-core --lib sources
nix develop --command cargo test -p typsidian-core --lib structure
nix develop --command cargo test -p typsidian-core --test sources_native
nix develop --command cargo build -p typsidian-core --target wasm32-unknown-unknown
nix develop --command bash -c "cd packages/core && wasm-pack test --headless --chrome -- --test sources_wasm"
nix develop --command cargo bench -p typsidian-core --bench sources_scale
```

Что доказывают тесты (`tests/common/sources_cases.rs`, оба таргета):
- чтение: `.bib` и `.yml` с одной негодной записью дают остальные записи и одну ошибку со
  строкой (FR-008); повтор ключа; YAML со сломанным синтаксисом — ошибка уровня файла, прочие
  файлы целы; посторонний `.yml` источником не считается (research.md §3);
- библиотека: `refresh` перечитывает только изменившийся файл; два файла с одним ключом — два
  источника (Edge Cases);
- поиск: по автору, названию, году, ключу; несколько слов; порядок; `limit` и `total_matches`;
- запись цитаты: `@k`, `#cite(<k>)`, `#cite(label("…"))`, формы в математике и коде, отказ в
  строке и комментарии; каждый результат разбирается `typst::syntax::parse` без ошибок (FR-003);
- список литературы: `Add`, `Extend`, `None`; путь от корня vault;
- индекс: переходы прохода, отмена, пропуск неизменённых, правка одной заметки, цитирующие с
  фрагментом, ключи без источника;
- отметки: вся таблица research.md §10.

`sources_scale` печатает: разбор файла на 10 000 записей; поиск по 10 000 (бюджет SC-002 —
200 мс на нажатие, ожидается на порядки меньше); выборка цитирующих на индексе 5 000 заметок
(SC-004 — 1 с).

## UI

```sh
nix develop --command bash -c 'cd ui && pnpm typecheck'
nix develop --command scripts/check-i18n.sh
nix develop -c pnpm dev          # в фоне
nix develop -c node scripts/dev/browser.mjs http://localhost:3000 \
    scripts/dev/scenarios/sources.mjs --opfs-vault --shot /tmp/sources.png
```

Сценарий `sources.mjs` кладёт в vault `references.bib` (три записи, одна негодная) и две
заметки с цитатами, открывает панель «Источники», вызывает палитру, вставляет цитату,
принимает предложение списка литературы; снимки сверяются с макетом 1a–1c. В консоли —
ни одного исключения.

## Ручная проверка (web и desktop)

1. Vault без файлов источников, `Ctrl+Alt+B`: пустое состояние, «Создать references.bib» —
   файл появился в корне. В vault только на чтение кнопка недоступна, причина названа.
2. Положить `.bib` на 200 записей, `Ctrl+Alt+B`, набрать «кнут», Enter: в тексте `@knuth1984`
   (или форма `#cite(…)` для ключа с пробелом); появился запрос «Добавить список
   литературы?» — «Не сейчас» текст не меняет и больше не спрашивает в этой заметке;
   «Добавить» дописывает `#bibliography("/references.bib")`; предпросмотр собирается со
   ссылкой (US1).
3. `Ctrl+Alt+R`: панель «Источники», идёт проход с прогрессом, во время него можно печатать.
   Выбрать источник, процитированный в двух заметках: обе указаны с фрагментом, клик ведёт к
   цитате. Включить «Не цитируются» (US2).
4. Внешним редактором удалить из `.bib` запись, процитированную в открытой заметке: в течение
   нескольких секунд цитата отмечена красным, подсказка называет причину, в статус-баре
   «1 битая», в панели — группа «Нет в файлах источников» (US3).
5. Внести в `.bib` синтаксическую ошибку в одну запись: остальные на месте, в «Ошибки в
   файлах» — файл, строка, ключ.
6. Второй файл `extra.yml` с тем же ключом: в палитре две строки с именами файлов.

## Не проверено

- iOS: оболочки нет (`apps/mobile` собирается только под Android).
- Android: проверяется на фиксированной папке `Documents/Typsidian`; шторка снизу вместо
  колонки.
