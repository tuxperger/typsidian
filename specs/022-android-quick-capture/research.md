# Research: Быстрый захват на Android

**Feature**: 022-android-quick-capture | **Date**: 2026-10-15

## §1. Настройки

**Decision**: ключ `capture` в `.typsidian/vault.json` (006, `VaultOverrides`):
`inbox` (умолчание `входящие.typ`), `daily_folder` (`дневник/`), `daily_template`
(необязательно), `daily_name` (`YYYY-MM-DD` | `YYYY/MM/YYYY-MM-DD` | `DD.MM.YYYY`),
`entry_style` (`list` | `paragraph`), `entry_time` (bool, умолчание `true`).
Неизвестное значение — умолчание (как прочие ключи 006).

## §2. Запись захвата

**Decision**: `entry(settings, capture, time) -> String`:
- ссылка: `#link("url")[заголовок]` (заголовок — из `EXTRA_SUBJECT`, иначе адрес);
- текст: экранированный текст разметки (те же правила, что в 021 §2);
- картинка: `#image("путь")` (путь — `markup_path` 006 после сохранения вложения);
- приписка — через « — » после содержимого;
- вид `list`: `- ЧЧ:ММ ` + содержимое; `paragraph`: абзац с `ЧЧ:ММ` в начале; без времени — без него.

## §3. Дописывание

**Decision**: `append(text, entry) -> TextEdit`: вставка в конец; если текст не кончается
переводом строки — сначала `\n`; для абзаца — пустая строка перед. Прежний текст побайтно
сохраняется (FR-003).

## §4. Ежедневная заметка

**Decision**: дата — от окна (`{ year, month, day }` по часам устройства, Edge Cases);
`daily_path(settings, date)`; нет файла — `create_daily` из шаблона 003 (`read_template` +
`apply_insertion`), без шаблона — `= <дата словами>` по языку интерфейса. Повторное
нажатие — тот же путь (SC-004); создание — запись с `expected = None` (не перезаписывать,
если файл появился между проверкой и записью).

## §5. Соседние дни

**Decision**: `daily_neighbours(index, settings, date) -> { previous, next }` — разбор имён
файлов папки ежедневных заметок по виду названия, ближайшая существующая в каждую сторону
(FR-008).

## §6. Запись без потерь

**Decision**: по образцу `LinkOutcome` 013: `capture_write(backend, target, entry, open_buffer?)`.
Заметка открыта в редакторе → `CaptureOutcome::EditBuffer(TextEdit)` — правка применяется к
буферу, сохранение — обычным путём 001. Иначе — чтение текста с отпечатком, `append`,
`write(path, text, Some(expected))`; конфликт отпечатка → повтор на свежем тексте до 3 раз
(Edge Cases «изменена на другом устройстве»), затем ошибка с сохранением в очереди. Предел
размера заметки → `TooLarge`, захват остаётся в окне (Edge Cases).

## §7. Приём «Поделиться»

**Decision**: `intent-filter` для `ACTION_SEND` с `text/plain` и `image/*` на `MainActivity`
(`singleTask` уже стоит). Kotlin-часть плагина `capture` в `onNewIntent`/`onCreate` читает
`EXTRA_TEXT`, `EXTRA_SUBJECT`, `EXTRA_STREAM` (картинку копирует к себе, пока есть
разрешение на URI) и кладёт запись `pending/<uuid>.json` в `filesDir/captures/`, затем шлёт
событие `shared`. Rust-часть плагина отдаёт `capture_pending()` и `capture_resolve(id)`
(удаляет запись после успешной записи в vault — FR-005, SC-003).

## §8. Возврат в исходное приложение

**Decision**: команда плагина `returnToSource` → `moveTaskToBack(true)`, если активность
открыта намерением `ACTION_SEND`; иначе ничего (захват из самого приложения).

## §9. Ярлыки

**Decision**: статический `res/xml/shortcuts.xml`: «Сегодня» (`typsidian://today`) и «Во
входящие» (`typsidian://capture`) — намерения `ACTION_VIEW` на `MainActivity`; плагин шлёт
событие `shortcut` с действием. Закрепление на рабочем столе — системное, из меню ярлыков.

## §10. Web и рабочий стол

**Decision**: «Сегодня», ‹ ›, настройки — во всех оболочках; лист захвата доступен командой
«Во входящие» (вставка текста вручную). Приёма «Поделиться» нет там, где оболочка не
принимает содержимое от других приложений: `captureSource` не передан (Edge Cases спеки).

## §11. Расхождение макета со спекой

Макет D5 добавляет ярлык «Во входящие» к «Сегодня». Это пустой лист захвата для своей
мысли, вход в уже описанный US1; спека не меняется.

## §12. Решения при реализации ядра (2026-10-16)

Отступления от плана и уточнения, найденные при реализации `packages/core/src/capture/`.

- **Тело новой ежедневной заметки без заготовки** — `= <название файла>` (например
  `= 2026-10-16`), а не «дата словами». Названия месяцев зависят от языка интерфейса,
  которого в ядре нет, а FR-011 требует одинакового результата во всех оболочках. Заготовка
  (003) кладётся дословно (подстановок у заготовок нет). Заготовка указана, но не
  читается — заметка создаётся с заголовком, а `OpenDaily.template = missing` позволяет
  окну сказать об этом; «Сегодня» не отказывает.
- **Настройки читает само ядро.** `open_daily`, `daily_neighbours`, `capture_write` берут
  настройки из `vault.json` через backend, а не из аргумента: окно держит копию, которая
  может устареть. Чистые функции (`entry`, `daily_path`, `daily_date_of`,
  `capture_target_path`) принимают `CaptureSettings` — их получают через
  `capture_settings(overrides.capture)`.
- **Раскладка в `vault.json`** — таблица `capture` с ключами из §1 (как таблицы `export`,
  `templates`); `VaultOverrides.capture: Option<CaptureOverrides>` (`None` — таблицы нет).
  Пути (`inbox`, `daily_folder`, `daily_template`) хранятся в нормальной форме
  (правило папки экспорта 009); `inbox` без `.typ` получает его; пустое поле — «не задано».
  Негодный путь при записи — `VaultSettingsError::InvalidCapture { field, problem }`, при
  чтении файла — молча умолчание. Неизвестные ключи внутри таблицы переживают запись.
- **`CaptureOutcome::EditBuffer` несёт `path`** (кроме `edit`): до записи окну нужно знать
  путь назначения, чтобы решить, открыта ли заметка; для этого есть `capture_target_path`
  (входящие/ежедневная/выбранная → путь). Окно зовёт её, ищет заметку среди открытых
  вкладок и передаёт `openBuffer` в `capture_write`.
- **Причины отказа** — `CaptureFailure`: `tooLarge`, `readOnly`, `noVault`, `conflict`,
  `unsavedElsewhere`, `targetMissing`, `invalidTarget`, `badImage`, `empty`, `io`
  (к четырём из data-model.md добавлены те, что реально различимы). Для показа есть
  `AppMessage::CaptureRefused { reason }`. `noVault` для ядра — vault недоступен
  (`AccessState::Unavailable`); «vault не открыт вовсе» отдаёт оболочка (`Failure::NoVault`
  в Tauri, отсутствие backend в web).
- **Несохранённые правки вне редактора** (`backend.has_unsaved_edits`, как в «Связать»):
  захват отказывает `unsavedElsewhere`, а не дописывает в файл поверх них.
- **Вложения (016) в ядре ещё нет** (спека 016 — Draft), поэтому картинка захвата
  сохраняется по правилам размещения 006 (`note_assets_folder` + `relative_to`), без
  собственной настройки папки: `<корень по политике>/assets/<заметка>/<заметка>-ГГГГ-ММ-ДД-ЧЧММ.<вид>`,
  занятое имя — `-2`, `-3`; если под именем лежат те же байты, берётся он (повтор захвата
  после отказа не плодит копии). Вид определяется по байтам (png, jpg, gif, webp, svg), а не
  по `mime` отправителя: HEIC и прочее, чего не читает Typst, — `badImage`. Когда 016
  появится, `store_image` заменяется её `target_folder`/`generated_name`.
- **Соседние дни** ищутся по индексу vault (`backend.list()`), распознаются только заметки
  с видом названия из действующих настроек; после смены вида старые заметки остаются на
  месте, но ‹ › по ним не ходит.
- **`CommandId::Today`**: понятия «команда без сочетания по умолчанию» в ядре нет
  (`default_shortcut()` обязано вернуть сочетание, и `resolve` подставляет его каждой
  команде без записи). Менять это ради одной команды — ломать контракт `KeybindingEntry`
  (`None` там уже значит «снято пользователем»). Взято свободное `Mod+Alt+J`
  («journal»): занятые `Mod+Alt`-буквы — `s c h u g m w p`; `t`, `d`, `l` отданы системе
  на Linux. Пользователь может снять или переназначить как любое другое.
- **Image-байты через Tauri** идут как `Vec<u8>` (JSON-массив чисел) — для снимков в
  несколько мегабайт это терпимо; если окажется медленно, команду можно перевести на
  `tauri::ipc::Request` с сырым телом, сигнатура ядра не меняется.
