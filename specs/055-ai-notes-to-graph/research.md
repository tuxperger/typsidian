# Research: Заметки в граф знаний

## §1. Тот же конвейер, что у уроков

**Decision**: импорт — задание извлечения 054 (`ai/knowledge/jobs.rs`) с источником-файлом.
Инструкции извлечения для заметок — отдельный текст без требования ссылаться на событие
урока; объединение и id — как в 054 §3. Покрытие источника — хэш содержимого части в
`sources.jsonl`: повтор неизменённого файла пропускает отправку частей, изменённого —
отправляет заново и дописывает формулировки (FR-006, SC-002).

**Alternatives**: в LearnHarness повторный импорт всегда отправляет файл целиком; здесь
пропуск неизменённых частей экономит деньги и не противоречит спеке.

## §2. Оценка до отправки

**Decision**: `ai_knowledge_import_estimate(paths)` раскрывает папки, проверяет доступ
(`check_access_in` 050), вид файла и текстовый слой PDF, считает объём (символы / 4) и
стоимость по `price` 050. Импорт стартует только с тем же списком (FR-002). Импорта «всего
vault» нет: корень vault в меню не предлагается (FR-001).

## §3. Виды файлов

**Decision**: заметки Typst и текстовые файлы — как есть; PDF — текст страниц через
`hayro-interpret`, уже входящий в дерево зависимостей через Typst (чистый Rust, оба
таргета). Если его API не отдаёт текст глифов — `pdf-extract` (чистый Rust), с проверкой
`nix-env-agent`. PDF без текста — `Skipped(NoText)`; доски, картинки — `Skipped(Unsupported)`.

## §4. Части большого файла

**Decision**: части до 20 тыс. символов по границам строк (для PDF — страниц); у каждой
части своё состояние; итог файла — `Done` / `Partial` / `Failed` / `Skipped(причина)`.
Повтор файла обрабатывает только незавершённые части.

## §5. Переименование источника

**Decision**: перенос заметки в приложении дописывает `Moved` в `sources.jsonl` (054 T002);
повторный импорт по новому пути узнаёт источник.

## §6. Решения ядра (T001–T007)

**Decision**:

- **PDF.** `hayro-interpret` 0.7.0 подключён к `packages/core` напрямую (раньше только
  транзитивно через `typst-render`/`typst-svg`), та же версия, `Cargo.lock` получил две строки
  зависимостей ядра (`hayro-interpret`, `kurbo` 0.13 — для типов `Device`), новых крейтов и
  нативных библиотек нет. Unicode даёт `Glyph::as_unicode()`; перенос строки — по смене
  вертикального положения, пробел — по зазору относительно `advance_width` глифа. PDF без
  единого глифа с Unicode — `NoText`. Пределы: 10 МБ (по метаданным листинга до чтения),
  300 страниц, 1 млн символов; зашифрованный и повреждённый — `Unsupported`.
- **Сверка оценки.** `ImportEstimate` несёт `requested` (очищенный выбор) и хэш содержимого
  каждого файла. Первый `begin_import` пересчитывает оценку по `requested` и сравнивает её
  целиком (`==`): изменились список, содержимое файла, покрытие частей, доступ или модель —
  отказ `LessonChanged` до записи журнала и до заведения задания. После сверки тексты частей
  держит задание в памяти (отправляется ровно то, что оценено); доступ проверяется заново
  перед каждой частью.
- **Покрытие.** `Covered { source, kind: Note, part, hash, at }`; `hash` — первые 32 hex
  blake3 текста части. Часть покрыта, если хэш есть у источника (с учётом `Moved`) и вклад
  позже не убирали (`SourceRemoved keep: false` сбрасывает покрытие). Одинаковые части внутри
  файла отправляются один раз.
- **Пределы.** До 200 путей в выборе; 500 файлов; просмотр до 5000 записей листинга; 1 МБ на
  текстовый файл, 64 МБ чтения и 4 млн символов на оценку; в перечне пропущенных до 200 записей
  (остальные считаются в `skipped_more`); до 1000 частей на задание (считает ядро). Часть —
  до 20 тыс. символов.
- **Сбои.** Непонятый ответ модели (`BadResponse`) закрывает только свой файл (`Partial`
  или `Failed`), остальные идут дальше; три подряд — остановка. Любой другой сбой и отмена
  останавливают задание, нетронутые файлы остаются `Pending`.
- **Повторно используемые отказы.** Новых вариантов `AiFailure` нет (под них нужны ключи
  локалей): корень vault, путь вне vault и слишком длинный выбор — `Forbidden`; изменившаяся
  оценка — `LessonChanged`; второй импорт в vault — `Cancelled`.

## §7. Ревью безопасности (T011)

`security-review-agent`, 2026-11-03.

**Открытый вопрос — H1, H2 (разбор PDF).** У `hayro-syntax`/`hayro-interpret` нет предела
распаковки сжатых потоков (килобайтный PDF разворачивается в гигабайты — падение
приложения, на сервере — общего процесса) и бюджета операций (экспоненциальное раскрытие
форм — бесконечный разбор под блокировкой vault). Срабатывает уже на оценке, до
подтверждения. Варианты: патч разборщика с пределами; отключить PDF до безопасного
разбора; изоляция в отдельном процессе или воркере. **Решение пользователя 2026-11-03:
оставить как есть, вернуться позже** — риск принят; вопрос записан спекой
`specs/069-pdf-parsing-hardening/spec.md`.

Исправляется в 055 (T013–T018):

- **M1** — паника разборщика PDF перехватывается (native) и даёт пропуск файла, а не сбой
  команды; в wasm остаётся риском до 069.
- **M2** — на сервере оценка импорта ограничена: одно место на аккаунт и общий предел.
- **L1** — тексты частей задания убираются при любом завершении задания, в том числе
  при обрыве соединения.
- **L2** — английские инструкции извлечения для заметок: испорченное правило о цепочках
  исправлено.
- **L3** — чтение файла для импорта не идёт по ссылке, подменённой после проверки, и не
  читает больше предела (проверка по открытому файлу, чтение с ограничением).
- **L4** — выбор, покрывающий все записи корня vault, приравнивается к корню: `Forbidden`.

## §8. Расхождения вёрстки с макетом (T006, T008)

**Decision** — намеренные:

- Подтверждение — модальное окно; ход и итог — немодальная карточка (на телефоне во всю
  ширину): редактирование во время импорта не блокируется (SC-003).
- В итоге — «Закрыть» и строка «добавлено N утверждений»; при нуле новых частей —
  подсказка «отправлять нечего», «Добавить» доступна (ядро запишет перенос источника).
- «Повторить» показывает новую оценку и подтверждение, а не отправляет сразу (принцип IX).
- Пункт меню дерева принимает один файл или папку: множественного выбора в дереве нет;
  несколько путей — через «Добавить заметки…» в виде графа.
