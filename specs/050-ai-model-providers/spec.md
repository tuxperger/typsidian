# Feature Specification: Провайдеры моделей для обучения с ИИ

**Feature Branch**: `050-ai-model-providers`

**Created**: 2026-11-01

**Status**: Implemented

**Priority**: P1

**Summary**: Для каждого vault можно явно включить обучение с ИИ, подключить свою модель — облачную по ключу или локальную — и всегда видеть, что ей отправлено и сколько это примерно стоит.

**Input**: Первая фича линейки обучения с ИИ 050–052, конституция 4.0.0, принцип IX «Обучение с ИИ». Уроки, агент и сессии — следующие фичи.

## Clarifications

### Session 2026-11-01

Вопросы закрыты без обращения к пользователю: ответы следуют из конституции и существующих
решений проекта (скилл `flow-typsidian`).

- Q: Может ли пользователь серверного режима указать свой адрес модели? → A: Только если администратор сервера разрешил это в конфигурации; по умолчанию разрешены лишь Anthropic и OpenAI (принцип XI: иначе адрес открывает запросы во внутреннюю сеть сервера).
- Q: Общий ли ключ на все vault устройства? → A: Нет, ключ привязан к vault и подключению, как секреты синхронизации в 011.
- Q: Где лежит журнал отправленного? → A: В служебном месте vault как данные устройства, вне синхронизации, как снимки 029; в серверном режиме — на сервере, в служебном месте vault этого пользователя. Журналы самого сервера текста запросов не содержат.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Включить и подключить модель (Priority: P1)

Пользователь открывает настройки vault, явно включает обучение с ИИ, прочитав, какие данные
и кому будут уходить. Выбирает вид подключения: облачный провайдер с ключом API или свой
совместимый адрес, в том числе локальную модель. Проверяет соединение и выбирает модель.

**Why this priority**: без подключения невозможны уроки 051–052; без явного включения
нарушается обещание принципа IX.

**Independent Test**: включить функцию в одном vault, подключить локальную модель, получить
успех проверки; в другом vault функция остаётся выключенной.

**Acceptance Scenarios**:

1. **Given** новый vault, **When** пользователь открывает настройки, **Then** обучение с ИИ
   выключено и никаких запросов к моделям не выполняется.
2. **Given** функция выключена, **When** пользователь включает её, **Then** до включения он
   видит, что содержимое заметок может уходить выбранному провайдеру, и подтверждает это.
3. **Given** введён ключ облачного провайдера, **When** пользователь нажимает «Проверить»,
   **Then** видит успех и список доступных моделей либо понятную причину отказа.
4. **Given** указан свой адрес, **When** провайдер не отдаёт список моделей, **Then** имя
   модели можно ввести вручную и проверить пробным запросом.
5. **Given** функция включена, **When** пользователь выключает её, **Then** запросы к
   моделям прекращаются, а заметки и настройки остальных функций не меняются.

---

### User Story 2 - Видеть, что отправлено и сколько стоит (Priority: P1)

Пользователь открывает журнал отправленного: для каждого запроса видно время, провайдера,
модель, текст запроса, объём и примерную стоимость. Журнал можно очистить.

**Why this priority**: это условие принципа IX, а не удобство.

**Independent Test**: выполнить пробный запрос и найти его в журнале с полным текстом.

**Acceptance Scenarios**:

1. **Given** выполнен пробный запрос, **When** пользователь открывает журнал, **Then** видит
   запись с дословным текстом отправленного и ответом провайдера об объёме.
2. **Given** цена модели известна, **When** запрос завершён, **Then** показана примерная
   стоимость с пометкой «примерно».
3. **Given** цена неизвестна (свой адрес, локальная модель), **When** запрос завершён,
   **Then** вместо стоимости написано «неизвестно», а не ноль.
4. **Given** журнал не пуст, **When** пользователь очищает его и подтверждает, **Then**
   записей больше нет.

---

### User Story 3 - Запретить папки для агента (Priority: P2)

Пользователь отмечает папки vault, которые агент не должен читать. Запрет действует и на
вложенные папки и файлы.

**Why this priority**: условие принципа IX, но проверяется в полную силу только когда агент
начнёт читать заметки (051).

**Independent Test**: запретить папку и получить отказ при проверке доступа к заметке в ней.

**Acceptance Scenarios**:

1. **Given** запрещена папка, **When** запрашивается доступ к заметке в ней или вложенной
   папке, **Then** доступ отклоняется.
2. **Given** запрещённая папка переименована или перемещена в приложении, **When** проверяется
   доступ, **Then** запрет продолжает действовать на её новое расположение.
3. **Given** запрос пути вне vault, **When** проверяется доступ, **Then** он отклоняется при
   любых настройках.

---

### User Story 4 - Понятные отказы (Priority: P1)

Без сети, при неверном ключе, исчерпанном лимите или недоступном адресе пользователь видит
заметное сообщение с причиной и может повторить. Остальное приложение продолжает работать.

**Why this priority**: принцип VII.

**Independent Test**: отключить сеть, нажать «Проверить», получить сообщение за ограниченное
время и продолжить редактировать заметку.

**Acceptance Scenarios**:

1. **Given** нет сети, **When** выполняется проверка, **Then** за ограниченное время
   появляется сообщение о недоступности, индикатор ожидания исчезает, настройки сохранены.
2. **Given** провайдер отверг ключ, **When** выполняется проверка, **Then** сообщение говорит
   о неверном ключе и не содержит сам ключ.
3. **Given** запрос идёт, **When** пользователь отменяет его, **Then** ожидание прекращается
   сразу.

### Edge Cases

- Свой адрес без шифрования вне этого устройства: ключ и заметки пошли бы открытым текстом —
  показывается предупреждение, подключение требует отдельного подтверждения.
- Адрес перенаправляет запрос на другой хост: ключ туда не передаётся, показывается ошибка.
- В web браузер не пускает запрос к адресу: сообщение объясняет именно это ограничение, а не
  общий «сбой сети».
- Хранилище секретов устройства недоступно: ключ не сохраняется ни в каком другом месте,
  пользователь видит отказ.
- Vault открыт на втором устройстве: включение синхронизируется с vault, ключ — нет; второе
  устройство просит ввести ключ.
- В журнале — текст заметок: журнал не попадает в синхронизацию и в экспорт.
- Журнал вырос: хранятся последние 500 записей, старые вытесняются.
- Ответ провайдера необычно большой или обрывается на середине: показывается ошибка, запись
  журнала сохраняется с пометкой о незавершённости.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Обучение с ИИ MUST быть выключено по умолчанию и включаться явно, отдельно для
  каждого vault, после показа того, какие данные и кому могут уходить.
- **FR-002**: При выключенной функции приложение MUST NOT обращаться к провайдерам моделей;
  все прочие функции MUST работать как раньше.
- **FR-003**: Система MUST поддерживать подключения: Anthropic по ключу, OpenAI по ключу и
  свой адрес с совместимым протоколом, включая локальную модель, с необязательным ключом.
- **FR-004**: Система MUST NOT поддерживать внешние программы командной строки и вход через
  подписки как способ подключения.
- **FR-005**: Пользователь MUST иметь возможность проверить подключение, увидеть список
  моделей, когда провайдер его отдаёт, и выбрать модель либо ввести её имя вручную.
- **FR-006**: Система MUST давать минимальный пробный запрос, не содержащий текста заметок.
- **FR-007**: Ключи MUST храниться только в защищённом хранилище устройства и MUST NOT
  попадать в файлы vault, синхронизацию, журналы приложения, журнал отправленного и сообщения
  об ошибках.
- **FR-008**: После сохранения ключ MUST NOT показываться снова; его можно только заменить
  или удалить.
- **FR-009**: Ключ и содержимое запроса MUST передаваться только по настроенному адресу;
  перенаправление MUST останавливать запрос с сообщением.
- **FR-010**: Незашифрованное подключение к адресу вне этого устройства MUST требовать
  отдельного подтверждения с предупреждением.
- **FR-011**: Каждый запрос к модели MUST записываться в журнал отправленного до отправки:
  время, провайдер, модель, дословный текст, затем объём, итог и примерная стоимость.
- **FR-012**: Если запись в журнал не удалась, запрос MUST NOT отправляться.
- **FR-013**: Журнал MUST храниться на устройстве, вне синхронизации и экспорта, быть
  ограничен 500 последними записями и очищаться пользователем с подтверждением.
- **FR-014**: Стоимость MUST показываться как примерная только при известной цене модели;
  при неизвестной цене MUST показываться «неизвестно».
- **FR-015**: Пользователь MUST иметь возможность запретить папки для агента; запрет MUST
  действовать на вложенное содержимое и следовать за переименованием в приложении.
- **FR-016**: Система MUST предоставлять следующим фичам единую проверку доступа: только
  чтение, только внутри vault, с учётом запрещённых папок; служебные каталоги vault
  агенту недоступны всегда.
- **FR-017**: Любой запрос MUST иметь предел ожидания и отмену; отказ MUST давать заметное
  сообщение с причиной и MUST NOT блокировать редактор или терять настройки.
- **FR-018**: Настройки функции MUST быть доступны в web с папкой на устройстве, web в
  серверном режиме, на рабочем столе и на Android с одинаковым поведением.
- **FR-019**: В серверном режиме ключи, журнал и настройки подключения MUST быть изолированы
  по пользователям; запросы к провайдеру выполняются сервером пользователя. Свой адрес модели
  в этом режиме MUST быть недоступен, пока его не разрешил администратор сервера; журналы
  сервера MUST NOT содержать текст запросов.
- **FR-020**: Все тексты интерфейса MUST быть локализованы.

### Key Entities

- **Настройка обучения с ИИ**: принадлежит vault: включено ли, вид подключения, адрес,
  выбранная модель, запрещённые папки. Не содержит ключа.
- **Ключ провайдера**: секрет устройства, привязанный к vault и подключению.
- **Запись журнала отправленного**: время, провайдер, модель, дословный запрос, объём, итог,
  примерная стоимость.
- **Цена модели**: известная стоимость единицы объёма для модели; может отсутствовать.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь с готовым ключом подключает модель и получает успешную проверку
  менее чем за 2 минуты.
- **SC-002**: При выключенной функции за всю работу с приложением к провайдерам выполняется
  0 запросов.
- **SC-003**: 100% запросов к моделям присутствуют в журнале с дословным текстом.
- **SC-004**: Поиск значения ключа в файлах vault, журналах и сообщениях об ошибках даёт 0
  совпадений.
- **SC-005**: Без сети сообщение об ошибке появляется не позднее чем через 30 секунд, и
  редактирование заметки всё это время не прерывается.
- **SC-006**: 100% проверок доступа к запрещённым папкам и путям вне vault отклоняются.

## Assumptions

- Конституция 4.0.0: условия принципа IX обязательны; фича проходит `/speckit-clarify` и
  `security-review-agent`.
- Подключение настраивается на vault: включение и адрес живут с vault, ключ — на устройстве.
- Список провайдеров первой версии — Anthropic, OpenAI и совместимый адрес; остальные
  доступны через совместимый адрес.
- Цены моделей — справочник в приложении, поэтому они могут устареть; отсюда «примерно».
- Зависит от 037 (серверный режим), 011 (защищённое хранилище устройства), 004 (настройки),
  006 (служебный каталог vault).
- Не входит: уроки, агент, сессии, карта знаний (следующие фичи линейки).
