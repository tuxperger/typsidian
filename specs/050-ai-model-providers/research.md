# Research: Провайдеры моделей для обучения с ИИ

## §1. HTTP-клиент

**Decision**: трейт `AiTransport` с общим API: native — `reqwest`, wasm — `web_sys` `fetch`
(§4), в тестах — подделка.
**Rationale**: принцип II допускает различие внутри реализации за трейтом. Официального Rust SDK
Anthropic нет, поэтому сырой HTTP допустим.
**Alternatives**: отдельный HTTP в UI — нарушает принцип I.

## §2. Протокол Anthropic

**Decision**: `POST https://api.anthropic.com/v1/messages`, `GET /v1/models`, заголовки
`x-api-key`, `anthropic-version: 2026-10-21`, `content-type: application/json`. Модель по
умолчанию при подключении Anthropic — `claude-opus-5-5`. Пробный запрос: без `temperature`,
`thinking` и `effort`, `max_tokens: 1024`. Ответ разбирается по `stop_reason`, в том числе
`refusal`; ошибки — по коду: 401 ключ, 402 оплата, 403 права, 404 модель, 429 лимит,
5xx и 529 перегрузка. В wasm добавляется `anthropic-dangerous-direct-browser-access: true`.
**Rationale**: сверено со скиллом `claude-api` (кэш 2026-10-06). Отказы цепочки `fallbacks`
не включаются: модель выбирает пользователь, серверный откат подменил бы её молча. Решение
пересматривается в 051. Браузерный заголовок в скилле не описан: проверяется при реализации
по живой документации (T010): заголовок подтверждён записью о поддержке CORS в SDK; у организаций с
нулевым хранением данных CORS не работает, в web это показывается как `BlockedByBrowser`.
**Alternatives**: `2023-06-01` — старая версия API без причины.

## §3. Совместимый адрес и OpenAI

**Decision**: один разбор для OpenAI (`https://api.openai.com/v1`) и своего адреса:
`POST {base}/chat/completions`, `GET {base}/models`, необязательный `Authorization: Bearer`.
Параметр предела длины ответа в пробном запросе не передаётся.
**Rationale**: де-факто общий протокол локальных серверов; имена параметров длины расходятся
между серверами, а пробный ответ короткий.

## §4. Перенаправления (FR-009)

**Decision**: native — `reqwest` с `redirect::Policy::none()`, любой 3xx становится отказом
`Redirected`. wasm — прямой `web_sys` `fetch` с `redirect: "error"` и `AbortController`, а не
`reqwest`: он настройки перенаправления не даёт, и при 307/308 браузер повторил бы тело запроса,
то есть текст заметок, на новый хост. В браузере перенаправление неотличимо от блокировки,
поэтому оба случая — `BlockedByBrowser`, и сообщение называет обе причины.
**Rationale**: ключ и содержимое не должны уходить на хост, которого пользователь не настраивал.

## §5. Незашифрованный адрес (FR-010)

**Decision**: чистая функция ядра `classify_endpoint`: `https` — ок; `http` на loopback — ок;
`http` иначе — `NeedsConfirmation`; прочие схемы и адреса с логином в URL — отказ. Подтверждение
хранится рядом с адресом и сбрасывается при смене адреса.

## §6. Хранение настроек

**Decision**: отдельный файл `.typsidian/ai.json`, едет с синхронизацией; нет файла или он
нечитаем — выключено. Подтверждение незашифрованного адреса — там же.
**Rationale**: FR-001 требует настройки на vault. `vault.json` разбирается полем за полем со
слоями устройства, а здесь слоя устройства нет; нечитаемый файл должен безопасно давать
«выключено», а не откладываться как `set_aside_invalid`. Ключ `Anthropic` или `OpenAI` никогда
не уходит на `Custom`, поэтому подменённый синхронизацией адрес ключа облака не получит.

## §7. Ключи

**Decision**: три новых `SecretKind`: `AiAnthropicKey`, `AiOpenAiKey`, `AiCustomKey`, через
существующий `SecretStore`: keyring на рабочем столе, приватный каталог на Android, файл на
сервере, IndexedDB в web. UI никогда не получает ключ обратно, только `key_present`.
**Rationale**: шов 011 уже закрывает FR-007 и изоляцию на сервере.
Команды принимают `vaultId` от клиента; сервер заменяет его своим id vault этого пользователя
до вызова ядра, как `sync_open` (038 §4), иначе клиент мог бы запросить чужой ключ.
**Known limit**: в web ключ доступен коду страницы, как и токены 011; это показывается в
подсказке и записывается в отчёт security-review.

## §8. Журнал

**Decision**: `.typsidian/ai-journal.jsonl`, добавлен в `derived_paths()`. Две записи на запрос:
`sent` до отправки (FR-011, FR-012), `done` после. Запись с `sent` без `done` показывается как
«оборвано». Лимит 500 запросов: при превышении файл атомарно переписывается. Нечитаемые строки
пропускаются.
**Rationale**: как снимки 029: не синхронизируется, по пользователям разделён самим vault.
**Alternatives**: SQLite — нет на wasm.

## §9. Отмена и предел ожидания

**Decision**: `.timeout(30 s)` у `reqwest` для проверки; отмена — реестр `AiCancels` в ядре:
`futures` `select` запроса против `oneshot`, команда `ai_cancel(request_id)`.
**Rationale**: `.timeout` есть на обоих таргетах (007 §2). `select` работает без tokio, значит
и на wasm. Тот же механизм понадобится потоковому выводу 051.

## §10. Цены

**Decision**: статическая таблица в ядре только для моделей Anthropic из скилла `claude-api`
(кэш 2026-10-06), на входные и выходные токены; у Haiku 5.5 — базовый тариф до 100K. OpenAI и
свой адрес — `None`, то есть «неизвестно».
**Rationale**: FR-014. Цен OpenAI у нас нет из проверенного источника, а выдумывать нельзя.

## §11. Запрещённые папки и единая проверка

**Decision**: чистая `check_access(path, &AiSettings) -> Result<(), AccessDenied>`, сравнение по
компонентам нормализованного относительного пути: абсолютные пути и `..` отклоняются, служебное
место закрыто всегда. Следование за переименованием — обновление списка там же, где
`vault::relocate` переписывает пути (FR-015).

## §12. Серверный режим

**Decision**: команды `ai_*` — в `allowed.rs`; не в списке демо-режима (`demo.rs`): чужие гости
не должны тратить ресурсы и слать данные наружу. Новый флаг конфигурации `ai_custom_endpoint`
(по умолчанию `false`): `invoke.rs` отклоняет `Custom` до ядра, как `sync_private_remotes`.
Журналы сервера не логируют тела команд.

## §13. Макет

**Decision**: временный HTML-макет. Claude Design требует `/design-login`, который выполняет
только пользователь.

## §14. Ревью безопасности (T028)

`security-review-agent`, 2026-11-02: CRITICAL и HIGH нет. Исправлено (T030–T036):

- **M1 — адрес из синхронизации.** `ai.json` едет с синхронизацией, поэтому адрес и
  подтверждение незашифрованного соединения в нём может поменять другое устройство.
  Решение: свой адрес одобряется на каждом устройстве отдельно, одобрение лежит в
  хранилище секретов (`SecretKind::AiCustomOrigin`), по образцу `RemoteOrigin` фичи
  синхронизации. Одобряет только явное действие на этом устройстве: ввод адреса,
  «Всё равно подключить», «Доверять адресу». Незашифрованный адрес ядро одобряет
  только с подтверждением, данным здесь. Без одобрения — `EndpointNotApproved` до
  журнала и сети.
- **M2 — внутренняя сеть сервера.** Транспорт ИИ на сервере использует политику
  синхронизации (`server_policy`): имя проверяется после разрешения на каждом
  соединении, адрес числом — до запроса (`InternalAddress`). Внутренние адреса
  разрешает тот же флаг администратора `sync_private_remotes`: обе настройки отвечают
  на один вопрос — можно ли запросам сервера ходить в его сеть.
- **M3 — журнал в истории.** Производные пути (`derived_paths`) не попадают в
  изменения истории версий независимо от `.gitignore` vault. Для Syncthing закрытие
  остаётся за `.stignore`: о недостающем правиле предупреждает существующий отчёт
  «неполные правила».
- **M4, L5 — `check_access`.** Компоненты сравниваются без учёта регистра,
  Unicode-формы и хвостовых точек и пробелов; при выключенной функции доступа нет;
  `check_access_in` (команда `ai_check_access`) отказывает путям через символические
  ссылки.
- **L1** — в wasm объявленный размер ответа проверяется до чтения тела.
- **L2** — на сервере не больше 16 одновременных запросов к моделям.
- **L3** — повтор id идущего запроса отказывает, отмена первого не теряется.

Не исправлено намеренно:

- **L4** — сбой записи перенесённого запрета при переименовании папки проходит молча,
  как и у остальных пометок, едущих за папкой (`move_section_marks`). Заметный отказ
  нужен им всем сразу — кандидат в отдельную фичу.
- **L6** — ключ в web лежит в IndexedDB открытым (§7).
- Значения `enabled` и `denied_folders`, пришедшие с другого устройства, не
  подсвечиваются: включение без ключа на этом устройстве запросов не даёт, свой адрес
  требует одобрения (M1).
