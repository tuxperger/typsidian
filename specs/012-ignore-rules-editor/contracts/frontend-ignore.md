# Contract: интерфейс — редактор правил исключения

## `SyncClient` (`ui/src/sync/sync-client.ts`)

```ts
ignoreOpen(file: IgnoreFile): Promise<IgnoreDocument>;
ignoreCheck(file: IgnoreFile, text: string): Promise<IgnoreCheck>;
ignoreRestore(file: IgnoreFile, text: string): Promise<string>;
ignoreSave(request: IgnoreSaveRequest): Promise<IgnoreSaveOutcome>;
```

Реализации — `sync-client-web.ts` (wasm) и `sync-client-tauri.ts` (команды `sync_ignore_*`).
Правил в клиентах и компонентах нет: они показывают ответ ядра.

## Вход

Раздел «Правила исключения» панели синхронизации — две строки: правила истории и правила
Syncthing, у каждой кнопка «Открыть» (FR-001). Раздел виден всегда, когда прочитана
сводка. Предупреждение о недостающих правилах (011 §FR-026) получает то же действие.

## Диалог `IgnoreEditor`

| Элемент | Поведение | Требование |
| --- | --- | --- |
| Заголовок | имя файла и его роль | FR-001 |
| Пояснение | «у каждого устройства свой» / «общий, попадает в снимки»; «правила сейчас не действуют»; «действуют и правила вышележащих каталогов» | FR-007, FR-008 |
| Поле | весь файл; строки `check.block` подсвечены и подписаны «правила приложения» | FR-002 |
| Новый файл | поле с предложенным блоком и пометка «будет создан при сохранении» | FR-005 |
| Нередактируемый | поле скрыто, названа причина (`editable`), сохранение недоступно | FR-016 |
| Проверка | `ignoreCheck` через ~300 мс после остановки набора; список `missing` с последствием и кнопка «Вернуть правила приложения» (`ignoreRestore` → текст поля) | FR-010, FR-011 |
| Сохранить | `ignoreSave`; недоступно без правки (кроме создания файла) и во время сохранения | FR-003 |
| `NeedsConfirmation` | подтверждение с перечнем правил и риском → повтор с `confirm_incomplete` | FR-012 |
| `Diverged` | различие (`DiffView`) и три действия: взять с диска, записать свою (`overwrite`), вернуться | FR-015 |
| `Refused` / `SyncError` | причина над кнопками, текст поля не тронут | FR-017, FR-018 |
| Обновление извне | рост `sync.revision` → `ignoreOpen`; `base` другая: без правки — заменить текст и сообщить, с правкой — предупредить | FR-014 |
| Закрытие с правкой | сохранить / отбросить / вернуться; `Escape` ведёт сюда же | FR-006 |

После `Saved` диалог остаётся открытым в состоянии «чистый» и вызывает `sync.refresh()`.

## Доступность

- Диалог — `role="dialog"` с `aria-modal`, фокус попадает в поле; все действия достижимы с
  клавиатуры, `Ctrl/Cmd+S` в поле — сохранить (FR-022).
- Проверка — `role="status"`, отказ — `role="alert"`.
- Ширина до 400 px: диалог на весь экран, кнопки переносятся.

## Локализация

Все строки — ключи `sync.ignore.*` в `ui/src/i18n/locales/{ru,en}/sync.ts` (FR-021).
Причины отказа и последствия правил — по ключу на вариант перечисления ядра.
