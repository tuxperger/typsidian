# Quickstart: проверка редактора правил исключения

Проверяется на копии vault (например, копии `/home/apokryf/notes`), в web и на рабочем
столе; на Android — сценарии 1, 3, 4. Типы и поведение — [data-model.md](./data-model.md),
[contracts/](./contracts/).

## Автоматические проверки

```bash
.specify/scripts/typsidian/gates.sh all     # fmt, оба таргета ядра, тесты, типы UI
scripts/check-i18n.sh                       # хардкод интерфейса
```

Случаи ядра — `packages/core/tests/common/sync_cases.rs` (группа `ignore_editor_*`),
запускаются из `sync_native.rs` и `sync_wasm.rs`.

## Ручные сценарии

1. **Правка и сохранение (US1)**. Vault с историей → панель синхронизации → «Правила
   исключения» → правила истории. Дописать `черновики/`, сохранить.
   Ожидается: файл на диске — текст редактора; файлы из `черновики/` пропали из списка
   изменений панели, сам `.gitignore` в нём появился.
2. **Создание файла (US1)**. Vault без `.stignore` → открыть правила Syncthing.
   Ожидается: поле с блоком приложения, пометка «будет создан»; на диске файла нет, пока не
   нажато «Сохранить».
3. **Обязательные правила (US2)**. В правилах Syncthing удалить строку `/.git`.
   Ожидается: под полем названо недостающее правило; «Вернуть правила приложения»
   восстанавливает блок, свои строки не меняются. Удалить снова и сохранить — запрос
   подтверждения; после подтверждения предупреждение в панели остаётся.
   Вписать **выше** блока `!/.git` — правило снова названо недостающим (в `.stignore`
   выигрывает первая строка); в правилах истории то же даёт отмена **ниже** блока.
4. **Внешнее изменение (US3)**. Открыть правила истории, изменить текст; другой программой
   дописать строку в `.gitignore`; нажать «Сохранить».
   Ожидается: файл не перезаписан, показано различие и три действия. «Взять с диска» —
   в поле версия с диска; повторить и выбрать «Записать свою» — на диске текст редактора.
   Без своей правки внешнее изменение появляется в поле само, с уведомлением.
5. **Закрытие с правкой (US1)**. Изменить текст, нажать `Escape`.
   Ожидается: вопрос «сохранить / отбросить / вернуться».
6. **Отказы**. (а) `.gitignore` — символическая ссылка (рабочий стол): редактор называет
   причину, файл цел. (б) Web без разрешения на запись: сохранение недоступно с причиной.
   (в) Файл в CRLF: после сохранения окончания строк прежние (`file .gitignore`).
7. **Правила не действуют**. Vault без истории → правила истории открываются с пояснением
   и редактируются.
