# Contract: Ядро → UI (события и запросы)

**Feature**: `specs/001-vault-manager/spec.md` | **Plan**: `plan.md`

Контракт границы WASM/JS, которую видит UI-слой (web/desktop/mobile, общий UI-код).
Все типы здесь порождаются из Rust-определений (принцип IV конституции, research.md
§9) — здесь описана форма контракта, не итоговый `.d.ts`.

## События (подписка на `watch()`)

UI подписывается на один поток `VaultEvent` (варианты — см. data-model.md
«Внешнее изменение»). Каждый вариант — самостоятельный кейс в `switch`; TS `strict`
обязан обработать их исчерпывающе (`never` в `default` для непокрытого варианта).

Требования к обработке на стороне UI (не переизобретают логику ядра, только
реагируют — принцип I):

| Событие | UI обязан |
|---|---|
| `NoteCreated` / `NoteUpdated` / `NoteRenamed` / `NoteDeleted` | Обновить дерево и открытый редактор без запроса подтверждения (FR-016, FR-017) |
| `ConflictDetected` | Показать диалог трёх вариантов (FR-022); не применять ни одну версию до ответа пользователя (FR-021) |
| `NoteDeletedWithUnsavedEdits` | Предупредить и предложить пересохранить или закрыть с явным подтверждением (FR-025) |
| `BulkChangeStarted` / `BulkChangeSettled` | Показать единый индикатор массового обновления вместо серии отдельных уведомлений (US3 AS5) |
| `VaultAccessChanged` | Отразить `ReadOnly` (заблокировать контролы записи) или `Unavailable` (полноэкранное уведомление, FR-020) без интерпретации как удаления всех заметок |
| `LinksInvalidated` | Обновить индикацию битых ссылок для затронутых заметок (FR-030) |

## Запросы (вызовы UI → ядро)

Формы вызовов из `VaultBackend` (contracts/vault-backend-trait.md), которые UI вызывает
напрямую как результат действий пользователя:

- `open`, `read`, `write`, `create`, `rename`, `delete`, `backlinks` — прямое
  отражение операций трейта.
- Перед `rename`/`delete` заметки со ссылками UI обязан вызвать `backlinks(path)` и
  показать список пользователю, дожидаясь подтверждения (FR-027, FR-028) — это
  оркестрация в UI поверх примитивов ядра, а не новая бизнес-логика (детали разрешения
  «что считается ссылкой» остаются в ядре).

## Ошибки

Все `Result<_, XError>` из трейта пересекают границу как размеченные объединения с
конкретными вариантами (не строка, не `any`). UI обязан показывать пользователю
причину отказа текстом, соответствующим варианту ошибки (FR-008, FR-013, FR-014),
без единого общего «что-то пошло не так».
