# Data Model: Vault Manager

**Feature**: `specs/001-vault-manager/spec.md` | **Plan**: `plan.md`

Сущности ниже — внутреннее представление ядра (`packages/core`), производное от
Key Entities в spec.md. Поля даны как контракт по смыслу и инвариантам, а не как
готовый Rust/SQL синтаксис — конкретные типы фиксируются в момент реализации.

## Vault

Корень открытого рабочего пространства (см. spec.md Key Entities: Vault).

| Поле | Смысл | Инварианты |
|---|---|---|
| `root_path` | Путь к папке на диске, выбранной пользователем | Ровно одна папка на открытый vault (Assumptions) |
| `access_state` | `ReadWrite` \| `ReadOnly` \| `Unavailable` | `ReadOnly` при отозванных правах записи с сохранённым чтением (FR-036); `Unavailable` при полной потере доступа (FR-020) |
| `last_opened_at` | Момент последнего успешного открытия | Используется для предложения «продолжить с последним vault» (FR-007) |
| `note_count` | Число заметок в индексе на момент последнего обхода | Всегда `<= 10 000`: vault большего размера не открывается вовсе (FR-038), поэтому величина справочная — режима, о котором UI должен был бы предупреждать, не существует |

Переходы `access_state`: `ReadWrite → ReadOnly` (права на запись отозваны, чтение
работает), `ReadWrite|ReadOnly → Unavailable` (папка/диск/разрешение пропали),
`Unavailable → ReadWrite|ReadOnly` (доступ восстановлен — только после явного
переоткрытия, FR-018).

## Заметка (Note)

Файл заметки внутри vault (spec.md Key Entities: Заметка).

| Поле | Смысл | Инварианты |
|---|---|---|
| `path` | Путь относительно `root_path` | Уникален внутри vault (FR-012); совпадение только по регистру на регистронезависимой ФС не считается разными заметками |
| `name` | Имя файла без учёта родительских папок | Должно быть допустимым для файловой системы (FR-013) |
| `mtime`, `size` | Снимок метаданных с последнего known-good состояния | Дешёвый предфильтр для обнаружения изменений (research.md §5) |
| `content_hash` | Хэш содержимого с последнего known-good состояния | Основа сравнения при подозрении на конфликт и для diff (FR-024) |
| `has_unsaved_edits` | Есть ли в открытом редакторе несохранённые правки этой заметки | Определяет, эмитится ли `ConflictDetected` вместо тихого `Updated` (FR-017 vs FR-021) |

## Папка (Folder)

Узел иерархии внутри vault (spec.md Key Entities: Папка). Не хранится как отдельная
персистентная запись — выводится из путей заметок (общие префиксы), поскольку у
пустых промежуточных папок нет отдельного состояния, которое нужно отслеживать сверх
факта их существования на диске.

## Ссылка (Link)

Направленная связь от заметки к заметке (spec.md Key Entities: Ссылка). Владелец
построения — модуль `graph` (research.md §8); vault-manager хранит только таблицу
обратных ссылок, нужную ему самому для FR-026…FR-031.

| Поле | Смысл | Инварианты |
|---|---|---|
| `source_path` | Заметка, содержащая ссылку | — |
| `target_path` | Заметка или путь, на который указывает ссылка | Не обязан существовать в индексе |
| `is_broken` | `target_path` отсутствует в текущем индексе заметок | Пересчитывается при любом изменении, влияющем на `target_path` (создание/удаление/переименование), включая внешние (FR-031) |

## Конфликт редактирования (EditConflict)

Временное состояние заметки, для которой одновременно существуют несохранённые правки
пользователя и более новое содержимое на диске (spec.md Key Entities: Конфликт
редактирования). Существует только в памяти — не персистентный (research.md §6:
персистентный кэш хранит только производные метаданные, не пользовательский буфер).

| Поле | Смысл | Инварианты |
|---|---|---|
| `note_path` | Заметка, к которой относится конфликт | Не более одного активного конфликта на заметку одновременно |
| `local_buffer` | Несохранённое содержимое из редактора | Живёт только в памяти сессии приложения (FR-035) |
| `disk_snapshot` | `(mtime, size, content_hash)` версии на диске на момент обнаружения | Обновляется, если диск меняется повторно до разрешения конфликта (US4 AS5) |
| `status` | `Pending` \| `ResolvedKeepLocal` \| `ResolvedAcceptExternal` | Автоматический переход запрещён (FR-021); переход только по явному действию пользователя (FR-023) |

## Внешнее изменение (ExternalChange / `VaultEvent`)

Зафиксированный факт создания/изменения/переименования/удаления файла vault вне
активного действия пользователя в текущем окне (spec.md Key Entities: Внешнее
изменение). Единый тип события, эмитируемый обоими backend-реализациями в UI.

Варианты (discriminated union на границе WASM/JS, см. research.md §9):

- `NoteCreated { path }`
- `NoteUpdated { path }` — только если у заметки нет несохранённых правок (FR-017)
- `NoteRenamed { from_path, to_path }`
- `NoteDeleted { path }`
- `ConflictDetected { note_path, disk_snapshot }` — вместо `NoteUpdated`, если есть
  несохранённые правки (FR-021)
- `NoteDeletedWithUnsavedEdits { note_path }` — вместо `NoteDeleted`, если есть
  несохранённые правки (FR-025)
- `BulkChangeStarted` / `BulkChangeSettled` — обрамляют массовые изменения (US3 AS5),
  чтобы UI мог показать единый индикатор вместо шторма отдельных событий
- `VaultAccessChanged { access_state }` — переход `Vault.access_state`
- `LinksInvalidated { affected_paths }` — от graph-модуля, когда набор битых ссылок
  меняется (FR-030)

Источник события (другое окно того же приложения или сторонняя программа) не
различается на уровне этого типа — оба обрабатываются одинаково (FR-034, Clarifications
Q1).
