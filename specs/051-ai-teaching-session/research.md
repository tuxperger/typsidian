# Research: Сессия урока с ИИ-учителем

## §1. Файл урока

**Decision**: урок — файл vault с расширением `.lesson`, JSON Lines: первая строка — шапка
(цель, язык, дата, версия формата), дальше события по одному на строку, только дописываются.
Новый вид файла `FileKind::Lesson`: виден в дереве, открывается вкладкой урока, как доска.
По умолчанию уроки создаются в папке «Уроки» (`lessons_folder` в настройках ИИ 050).

**Rationale**: дописывание строки не переписывает прежнее — сбой посреди записи портит не
больше последней строки, а нечитаемая строка пропускается (как журнал 050). Текст читается
любым редактором (FR-006). Конституция требует, чтобы записи модели были файлами vault.

**Alternatives**: документ Typst — красиво, но восстановление вопросов, уверенности и событий
потребовало бы разбора Typst и держало бы два источника истины; цельный JSON — перезапись
всего файла на каждом шаге.

## §2. Учитель и инструменты

**Decision**: один запрос к модели — «ход». Учитель отвечает текстом и может вызвать
инструменты:

- `ask_question { question, choices? }` — вопрос пользователю; ход заканчивается ожиданием
  ответа;
- `read_note { path }` — чтение заметки через `check_access_in` 050; результат (текст или
  отказ) записывается событием и уходит модели следующим ходом без участия пользователя.

Решение «продолжать или ждать пользователя» принимает ядро (`finish_turn` → `Next`); оболочки
только повторяют вызов. Предел — 4 автоматических продолжения на один ответ пользователя:
модель, читающая заметку за заметкой, не тратит деньги без конца.

**Alternatives**: разбор вопросов из текста по разметке — хрупко; инструменты есть у
Anthropic, OpenAI и у большинства совместимых серверов. Сервер без инструментов: вопрос
приходит обычным текстом (Edge Case спеки) и показывается как реплика учителя.

## §3. Потоковая выдача

**Decision**: ядро разбирает поток событий ответа (`stream: true`; события Anthropic и
совместимого протокола) инкрементально в `ai/stream.rs` на обоих таргетах. Полученный текст
копится в памяти процесса по ключу `vault_id/request_id`; интерфейс опрашивает его командой
`ai_lesson_progress` раз в 150 мс.

**Rationale**: опрос одинаково работает в Tauri, через HTTP сервера и в wasm. Каналы Tauri,
поток с сервера и обратные вызовы в JS — три разных механизма ради одной задачи.

**Alternatives**: события Tauri + SSE сервера + колбэк wasm — отвергнуто (см. выше).

## §4. Пределы ожидания потока

**Decision**: у потокового запроса нет общего предела в 30 с (050): длинный ответ законно
идёт минутами. Предел — 30 с до начала ответа и 60 с тишины между частями; тело не больше
8 МиБ. Отмена — реестр `cancel` 050.

## §5. Порядок записи и обрыв

**Decision**:

1. Ответ пользователя дописывается в файл урока до журнала и сети (FR-007).
2. Журнал 050 получает запрос до отправки (FR-012).
3. Во время потока интерфейс раз в секунду зовёт `ai_lesson_checkpoint`: накопленный текст
   переписывается в `.typsidian/lesson-partial/<hash пути>` — маленький файл устройства, вне
   синхронизации (`derived_paths`).
4. Итог дописывает реплику учителя (целиком или оборванную, с пометкой) и удаляет
   промежуточный файл.
5. Открытие урока, где последняя строка — ответ пользователя, а промежуточный файл есть,
   дописывает из него оборванную реплику (SC-002 при закрытии приложения).

## §6. Сжатие переписки

**Decision**: перед ходом ядро оценивает объём переписки (символы / 4). Выше порога (по
умолчанию 100 тыс. единиц, поле `context_budget` в настройках ИИ) ход становится запросом
сжатия: модель получает переписку и просьбу изложить пройденное. Изложение дописывается
событием `Summary`; дальше модель получает шапку, изложение и события после него. Полная
переписка остаётся в файле (FR-009).

## §7. Инструкции учителя

**Decision**: встроенный текст на русском и английском в `ai/lesson/prompt.rs`; язык общения —
поле шапки, по умолчанию язык интерфейса, смена — событие `Language`. Правка инструкций — 059.

## §8. Стоимость

**Decision**: объём и цена каждого хода — из последнего события потока; сохраняются в
событии реплики. Счётчик урока — сумма. Правила 050 FR-014: неизвестная цена — «неизвестно».

## §9. Список уроков

**Decision**: все файлы `.lesson` vault из индекса файлов, не только папка «Уроки»: урок,
перенесённый в другую папку, остаётся уроком. Сводка берётся из шапки и последних событий.

## §10. Один урок в двух местах

**Decision**: вкладка урока одна на путь (как доска). Для двух окон, двух устройств и
синхронизации — оптимистическая проверка: команда хода передаёт число событий, которое
видит интерфейс; несовпадение — отказ `LessonChanged`, интерфейс перечитывает урок.
Это заменяет «второй вкладки только для чтения» из Edge Cases: вторая вкладка не открывается,
а второе окно получает отказ и свежую переписку.

## §11. Серверный режим

**Decision**: команды `ai_lesson_*` — в `allowed.rs`; сетевая `ai_lesson_answer` — в
`AI_NETWORK_COMMANDS` (предел 050 L2); `vault_id` подставляет сервер. Тот же опрос.

## §12. Чтение заметок

**Decision**: явное прикрепление при создании урока и вызов `read_note` проходят одну
проверку `check_access_in`. Текст заметки — до 100 тыс. символов, длиннее — обрезается с
пометкой. Событие `NoteRead { path, by_user, outcome }` в файле; сам текст в урок не
пишется — он есть в заметке и в журнале 050.

## §13. Принцип I в wasm

**Decision**: в wasm цикл «начать — отправить — завершить» крутит `vault-client-web.ts`, как
пробный запрос 050, но каждое решение (продолжать, ждать, сжимать) возвращает ядро.

## §14. Ревью безопасности (T030)

`security-review-agent`, 2026-11-02: CRITICAL нет. Исправляется (T032–T045):

- **H1 — ключ на неодобренный адрес между ходами.** Хост проверял одобрение адреса и ключ
  один раз, а `begin_turn` на каждом ходу перечитывал `ai.json`: настройки, сменённые
  синхронизацией посреди цикла, отправили бы ключ прежнего подключения на новый адрес
  (регрессия M1 050). Решение: проверенный снимок подключения передаётся в каждый ход;
  `send_turn` отказывает, если провайдер или адрес хода не совпадают со снимком.
- **M1** — запись урока не идёт через символические ссылки (`crosses_symlink`, `is_symlink`),
  свободное имя выбирается по существованию, а не по ошибке чтения.
- **M2** — `lessons_folder` и `context_budget` нормализуются при чтении настроек, не только
  при сохранении (служебная папка, 0, огромные значения).
- **M3** — `read_note` и прикрепление: только заметки (`classify == Note`) и текстовые файлы
  с пределом размера по метаданным до чтения; предел размера файла урока.
- **M4** — предел числа (10) и суммарного объёма прикреплённых заметок, пути сравниваются
  после нормализации, `by_user` принимается только из начальных событий урока.
- **M5** — разбор потока линейный (смещение просканированного, предел строки SSE,
  `reading()` по завершению блока, дельта в буфер), общий предел потока 10 мин, на сервере —
  предел одновременных запросов к моделям на аккаунт.
- **M6** — цикл хода на хосте доживает до `finish_turn` независимо от соединения (отдельная
  задача) либо снимает буфер и слот отмены при сбросе; уборка забытых буферов.
- **L1** — слот отмены занимается до буфера и записи ответа; **L2** — отмена действует на
  весь цикл; **L3** — `checkpoint` берёт путь из буфера хода, пути нормализуются.
- **L5** — дописывание урока атомарно на native (`write_atomically`), уроки не разбираются
  как Typst для таблицы ссылок; **L6** — команды принимают только пути вида `Lesson` вне
  служебного места; **L7** — имя из цели без зарезервированных имён Windows и символов
  форматирования; **L8** — вопрос: до 5 вариантов, пределы длины.

Не исправляется в 051:

- **L4** — промежуточный файл может приехать через Syncthing без правила `.stignore`; его
  закрывает существующий отчёт «неполные правила» через `derived_paths` (проверить в T045).
  Текст из него в модель не уходит.
- **L9** — `.stversions/` не закрыт `check_access` (было до 051) — исправляется здесь же
  (T044), так как `read_note` расширил поверхность.
- Инъекция инструкций через текст заметок и файла урока — ожидаемый риск обучения с ИИ;
  граница — запрещённые папки. Интерфейс показывает текст учителя как текст, не HTML.

**Как исправлено (T032–T046)** — расхождения с решениями выше:

- H1: тип `ai::client::Connection` (провайдер и базовый адрес); `begin_*`/`send_*` у урока и
  пробного запроса 050 принимают `&Connection`, отказ — `EndpointNotApproved`. В wasm
  «начать» проверяет настройки под одной блокировкой, «отправить» берёт снимок по самому
  запросу (`Connection::of_request`): сигнатура одна, смена настроек между вызовами клиента
  невозможна.
- M6: выбран вариант «снимать при сбросе»: `cancel::Cycle`, `partial::BufferGuard`, слот
  отмены (`Drop`) и место аккаунта на сервере освобождаются при обрыве соединения; полученный
  текст в этом случае берётся из промежуточного файла устройства (`checkpoint`), а не
  дописывается сразу.
- M3: слишком большая и не-`.typ` заметка отвечает `Denied` — нового исхода в `NoteOutcome` нет.
- M4: заметки сверх десяти при создании урока не прикрепляются (молча).
- L3: `checkpoint` сохранил параметр пути ради совместимости вызова; путь для записи берётся
  из буфера хода, чужой путь — ничего не пишется.
- L5: уроки не попадают в `record_links` (ссылки у них и раньше извлекались только из `.typ`).
- L2: `Cycle` ведёт хост; в wasm цикл крутит клиент и сам прекращает его при отмене.

## §15. Расхождения вёрстки с макетом (T017, T022)

**Decision** — намеренные, обратно под макет не переделываются без вопроса:

- Язык учителя и «Завершить урок» — полоса под шапкой, а не конец ленты: всегда под рукой
  при прокрутке (артборд I не задаёт место однозначно).
- Метка вкладки — тег «урок» в стиле тега доски вместо «◆».
- Текст учителя — как есть, с переносами, без разметки: показывать разметку модели как
  HTML нельзя (§14), а свой разбор разметки — отдельная задача.
- Отметка сжатия считает события, а не шаги: шагов у урока без плана 052 нет.
- Подпись сочетания — `Ctrl+Enter` / `⌘+Enter` по платформе.
- Дата в списке — формат `Intl` языка интерфейса.
- Состояние «ждёт ответа» / «ответ оборван» в списке требует признака ожидания в
  `LessonSummary` — добавляется в ядро (T046).
