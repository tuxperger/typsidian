# Quickstart: проверка вложений

Все команды — из корня репозитория внутри `nix develop` (cargo-команды строго по одной).
Если wasm-тесты падают «http status: 404» — запускать через `env -u LD_LIBRARY_PATH`.

## Ядро

```sh
nix develop --command cargo test -p typsidian-core --lib attachments
nix develop --command cargo test -p typsidian-core --lib ignore_match
nix develop --command cargo test -p typsidian-core --test attachments_native --test vault_native --test settings_native --test preview_native
nix develop --command cargo build -p typsidian-core --target wasm32-unknown-unknown
nix develop --command bash -c "cd packages/core && wasm-pack test --headless --chrome -- --test attachments_wasm --test vault_wasm --test settings_wasm --test preview_wasm"
nix develop --command cargo test -p typsidian-shell
```

Что доказывают тесты:
- `attachment_cases` (оба таргета), правила: сигнатуры пяти видов и отказ для PDF, HEIC,
  пустого файла и текста (FR-006, FR-007); имя из заметки и момента, очистка и замена
  расширения (FR-012); папка назначения и путь вставки для обоих размещений и заметок
  разной вложенности (FR-001, FR-016); правка текста — в точке и построчно (FR-005).
- `attachment_cases`, пачка: запись в пустую папку; занятое имя даёт `-2`, прежний файл
  цел байт в байт (FR-009, SC-003); то же содержимое в папке назначения и то же имя с тем
  же содержимым в другой папке дают `Reused` без нового файла (FR-010, FR-011, SC-004);
  неподдерживаемый вид не записан (FR-006); vault только на чтение — `Refused`, отказ
  записи — `Failed` без остатков (FR-014, FR-024); файл больше 20 МБ ждёт подтверждения
  (FR-013); отмена оставляет записанное и отменяет остальное (FR-023); запрещённые переходы
  не меняют состояние.
- `ignore_match` (модульные, оба таргета через `attachment_cases`): папка, исключённая
  правилом, родителем, отменённая `!`, порядок для двух видов файлов (FR-020).
- `vault_settings_cases`: круговая запись двух полей; негодное название отклонено, файл не
  тронут (FR-017, FR-018).
- `vault_native` / `vault_wasm`: `list_images` на настоящих бэкендах даёт один и тот же
  список (FR-025).
- `preview_cases`: изображение больше 10 МБ собирается в предпросмотре (FR-008).

## Сценарий в браузере (web)

```sh
nix develop -c pnpm dev          # в фоне
nix develop -c node scripts/dev/browser.mjs http://localhost:3000 \
    scripts/dev/scenarios/attachments.mjs --opfs-vault --shot <scratchpad>/attachments.png
```

Сценарий создаёт заметку, подаёт синтетические `paste` и `drop` с файлами, проверяет файлы
в хранилище и текст, снимает экраны для сверки с макетом 1a–1c. В консоли не должно быть
ошибок.

## Ручная проверка (web и desktop)

1. **Буфер** (US1). Снять снимок экрана, вставить в `Диссертация/Результаты.typ`. Появится
   `Диссертация/attachments/Результаты-<дата>-<время>.png`, в тексте — `#image("attachments/…")`,
   каретка за скобкой, картинка в предпросмотре не позже чем через 2 с (SC-001). `Ctrl+Z` —
   запись исчезла, файл остался; второй `Ctrl+Z` откатывает предыдущую правку, а не весь
   текст.
2. **Текст не сломан**. Скопировать абзац из текстового редактора и вставить — вставился
   текст. Скопировать картинку из Writer (в буфере и текст, и картинка) — вставился текст.
3. **Перетаскивание** (US2). Тащить три картинки над редактором: видна линия на границе
   строки и подпись «3 изображения — сюда, строка N», рамка редактора подсвечена. Бросить в
   середину заметки: три записи на своих строках в порядке перетаскивания; один `Ctrl+Z`
   убирает все три.
4. **Повтор и коллизия**. Бросить ту же картинку ещё раз — нового файла нет, вставка ведёт
   на прежний. Бросить другую картинку с тем же именем — появился `<имя>-2.<расш>`, первая
   цела.
5. **Уже в vault**. Перетащить из файлового менеджера картинку, лежащую в другой папке
   vault, — копии нет, путь во вставке с `../`.
6. **Смешанная пачка**. Бросить две картинки, PDF и `.xlsx`: «Вставлено 2 из 4», PDF и
   таблица названы пропущенными, в vault их нет.
7. **Много файлов**. Бросить 50 картинок: панель «Копирую вложения: N из 50», печатать в
   редакторе можно; «Отменить» на середине — вставлены уже скопированные, остальных нет,
   обрезанных файлов нет (`find <vault> -size 0` пуст).
8. **Большой файл**. Вставить картинку 34 МБ: диалог с именем и размером; «Отмена» — ни
   файла, ни текста; «Вставить» — файл скопирован, предпросмотр показывает.
9. **Команда**. `Ctrl+Alt+I`, палитра и меню вставки открывают выбор файлов; результат как
   у перетаскивания к каретке. Открыть доску и редактор правил — вставка картинки там
   ничего не делает, вставка текста работает как раньше.
10. **Настройка** (US3). Настройки → Vault → «Вложения» → «В одну папку vault», название
    `файлы`. Вставить в заметку из вложенной папки: файл в `файлы/`, путь `../файлы/…`.
    Старые вложения на месте и показываются. Название `../картинки` и `.typsidian` —
    отказ с причиной под полем.
11. **Только чтение**. Открыть vault без права записи: вставка картинки даёт «Изображение
    не вставлено… Текст заметки не изменён», пункт палитры недоступен с причиной.
12. **Правила**. Добавить `attachments/` в `.gitignore`, вставить картинку: файл сохранён,
    предупреждение показано, «Открыть правила» открывает редактор правил.
13. **Ссылка**. Перетащить картинку со страницы браузера так, чтобы файла в перетаскивании
    не было: сообщение о ссылке, текст не изменён, сети не было.
14. **Другое устройство** (SC-006). Открыть тот же vault в другой оболочке: вставка
    показывается без правки путей; настройка размещения та же.

## Android (US4)

15. В открытой заметке «＋» → шторка «Вставить изображение». «Снять фото» → снимок →
    `attachments/<заметка>-<дата>-<время>.jpg` и запись в месте каретки. Отмена съёмки —
    текст не изменён.
16. «Выбрать из галереи» — несколько снимков, записи построчно. «Выбрать файл…» — то же
    через системный выбор.
17. На web и desktop в действиях вставки нет «Снять фото» и «галереи».

Шаги 15–16 требуют устройства или эмулятора с камерой. Без них фиксируются как **«не
проверено»**, а не как пройденные (research.md §17). iOS-оболочки нет — не проверяется.
