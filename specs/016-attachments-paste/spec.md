# Feature Specification: Вложения из буфера и перетаскиванием

**Feature Branch**: `016-attachments-paste`

**Created**: 2026-10-10

**Status**: Draft

**Priority**: P2

**Summary**: Картинка вставляется в заметку из буфера обмена, перетаскиванием или с камеры: файл сам ложится в папку вложений, а в тексте появляется готовая вставка изображения.

**Input**: User description: "Вложения из буфера и перетаскиванием. Картинка вставляется из буфера или бросается в редактор, файл ложится в папку вложений, в текст подставляется #image(...). На Android — снимок с камеры."

## Термины

- **Вложение** — файл изображения, лежащий в vault и вставленный в заметку.
- **Папка вложений** — место в vault, куда приложение кладёт новые вложения; задаётся
  настройкой vault.
- **Вставка изображения** — запись в тексте заметки, показывающая вложение в документе.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Вставить картинку из буфера обмена (Priority: P1)

Пользователь делает снимок экрана или копирует картинку в другой программе, ставит
каретку в заметке и вставляет. Приложение сохраняет картинку файлом в папку вложений и
подставляет в текст вставку изображения; предпросмотр показывает картинку.

**Why this priority**: Самый частый способ: сейчас для этого нужно сохранить файл
вручную, перенести в папку vault и написать путь руками.

**Independent Test**: Скопировать снимок экрана, вставить в заметку; убедиться, что в
папке вложений появился файл, в тексте — вставка с путём к нему, предпросмотр показывает
картинку.

**Acceptance Scenarios**:

1. **Given** в буфере картинка, каретка в заметке, **When** пользователь вставляет,
   **Then** в папке вложений появляется файл с этой картинкой, в месте каретки — вставка
   изображения с путём к нему, каретка стоит после вставки.
2. **Given** вставка сделана, **When** показан предпросмотр, **Then** картинка видна в
   документе без дополнительных действий.
3. **Given** в буфере и текст, и картинка (копирование из текстового редактора),
   **When** пользователь вставляет, **Then** вставляется текст, как и раньше.
4. **Given** в буфере текст, **When** пользователь вставляет, **Then** поведение вставки
   текста не изменилось.
5. **Given** вставка картинки сделана, **When** пользователь отменяет действие в
   редакторе, **Then** запись из текста исчезает; файл остаётся в папке вложений.
6. **Given** файл сохранить не удалось (нет места, vault только на чтение), **When**
   пользователь вставляет, **Then** текст заметки не меняется, причина названа.

### User Story 2 - Перетащить файлы в редактор (Priority: P2)

Пользователь перетаскивает один или несколько файлов изображений из файлового менеджера
в редактор. Каждый копируется в папку вложений, вставки появляются в том месте, куда
файлы брошены. На устройствах без перетаскивания то же делает действие «Вставить
изображение…» с выбором файлов.

**Why this priority**: Второй по частоте способ и единственный для уже существующих
файлов.

**Independent Test**: Перетащить три картинки в середину заметки; убедиться, что три
файла в папке вложений и три вставки в месте броска, в порядке перетаскивания.

**Acceptance Scenarios**:

1. **Given** пользователь тащит файл изображения над редактором, **When** указатель над
   текстом, **Then** видно место, куда попадёт вставка.
2. **Given** брошено несколько изображений, **When** копирование завершено, **Then**
   вставки стоят в месте броска, каждая на своей строке, одной отменяемой правкой.
3. **Given** брошен файл, который уже лежит в vault, **When** он обрабатывается,
   **Then** копия не создаётся, вставка указывает на существующий файл.
4. **Given** среди брошенных есть файл неподдерживаемого вида, **When** обработка
   завершена, **Then** поддерживаемые вставлены, о пропущенных сообщено поимённо.
5. **Given** пользователь выбирает «Вставить изображение…», **When** выбирает файлы в
   системном диалоге, **Then** результат тот же, что при перетаскивании к каретке.

### User Story 3 - Решить, где лежат вложения (Priority: P2)

Пользователь в настройках vault выбирает, куда класть новые вложения: в подпапку рядом
с заметкой или в одну общую папку vault, и как её назвать. Настройка едет вместе с vault.

**Why this priority**: Vault — папка пользователя (принцип VI); порядок в ней он
определяет сам, и менять его после сотни вставок дорого.

**Independent Test**: Выбрать общую папку `файлы`, вставить картинку в заметку из
вложенной папки; убедиться, что файл лёг в `файлы` в корне vault, а путь во вставке
ведёт к нему.

**Acceptance Scenarios**:

1. **Given** настройка по умолчанию, **When** пользователь вставляет картинку,
   **Then** файл ложится в подпапку вложений рядом с заметкой.
2. **Given** выбрана общая папка vault, **When** пользователь вставляет картинку в
   заметку любой вложенности, **Then** файл ложится в общую папку, а путь во вставке
   верен для этой заметки.
3. **Given** настройка изменена, **When** пользователь смотрит на старые вложения,
   **Then** они остались на местах и по-прежнему показываются.
4. **Given** vault открыт на другом устройстве, **When** там вставляют картинку,
   **Then** действует та же настройка.

### User Story 4 - Снимок с камеры на телефоне (Priority: P3)

На Android пользователь выбирает «Снять фото», делает снимок — он становится вложением
и вставкой в заметке, как картинка из буфера. Там же доступен выбор из галереи.

**Why this priority**: Расширяет охват на мобильный сценарий (конспект, доска в
аудитории); остальная фича работает без него.

**Independent Test**: На Android-устройстве в открытой заметке выбрать «Снять фото»,
сделать снимок; убедиться, что файл в папке вложений и вставка в тексте.

**Acceptance Scenarios**:

1. **Given** заметка открыта на телефоне, **When** пользователь делает снимок через
   действие приложения, **Then** снимок сохранён вложением и вставлен в месте каретки.
2. **Given** пользователь отменил съёмку или не дал разрешения на камеру, **When**
   возвращается в заметку, **Then** текст не изменён, при отказе в разрешении названа
   причина и способ её устранить.
3. **Given** устройство без камеры или оболочка без доступа к ней, **When** пользователь
   смотрит на действия вставки, **Then** «Снять фото» отсутствует, выбор файла доступен.

### Edge Cases

- **Имя уже занято другим файлом**: новое вложение получает отличающееся имя; существующий
  файл не перезаписывается никогда.
- **Тот же самый файл вставляется повторно** (совпадает содержимое): второй файл не
  создаётся, вставка указывает на уже лежащий.
- **Очень большая картинка**: сверх порога (20 МБ) приложение спрашивает подтверждение,
  называя размер; уменьшать или пережимать картинку само оно не берётся.
- **Вставка в несохранённую, только что созданную заметку**: вложение кладётся
  относительно того места, где заметка лежит в vault; заметка всегда имеет путь.
- **Каретка в доске (002), в файле правил (012) или в ином нетекстовом редакторе**:
  вставка вложений недоступна, поведение вставки там не меняется.
- **Каретка внутри кода или формулы**: вставка делается как есть — пользователь решает,
  уместна ли она; отмена возвращает текст.
- **Папка вложений исключена правилами истории или доставки (012)**: вложение
  сохраняется, а пользователь предупреждён, что оно не попадёт в историю или на другие
  устройства.
- **Имя папки вложений в настройке недопустимо** (пустое, с выходом за пределы vault,
  служебная папка 006): настройка не принимается, причина названа.
- **Заметку с вложениями переместили в другую папку**: вставки могут перестать
  показываться — исправление путей при перемещении вне скоупа, как и для ссылок (001).
- **Много файлов сразу (50)**: копирование идёт с прогрессом, отменяется, редактор не
  блокируется; при отмене уже скопированные файлы остаются и вставлены, остальные — нет
  (принцип X).
- **Web-оболочка без доступа к буферу изображений**: вставка из буфера работает там, где
  браузер отдаёт картинку при обычной вставке; выбор файла и перетаскивание доступны
  всегда.
- **Нет сети**: всё работает; изображение, перетащенное из браузера ссылкой, без сети не
  скачивается — сообщается причина.

## Requirements *(mandatory)*

### Functional Requirements

**Вставка**

- **FR-001**: При вставке из буфера, содержащего изображение без текста, система MUST
  сохранять изображение файлом в папку вложений и подставлять в место каретки вставку
  изображения с путём, верным для этой заметки.
- **FR-002**: Если в буфере есть текст, вставка MUST вести себя как прежде.
- **FR-003**: Система MUST принимать файлы изображений, перетащенные в редактор,
  показывать место будущей вставки во время перетаскивания и вставлять их в месте броска.
- **FR-004**: Система MUST давать действие «Вставить изображение…» с выбором одного или
  нескольких файлов — из меню вставки, палитры команд и с клавиатуры.
- **FR-005**: Вставка одного действия пользователя, сколько бы файлов в ней ни было,
  MUST отменяться в редакторе одним шагом; файлы при отмене остаются в vault.
- **FR-006**: Поддерживаемые виды MUST включать PNG, JPEG, GIF, SVG и WebP; файлы иных
  видов MUST пропускаться с поимённым сообщением и MUST NOT копироваться в vault.
- **FR-007**: Вид файла MUST определяться по содержимому, а не только по расширению.
- **FR-008**: После вставки предпросмотр MUST показывать изображение без дополнительных
  действий пользователя.

**Файлы вложений**

- **FR-009**: Система MUST NOT перезаписывать существующие файлы: при занятом имени
  новое вложение получает отличающееся.
- **FR-010**: Если в папке назначения уже лежит файл с тем же содержимым, система
  MUST NOT создавать второй и MUST ссылаться на существующий.
- **FR-011**: Файл, уже лежащий в vault, при перетаскивании MUST NOT копироваться.
- **FR-012**: Имя вложения из буфера или камеры MUST быть читаемым и содержать название
  заметки и момент вставки; имя перетащенного или выбранного файла сохраняется.
- **FR-013**: Для изображения больше 20 МБ система MUST запрашивать подтверждение с
  указанием размера.
- **FR-014**: Если файл сохранить не удалось, текст заметки MUST NOT изменяться, а
  причина MUST быть названа; частично записанных файлов оставаться не должно.
- **FR-015**: Вложения — обычные файлы vault: они MUST быть видны во внешних программах,
  попадать в историю и доставку (011) на общих основаниях.

**Папка вложений**

- **FR-016**: Пользователь MUST иметь возможность выбрать место новых вложений: подпапка
  рядом с заметкой (по умолчанию) или одна папка в vault, — и её название.
- **FR-017**: Настройка MUST храниться вместе с vault (006 User Story 4) и действовать на
  всех устройствах, где он открыт.
- **FR-018**: Система MUST отклонять недопустимое название папки (пустое, ведущее за
  пределы vault, совпадающее со служебным местом 006) с названной причиной.
- **FR-019**: Смена настройки MUST NOT перемещать и изменять существующие вложения.
- **FR-020**: Если папка вложений исключена правилами истории или доставки, система MUST
  предупреждать об этом при вставке.

**Камера и устройства**

- **FR-021**: В мобильной оболочке система MUST давать действия «Снять фото» и «Выбрать
  из галереи», результат которых обрабатывается как вставка изображения.
- **FR-022**: При отказе в разрешении или отмене съёмки текст MUST NOT изменяться; при
  отказе MUST быть названа причина. Действие, недоступное в оболочке, MUST NOT
  показываться.

**Общее**

- **FR-023**: Копирование нескольких файлов MUST NOT блокировать редактор, MUST
  показывать прогресс и MUST быть отменяемым с предсказуемым итогом (принцип X).
- **FR-024**: Вставка вложений MUST быть недоступна в vault только на чтение и в
  нетекстовых редакторах, с названной причиной в первом случае.
- **FR-025**: Правила размещения, именования, сопоставления содержимого и построения
  пути MUST давать одинаковый результат в web-, desktop- и мобильной оболочке
  (принцип II).
- **FR-026**: Все тексты MUST браться из переводов (010).

### Key Entities

- **Вложение**: файл изображения в vault — имя, вид, размер, содержимое.
- **Настройка вложений vault**: способ размещения (рядом с заметкой / общая папка) и
  название папки.
- **Вставка изображения**: запись в тексте заметки с путём к вложению.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: От нажатия «вставить» до картинки в предпросмотре проходит не больше
  2 секунд для снимка экрана обычного размера (до 5 МБ).
- **SC-002**: Вставка картинки из буфера требует одного действия пользователя вместо
  четырёх (сохранить, перенести, написать вставку, указать путь).
- **SC-003**: Ни одна вставка не перезаписывает существующий файл — в 100 % случаев.
- **SC-004**: Повторная вставка того же изображения не увеличивает число файлов в vault.
- **SC-005**: Во время копирования 50 файлов задержка отклика редактора на нажатие
  клавиши остаётся прежней, а отмена срабатывает не позже чем через 1 секунду.
- **SC-006**: Вставка, сделанная на одном устройстве, показывается на другом после
  доставки vault без правки путей.

## Вне скоупа

- Вложения не-изображений (PDF, архивы, звук, видео).
- Уменьшение, обрезка, пережатие и переименование изображений.
- Поиск и удаление вложений, на которые никто не ссылается.
- Исправление путей вложений при перемещении заметки.
- Скачивание изображений по адресу из сети как отдельное действие.
- Параметры вставки (ширина, подпись) — их правит форма 008.

## Assumptions

- Зависит от 001 (файлы vault, vault только на чтение, внешние изменения), 005
  (предпросмотр изображений из vault), 006 (настройки, едущие с vault; служебные места),
  008 (форма параметров изображения), 010 (тексты).
- По умолчанию — подпапка рядом с заметкой: путь во вставке короткий и переживает
  перенос папки с заметкой целиком.
- Название папки по умолчанию определяется при планировании и одинаково для всех языков
  интерфейса — оно часть содержимого vault, а не текст интерфейса.
- Порог 20 МБ настройкой не делается.
- Вид индикатора места вставки, прогресса и раздела настроек определяет макет (скилл
  `design-typsidian`).
