# Feature Specification: Задачи из заметок

**Feature Branch**: `033-vault-tasks`

**Created**: 2026-10-21

**Status**: Implemented

**Priority**: P2

**Summary**: Все пункты-задачи из всех заметок собраны в одном списке: отметить выполненным, отфильтровать по сроку, заметке и свойствам, перейти к месту задачи.

**Input**: User description: "Задачи из заметок: чекбоксы со всего vault в одном списке с фильтрами по свойствам из 020."

## Термины

- **Задача** — пункт списка с отметкой выполнения в заметке (форма записи выбирается в плане
  так, чтобы оставаться валидным Typst и читаться без приложения).
- **Срок** — дата у задачи, записанная в её тексте.

## Clarifications

### Session 2026-10-23

Закрыто по конституции и существующим спекам, без вопроса пользователю.

- Q: Как записана задача? → A: Пункт списка с отметкой: `- [ ] текст` — не выполнена,
  `- [x] текст` — выполнена (так же у нумерованного `+`). Для Typst это обычный пункт
  списка, заметка читается без приложения. Пункт внутри кода, сырого текста или
  комментария задачей не считается.
- Q: Как записан срок? → A: Дата `ГГГГ-ММ-ДД` в тексте задачи после `📅` или `срок:`
  (`due:` — тоже). В списке срок показан отдельно, из текста задачи убран.
- Q: Где экран? → A: Окно «Задачи» из палитры, как «Состояние ссылок» (028): сверху
  фильтры, ниже список, сгруппированный по заметке или по сроку (переключатель).
  Вложенные задачи — с отступом под родительской.
- Q: Фильтры? → A: Состояние: невыполненные (по умолчанию), выполненные, все. Срок: любой,
  просроченные, на сегодня, на неделю, без срока. Папка. Условия по свойствам заметки
  строкой `ключ:значение` — тот же язык, что в поиске 020 (`тег:проект`, `статус:черновик`).
- Q: Как отметка не теряет чужих правок? → A: Отметка меняет один знак в одной строке;
  строка ищется по её тексту, а не только по номеру. Если строки с таким текстом в заметке
  уже нет — отметка не выполняется и список обновляется с объяснением.
- Q: Как быстро на 5 000 заметок? → A: Задачи собираются из индекса задач на устройстве; при
  открытии экрана перечитываются только изменившиеся заметки.
- Q: «Переключить задачу» в редакторе? → A: Команда палитры для строки под кареткой: пункт
  с отметкой — переключает её, обычный пункт списка — делает задачей.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Все задачи в одном месте (Priority: P1)

Экран «Задачи» показывает невыполненные задачи всех заметок, сгруппированные по заметке или
по сроку. Отметка выполненным прямо в списке меняет текст заметки; щелчок по задаче открывает
заметку на её строке.

**Independent Test**: 3 заметки, 10 задач — список из 10; отметка одной меняет ровно её
строку в файле.

**Acceptance Scenarios**:

1. **Given** задачи в заметках, **Then** экран показывает их с текстом, заметкой и сроком.
2. **Given** задача в списке, **When** пользователь отмечает её, **Then** отметка
   записывается в заметку (через редактор, если она открыта, 013).
3. **Given** щелчок по задаче, **Then** заметка открывается на её строке.

---

### User Story 2 - Фильтры (Priority: P2)

Фильтры: выполненные/невыполненные, просроченные, на сегодня, на неделю, папка, тег и
условия по свойствам заметки (тот же язык условий, что в 020).

### User Story 3 - Задача из любого места (Priority: P3)

В редакторе — команда «Переключить задачу» для строки под кареткой.

### Edge Cases

- Задача в коде или комментарии не считается.
- Вложенные задачи — показываются под родительской.
- Заметка изменилась на диске между показом и отметкой — отметка не теряет чужих правок.
- Vault в 5 000 заметок — список строится из индекса.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Экран MUST собирать задачи всех заметок vault.
- **FR-002**: Отметка в списке MUST менять только строку задачи в заметке.
- **FR-003**: Экран MUST фильтровать по состоянию, сроку, папке, тегу и свойствам (020).
- **FR-004**: Переход MUST открывать заметку на строке задачи.
- **FR-005**: Список MUST обновляться при изменениях vault.
- **FR-006**: Сбор задач — в ядре, из индекса (принципы I, IX).
- **FR-007**: Одинаково во всех оболочках; тексты — из переводов.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Экран задач на 5 000 заметок открывается не дольше 1 с.
- **SC-002**: Отметка задачи меняет 1 строку и 0 прочих в 100% случаев.

## Assumptions

- Зависит от 020 (свойства и язык условий), 013 (правка открытой заметки), 022 (дневные
  заметки — частый источник задач).
