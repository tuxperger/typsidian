# Research: Закладки

## 1. Где хранить

**Decision**: в настройках vault (`.typsidian/vault.json`), ключ `bookmarks` — список
записей: закладка или группа с закладками (один уровень). Разбор мягкий: негодная запись
пропускается, а не делает файл нечитаемым (как таблицы 016, 029).
**Rationale**: закладки едут с синхронизацией 011, как отметки 028 (Edge Cases); одна запись
через `write_vault_settings` на всех оболочках.

## 2. Что такое закладка

**Decision**: `{ id, name, target }`, цель — `Note { path }`, `Section { path, heading }`,
`Search { query: SearchQuery }` (тот же запрос, что у поиска 027/020), `Folder { path }`.
`id` — 12 знаков blake3 от цели и времени. Повтор — та же цель (у поиска — тот же запрос):
ответ `Exists`, без дубля.

## 3. Операции

**Decision**: модуль ядра `bookmarks`: `bookmarks_view`, `bookmark_add`, `bookmark_remove`,
`bookmark_rename`, `bookmark_move` (в группу/из группы, на позицию; группы — только на верхнем
уровне), `bookmark_group_create/rename/delete/toggle`. Каждая операция читает настройки,
меняет список, пишет и отдаёт новый вид — UI не держит своей копии правил.

## 4. Переименование и перенос

**Decision**: `move_bookmarks(backend, from, to)` зовут `rename` обоих backend и перенос 023
(`move_section_marks`) — рядом с `move_intentional_orphans` (028) и `move_snapshots` (029).
Путь заметки или папки и всё под перенесённой папкой переписываются (SC-002).

## 5. Доступность

**Decision**: вид считает при каждом показе: заметка или папка есть в списке файлов vault;
у раздела — есть ли заголовок с таким текстом (`structure`, 015). Нет цели — `Missing`; нет
заголовка — `SectionMissing` (закладка открывает заметку). Удаление ничего не пишет.

## 6. Открытие

**Decision**: UI по виду цели: заметка — `openPath`; раздел — открыть и перейти к заголовку
тем же путём, что оглавление 015; поиск — окно поиска с запросом закладки; папка — раскрыть
в дереве и выделить.
