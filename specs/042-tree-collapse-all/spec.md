# Feature Specification: Свернуть и развернуть папки разом

**Feature Branch**: `042-tree-collapse-all`

**Created**: 2026-10-27

**Status**: Implemented

**Priority**: P3

**Summary**: Папки дерева vault сворачиваются и разворачиваются разом — все сразу кнопками над деревом или папка вместе со всеми вложенными из её меню, а не по одной.

**Input**: User description: "Добавь кнопки, чтобы можно было свернуть несколько папок." Развивает 001 (дерево vault) и 023 (свёрнутость едет за перенесённой папкой).

## Clarifications

### Session 2026-10-27

- Q (закрыто по коду): Раскрывает ли дерево папки при переходе к заметке из поиска или по
  ссылке? → A: Нет, и фича этого не меняет; раскрытие под указателем есть только при
  перетаскивании (023 §FR-013).
- Q (закрыто по умолчанию): Запоминается ли свёрнутость между запусками? → A: Нет, как и
  сейчас (001); это вне фичи.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Свернуть всё дерево одним действием (Priority: P1)

В большом vault раскрыты десятки папок, и нужная заметка теряется в длинном дереве.
Пользователь одним действием над деревом сворачивает все папки и видит только верхний
уровень; вторым действием так же разом раскрывает их обратно.

**Why this priority**: сейчас папки сворачиваются только по одной — в vault с глубокой
вложенностью это десятки нажатий. Это основная просьба.

**Independent Test**: в vault с вложенными папками нажать «Свернуть все папки» — видны только
элементы верхнего уровня; «Развернуть все папки» — видно всё дерево.

**Acceptance Scenarios**:

1. **Given** дерево с раскрытыми папками на нескольких уровнях, **When** пользователь
   выбирает «Свернуть все папки», **Then** свёрнуты все папки на всех уровнях, видны только
   папки и заметки верхнего уровня.
2. **Given** свёрнутое дерево, **When** пользователь выбирает «Развернуть все папки»,
   **Then** раскрыты все папки на всех уровнях.
3. **Given** всё свёрнуто, **When** пользователь раскрывает одну папку обычным способом,
   **Then** её вложенные папки остаются свёрнутыми — раскрывается ровно один уровень.
4. **Given** в vault нет ни одной папки, **Then** действия над деревом недоступны.

---

### User Story 2 - Свернуть ветку из меню папки (Priority: P2)

Пользователь работает в одной большой папке и хочет убрать с глаз её содержимое целиком
либо, наоборот, раскрыть её до самого дна, не трогая остальное дерево.

**Why this priority**: точечное дополнение к US1 для больших веток; без него US1 всё равно
закрывает основную просьбу.

**Independent Test**: в меню папки с подпапками выбрать «Развернуть вложенные» — раскрыты
папка и все её подпапки, прочие папки дерева не изменились; «Свернуть вложенные» — свёрнуты
папка и все её подпапки.

**Acceptance Scenarios**:

1. **Given** папка с подпапками на нескольких уровнях, **When** пользователь выбирает в её
   меню «Развернуть вложенные», **Then** раскрыты сама папка и все папки внутри неё на всех
   уровнях; свёрнутость остальных папок дерева не меняется.
2. **Given** та же папка, **When** пользователь выбирает «Свернуть вложенные», **Then**
   свёрнуты сама папка и все папки внутри неё; при последующем раскрытии самой папки её
   подпапки показаны свёрнутыми.
3. **Given** папка без подпапок, **Then** пункты меню для ветки не показываются — для неё
   достаточно обычного сворачивания.

### Edge Cases

- Открытая сейчас заметка оказывается внутри свёрнутой папки: заметка остаётся открытой в
  редакторе, дерево просто её не показывает.
- Новая папка, появившаяся после «Свернуть все папки» (создана или пришла извне), видна в
  своём родителе в обычном для новой папки состоянии — раскрытой.
- Перенос свёрнутой папки сохраняет её свёрнутость и свёрнутость вложенных (023).
- Переход к заметке из поиска, ссылки или вкладки папки дерева не раскрывает — как и до
  фичи; заметка открывается в редакторе. При перетаскивании свёрнутая папка под указателем
  раскрывается, как в 023 §FR-013.
- Только чтение (vault недоступен на запись) действия сворачивания не ограничивает: они не
  меняют файлов.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Над деревом vault MUST быть действие «Свернуть все папки», сворачивающее все
  папки дерева на всех уровнях.
- **FR-002**: Над деревом vault MUST быть действие «Развернуть все папки», раскрывающее все
  папки дерева на всех уровнях.
- **FR-003**: В меню папки, у которой есть вложенные папки, MUST быть действия «Свернуть
  вложенные» и «Развернуть вложенные», меняющие свёрнутость самой папки и всех папок внутри
  неё и только их.
- **FR-004**: Раскрытие одной папки обычным способом MUST раскрывать ровно её, не меняя
  свёрнутости вложенных папок.
- **FR-005**: Действия над деревом MUST быть недоступны, когда в дереве нет папок; пункты
  ветки MUST NOT показываться у папки без вложенных папок.
- **FR-006**: Действия MUST NOT менять ни одного файла vault и ничего не открывать и не
  закрывать в редакторе.
- **FR-007**: Действия над деревом MUST быть доступны с клавиатуры и иметь доступные
  названия для программ чтения с экрана; у кнопок без подписи MUST быть всплывающая
  подсказка.
- **FR-008**: Все тексты действий MUST быть на языке интерфейса (010).

### Key Entities

- **Свёрнутость папки** — показывает ли дерево содержимое папки; принадлежит показу дерева,
  а не vault, и в файлы не пишется.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Свернуть или развернуть всё дерево — одно действие независимо от числа папок.
- **SC-002**: В vault на 500 папок результат «Свернуть все папки» виден не позже чем через
  0,2 секунды; «Развернуть все папки» — не позже чем через 0,5 секунды: это одна отрисовка
  всего дерева, та же, что при открытии такого vault (research.md, Decision 4).
- **SC-003**: После «Свернуть все папки» в дереве видны только элементы верхнего уровня —
  в 100% проверок.

## Assumptions

- Свёрнутость между запусками приложения не запоминается — как и сейчас (001); это вне фичи.
- Кнопки стоят в строке подписи дерева «Vault»; их вид определяет макет.
- Бизнес-логики в ядре не появляется: свёрнутость — состояние показа дерева, а перечень
  папок дерево уже знает.
