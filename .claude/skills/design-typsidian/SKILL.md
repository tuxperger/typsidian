# Макет в Claude Design

Запрос пользователя: `$ARGUMENTS`

**Правило проекта.** Фича с интерфейсом идёт в три шага: придумать функционал →
нарисовать его в Claude Design → верстать по этому макету. Макет — источник истины
для вёрстки; словесное описание из диалога им не является. Фиче без интерфейса
(чистое ядро, сборка, скрипты) макет не нужен — в Summary `plan.md` пишется
«Макет — не требуется: <причина>».

## Где что лежит

| Что | Где |
| --- | --- |
| Проект Claude Design | «Typsidian: Typst Editor Design», `b7a3b1f6-608f-403d-8c07-8101d15dce66` |
| Файлы макетов в проекте | `*.dc.html`, по группам экранов (пример: `Typsidian Утилиты.dc.html`, экран Export) |
| Дизайн-система | «Спецформа Design System», `83034930-0534-464a-8231-1ccaf855bba0`, привязана к проекту макетов |
| Её копия в коде | `ui/src/styles/tokens/{colors,typography,spacing,elevation}.css` — дословная, построчно сверяемая |
| Тёмный контекст приложения | `ui/src/styles/app.css` переопределяет семантические алиасы токенов |
| Ссылка на макет фичи | `specs/NNN-…/plan.md`, абзац «Макет — …» в Summary |
| Намеренные расхождения | `specs/NNN-…/research.md`, отдельным Decision |

## Чем рисовать

MCP-сервера у Claude Design нет. Инструменты — встроенные команды Claude Code:

| Команда | Что делает | Кто запускает |
| --- | --- | --- |
| `/design <бриф>` | макеты экранов артбордами на одном холсте, публикуются как артефакт Claude Design | ты, через Skill — если скилл `design` есть в списке сессии |
| `/design-login` | авторизация доступа к Claude Design для `DesignSync` | только пользователь |
| `/design-sync` | выгрузка React-компонентов репозитория в дизайн-систему; экраны не рисует | только пользователь |

Рисуешь сам, без вопроса «нарисовать?». Чем — выбирается по тому, что есть в
сессии, а не по предположению:

1. **Скилл `design` есть в списке скиллов сессии** → вызови его через Skill с
   брифом. Результат — артефакт Claude Design.
2. **Скилла `design` нет** (шаблон Design не включён на аккаунте claude.ai или
   недоступен сессии) → не останавливайся: свёрстай макет HTML-страницей на
   токенах проекта и опубликуй инструментом Artifact (скилл `artifact-design`).
   В отчёте пользователю скажи прямо, что это временный макет, а не Claude Design,
   и приложи готовый бриф одной командой `/design …` — чтобы он мог перерисовать
   его в Claude Design сам. В `plan.md` такой макет помечается словом «временный».

Верстать «по описанию», минуя оба пути, нельзя.

## Когда вызывается

- **Перед планом** — хук `before_plan` в `.specify/extensions.yml` зовёт этот скилл
  в начале `/speckit-plan`, обязательным шагом.
- **Перед вёрсткой** — хук `.claude/hooks/design-gate.sh` запрашивает подтверждение
  на правку `*.tsx` и `*.css` в `ui/` и `apps/`, пока в `plan.md` активной фичи нет
  заполненной строки «Макет — …». Действует с фичи 013; выключатель —
  `TYPSIDIAN_DESIGN_GATE=off`.
- **Вне фичи** — когда пользователь просит придумать или показать экран: рисуй
  макет, а не описывай его словами.

## Порядок для фичи

1. **Функционал.** Придумываешь сам и фиксируешь в `spec.md` (`/speckit-specify`,
   `/speckit-clarify`): сценарии, состояния, что видит пользователь. Макет рисуется
   по спеке, а не вместо неё.
2. **Бриф.** Для каждого экрана: назначение, содержимое настоящими данными (имена
   файлов vault, тексты на русском), состояния — пусто, загрузка, ошибка, длинный
   список, узкая ширина. В брифе назвать дизайн-систему «Спецформа», тёмный
   контекст и соседние уже свёрстанные экраны, чтобы новый не выпадал из ряда.
3. **Рисование.** По разделу «Чем рисовать» — до `/speckit-plan`. Один холст на фичу,
   артборд на экран или состояние. Клавиатурные сочетания в макете сверить с
   `packages/core/src/settings/keybindings.rs`: занятые не рисовать.
4. **Показ.** Отдать пользователю ссылку и остановиться, если макет вводит то, чего
   нет в спеке, либо есть развилка без разумного умолчания. Иначе идти дальше.
5. **Запись.** В Summary `plan.md` — абзац по образцу `specs/009-pdf-export/plan.md`:

   ```text
   Макет — Claude Design, проект «Typsidian: Typst Editor Design»
   (`b7a3b1f6-608f-403d-8c07-8101d15dce66`), файл `<имя>.dc.html`, экран <имя>.
   ```

   Для артефакта, нарисованного через `/design`, вместо файла — его ссылка; для
   HTML-замены — «Макет — временный (не Claude Design), <ссылка>, экран <имя>».
   Строка начинается с «Макет — » с начала строки: по ней `design-gate` решает,
   можно ли верстать.
6. **Вёрстка.** На `/speckit-implement` отдать `frontend-agent` вместе со ссылкой.
   Цвета, кегли, отступы, тени — только токены из `ui/src/styles/tokens/`; значения
   из макета, которого в токенах нет, — повод сверить токены с дизайн-системой, а
   не вписать число в компонент. Тексты — из `ui/src/i18n/locales/`.
7. **Сверка.** Открыть экран в браузере (`scripts/dev/browser.mjs … --shot`) и
   сравнить снимок с артбордом: состав, порядок, состояния, отступы.

## Расхождения с макетом

- Макет изменился после вёрстки — правится код, не наоборот.
- Макет противоречит спеке, конституции или занятому сочетанию клавиш — решение
  записывается в `research.md` как Decision с причиной (образцы: `009` — `Mod+Shift+E`
  занят фичей 008; `004` — полотно редактора тёмное при любой теме).
- Записанное расхождение намеренное: обратно под макет его не переделывают без
  вопроса пользователю.
- Токены в `ui/src/styles/tokens/` — копия, а не переосмысление. Меняются только
  вслед за дизайн-системой, целиком файлом.
