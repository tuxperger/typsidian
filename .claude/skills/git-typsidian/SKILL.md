# Git в Typsidian

Дополняет скилл `git`: там общий порядок работы, здесь — конвенции этого репозитория.
Спорные места решаются в пользу этого файла.

## Устройство репозитория

- Одна ветка — `master`, remote нет, хуков нет, `gh` не установлен.
  Пользователь работает прямо в `master`: коммит туда здесь нормален, отдельная ветка —
  только если он просит или работа заведомо экспериментальная. PR-поток недоступен,
  пока не появятся remote и `gh`; предлагать `gh pr create` не надо.
- Рабочее дерево тут обычно грязное на сотню файлов — накопленные фичи Spec Kit.
  Это норма, а не повод коммитить всё разом.
- `git branch` падает: `fatal: неизвестное имя поля: commiterdate` — опечатка в
  `branch.sort=-commiterdate` в `~/.config/git/config` (глобальный, чинить только с
  разрешения; верное поле — `-committerdate`). Обход:
  `git for-each-ref --format='%(refname:short)' refs/heads`, в крайнем случае
  `GIT_CONFIG_GLOBAL=/dev/null git branch`. Флаги `-c branch.sort=…` и `--sort=…`
  не помогают: ключи сортировки накапливаются, битый всё равно разбирается.
- Конфиг меняет поведение по умолчанию: `pull.rebase=true`, `rebase.autostash=true`,
  `push.default=current`, `push.autoSetupRemote=true`, `push.followTags=true`.

## Граница коммита — фича, а не слой

Коммит собирает изменение целиком по вертикали: ядро + UI + связующий слой + артефакты
спеки + правка README. Разрезать по `packages/core` / `ui/src` / `apps/*` **нельзя** —
такие половинки не собираются и нарушают паритет таргетов (принцип II конституции).

Отдельными коммитами идут только вещи, не относящиеся к фиче: чисто инфраструктурная
правка (`flake.nix`, конфиги сборки), обновление зависимостей, независимый багфикс.

Естественные швы для стейджинга внутри фичи:

```
packages/core/src/<модуль>/   packages/core/tests/<модуль>_{native,wasm}.rs
ui/src/<модуль>/              apps/web/…  apps/desktop/…
specs/<NNN>-<фича>/           README.md   Cargo.lock  pnpm-lock.yaml
```

Лок-файлы (`Cargo.lock`, `pnpm-lock.yaml`) едут в том же коммите, что и правка
`Cargo.toml` / `package.json`.

Никогда не стейджить (всё в `.gitignore`, `git add -f` — только по прямой просьбе):
`target/`, `node_modules/`, `packages/core/pkg/`, `ui/src/wasm-core/`,
`ui/dist/`, `apps/desktop/dist/`, `.next/`, `apps/desktop/src-tauri/gen/schemas/`,
`.claude/settings.local.json`, `.env*`.

## Сообщение коммита

Русский язык, без префиксов Conventional Commits.

- **Заголовок**: суть фичи, ≤ ~60 символов, без точки; если работа привязана к спеке —
  `(фича NNN)` в конце. Пример: `Живой предпросмотр Typst (фича 005)`.
- **Тело**: абзацы прозой, ручной перенос по **74 колонки**. Абзац начинается с роли —
  `Ядро:`, `UI:`, `Заодно:`, `Плюс …`. Идентификаторы и пути — в обратных кавычках.
- Тело объясняет **зачем** и фиксирует временные решения: что сделано на время, до какой
  задачи это живёт. Ссылки на требования и задачи — как в спеке: `FR-002`, `T029`.
- Трейлер `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>` в конце.

Скелет (heredoc обязателен — редактор в этой среде не откроется):

```bash
git commit -m "$(cat <<'EOF'
Короткая суть изменения (фича NNN)

Ядро: что появилось в `packages/core`, за какое поведение отвечает и как
собирается под оба таргета. Временное решение — с указанием задачи, до
которой оно живёт.

UI: что появилось в `ui/src` и в связующем слое клиента, какое требование
спеки это закрывает (FR-00X).

Заодно: побочные правки, которые нельзя было отделить, и почему.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
EOF
)"
```

Перед написанием сообщения свериться с образцом: `git log -1 --format='%B'`.

## Гейты перед коммитом

Всё запускается **внутри `nix develop`** — вне dev-shell нет ни `cargo`, ни `pnpm`,
ни `wasm-pack`.

Коммит трогает `packages/core` → до коммита должно быть зелёным (Definition of done
конституции, `.specify/memory/constitution.md`):

- сборка под `wasm32-unknown-unknown` **и** под нативный таргет;
- `cargo test` и `wasm-bindgen-test`;
- в UI не добавлено бизнес-логики (принцип I);
- фронтенд проходит проверку типов в `strict`, без `any` (принцип IV).

Проверять на свежесобранном wasm: после правки ядра нужны обе пересборки, иначе
зелёный `ui` при красном `apps/desktop` — это устаревший `ui/dist`, а не ошибка кода.
Прогон тестов уместно отдать `test-runner-agent`.

Результат гейтов сообщать честно: тесты красные или не запускались — сказать об этом
и не коммитить.

## Артефакты Spec Kit

Правки в `specs/<NNN>-*/` (`spec.md`, `plan.md`, `tasks.md`, contracts, quickstart) —
часть фичи и едут вместе с кодом. Отметки о выполнении в `tasks.md` должны
соответствовать тому, что реально в коммите: расхождение здесь дороже, чем в коде,
потому что по `tasks.md` потом определяется, что сделано.
