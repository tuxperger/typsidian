# Цикл фичи в Typsidian

Запрос пользователя: `$ARGUMENTS`

**Правило проекта.** Любая фича — новая возможность, изменение поведения, новый
экран или настройка — идёт через Spec Kit. Команды `/speckit-*` вызываешь сам, через
инструмент Skill, не дожидаясь, пока пользователь их наберёт. Код в `packages/`,
`ui/`, `apps/`, `nix/`, `scripts/`, `flake.nix` правится только под открытую задачу
из `tasks.md` активной фичи — иначе хук `spec-gate` запросит подтверждение.

Исключение — hotfix: исправление поведения, которое уже описано в существующей спеке
и просто не выполняется. Его делают без новой спеки, но говорят об этом вслух и
ссылаются на нарушенное требование (`specs/NNN-…/spec.md`, FR-NNN).

## Где что лежит

| Что | Где |
| --- | --- |
| Активная фича | `.specify/feature.json` → `.specify/scripts/typsidian/feature.sh` |
| Все фичи и их стадии | `specs/ROADMAP.md` (генерируется, руками не править) |
| Конституция (принципы I–X) | `.specify/memory/constitution.md` |
| Хуки этапов Spec Kit | `.specify/extensions.yml` |
| Гейты качества | `.specify/scripts/typsidian/gates.sh`, скилл `quality-gates-typsidian` |
| Работа с артефактами спек | агент `speckit-agent` |
| Макеты и дизайн-система | скилл `design-typsidian` |

## Порядок

Порядок задан конституцией («Рабочий процесс и гейты качества»).

1. **Выбрать фичу.**
   - Новая → `/speckit-specify <описание>`. Каталог `specs/NNN-имя/` и запись в
     `feature.json` создаёт сама команда.
   - Уже заведённая → `.specify/scripts/typsidian/feature.sh use NNN`.
     `feature.json` — след последней `/speckit-*` команды, а не приоритет: какую
     незакрытую фичу продолжать, решает скилл `roadmap-typsidian`.
2. **`/speckit-specify`** — только наблюдаемое поведение (принцип III): без API,
   структур данных и имён библиотек. В шапке заполнить `**Priority**` и
   `**Summary**` (их читает роадмап). Не больше трёх `[NEEDS CLARIFICATION]`.
3. **`/speckit-checklist`** — гейт качества требований; хук `before_plan` его
   предлагает. Повторяется после плана под другим углом (безопасность, офлайн).
4. **`/speckit-clarify`** — хук `after_specify`, автоматически. Для работ по внешним
   процессам обязателен (принцип V). Вопросы, на которые отвечает конституция или
   существующий код, закрывай сам и записывай в Assumptions.
5. **Макет** — скилл `design-typsidian`, хук `before_plan`, автоматически. Фича с
   интерфейсом сначала рисуется по готовой спеке и только потом планируется:
   строка «Макет — …» попадает в Summary `plan.md`, по ней верстает
   `frontend-agent`, без неё хук `design-gate` не даёт править `*.tsx`/`*.css`.
   Фиче без интерфейса — «Макет — не требуется: <причина>».
6. **`/speckit-plan`** — research.md, data-model.md, contracts/, quickstart.md.
   Constitution Check заполняется по существу: для каждого принципа — как фича его
   соблюдает. Отклонение — только с обоснованием в разделе Complexity/Deviation.
7. **`/speckit-tasks`** — задачи по user stories. Тесты ядра на обоих путях
   (`cargo test` и `wasm-bindgen-test`) входят в задачи, а не откладываются.
8. **`/speckit-analyze`** — хук `after_tasks`, автоматически; пропускать нельзя.
   CRITICAL и HIGH находки исправляются в артефактах до реализации.
9. **`/speckit-implement`** — по задачам, отмечая `[X]` по мере выполнения. Работу
   по зонам отдавать агентам: `rust-core-agent`, `frontend-agent`,
   `tauri-shell-agent`, `nix-env-agent`.
10. **`quality-gates-typsidian`** — хук `after_implement`, автоматически.
11. **`/speckit-converge`** — хук `after_implement`: сверка кода со спекой;
    недостающее дописывается в `tasks.md` и доделывается. Отдельно проверить, что
    логика ядра достижима из UI: цепочка ядро → биндинг → вызов в `ui/src`.
12. В шапке спеки `**Status**: Implemented`, обновить README, если изменилось
    пользовательское поведение. Коммит — по скиллу `git-typsidian`, фичей целиком.

## Точки, где останавливаться

Между этапами не спрашивай «продолжать?» — иди дальше. Остановиться и показать
пользователю нужно, когда:

- спека содержит развилку, меняющую объём фичи, и разумного умолчания нет;
- план требует поправки конституции (отдельный шаг `/speckit-constitution`);
- реализация упёрлась в гейт, который не чинится в рамках задач фичи;
- решение расходится с макетом — часть расхождений намеренная, не переделывать
  обратно без вопроса;
- макет вводит то, чего нет в спеке, — показать его до плана.

## Мелкие правила

- Одна фича — один каталог. Не дописывай новую возможность в чужую спеку: заводи
  следующую NNN и ссылайся на прежнюю.
- Язык артефактов — русский, идентификаторы (`FR-001`, `SC-001`, `T001`, `US1`) —
  как в шаблонах.
- На требования и задачи других фич ссылайся с номером фичи: `001 §FR-016`,
  `001 T111`.
- Отметка `[X]` в `tasks.md` ставится, когда задача сделана на всех таргетах, а
  не когда написан код: по `tasks.md` потом определяется, что готово.
- Идеи на будущее не теряй: заведи спеку стадии `spec` (скилл
  `roadmap-typsidian`), а не оставляй TODO в коде.
